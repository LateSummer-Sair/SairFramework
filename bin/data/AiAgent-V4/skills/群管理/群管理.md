# 群管理（工具 `group`：二十个动作各有自己的 op，按**技能管控表**判）

群查询、群管动作，以及 NapCat 4.18 的边缘能力（群待办 / 群打卡 / 群成员策略 / 群分享链接 / 群相册取消点赞 / QQ 空间说说），全部经 `h.napcat()` 发出。**未连接 NapCat 时查询与动作都返回基板话术「Napcat 没有连接」**，不抛异常、本地能力不受影响。

## op 表

| op（技能管控表里的名字） | NapCat 动作 | 判定 | 说明 |
|---|---|---|---|
| `group.list` | `get_group_list` | 每个动作各判自己的 op：空 / Ban = 不可用 | 群列表（群号/群名/成员数/上限） |
| `group.members` | `get_group_member_list` | 同上 | 成员列表（`prompt.md` 的「成员列表最多」截断） |
| `group.member` | `get_group_member_info` | 同上 | 单个成员详情（昵称/名片/角色/等级/头衔/入群时间） |
| `group.ban` | `set_group_ban` | 同上 | 禁言；`duration=0` = 解除 |
| `group.kick` | `set_group_kick` | 同上 | 踢人；`reject=true` 顺带拉黑（拒绝再加群） |
| `group.muteall` | `set_group_whole_ban` | 同上 | 全员禁言开关；没给 `enable` 时先 `get_group_info` 读当前状态再取反 |
| `group.setadmin` | `set_group_admin` | 同上 | 设置 / 取消管理员 |
| `group.setname` | `set_group_name` | 同上 | 改群名 |
| `group.setcard` | `set_group_card` | 同上 | 改群名片（空串 = 清空）；没给 `qq` = 改自己的 |
| `group.leave` | `set_group_leave` | 同上 | 退群；`dismiss=true`（解散）会把同一个 `group.leave` 再判一遍，没授权一律拒 |
| `group.tododone` | `complete_group_todo` | 同上 + 确认闸 | 把某条消息的群待办标记完成（`msg` 必填，NapCat 4.18.0+） |
| `group.todocancel` | `cancel_group_todo` | 同上 + 确认闸 | 取消某条消息的群待办（`msg` 必填，4.18.0+） |
| `group.signedlist` | `get_group_signed_list` | 同上（读类） | 今天的群打卡名单（4.18.5+；字段名只有真机能核） |
| `group.invitepolicy` | `set_group_member_invite_policy` | 同上 + 确认闸 | 群成员邀请策略（4.18.14+，四个取值） |
| `group.memberperm` | `set_group_member_permissions` | 同上 + 确认闸 | 成员上传相册 / 临时会话 / 发起新群聊三个开关；没给的项保持不变 |
| `group.newmembervis` | `set_group_new_member_history_visibility` | 同上 + 确认闸 | 新成员默认能不能看最近的聊天记录（4.18.14+） |
| `group.sharelink` | `get_group_share_link` | 同上（读类） | 群分享 / 加群链接（4.18.26+） |
| `group.albumunlike` | `cancel_group_album_media_like` | 同上 + 确认闸 | 取消点赞群相册媒体（4.18.4+；`album`+`batch` 必填，`lloc` 可空） |
| `group.qzonesend` | `send_qzone_msg` | 同上 + 确认闸 | **发 QQ 空间说说（公开可见的动态，不是群消息）**（4.18.14+） |
| `group.qzonedel` | `delete_qzone_msg` | 同上 + 确认闸 | 删一条空间说说（4.18.14+，`tid` 必填） |

## 权限口径

1. **每个动作分支在动第一件事之前各判一次自己的 op**（`h.need("group.ban")` 这种写法，
   二十个动作二十条，彼此不牵连）：技能管控表里没给这个身份授权（**空** = 没写这条，或写了没给身份）或命中
   **Ban**，就把基板的 `[权限阻断] …` 拒绝原文原样回给模型、**动作不发**；技能里没有任何硬编码门槛。
   装在 `guardedApi` 上的 NapCat Guard 是**另一道**闸门（按 `napcat.<动作名>` 判），两道都过动作才发得出去。
2. **两道闸的意义**（边缘能力尤其要看清）：技能这一层的 op 是 `group.xxx`，基板那一层的 op 是
   `napcat.xxx`。`napcat.*` **不属于任何技能** —— 它只能由主人写进数据根的 `perms-core.jsonc`
   （写进技能目录的 `perms.jsonc` 会被当成越界条目忽略）。所以本技能目录里那份 `perms.jsonc`
   说明的是**技能层的意图**，真正让某个身份调得动这个平台动作的是 `perms-core.jsonc` 里那一行。
3. **出厂的表里没有身份 ⇒ 非主人一把都用不了**
   （**含该群的群主/管理员**），回基板那句带 `[权限阻断]` 的原文（`prompt.md` 里让她对用户说「这得主人定」）。
   要放开只能由主人写技能管控表（数据根 `skillctl` 那一族权限文件），例如
   `Run["group.ban","user:10001"]` = 只给这个人禁言的本事；条目里写工具名 `group` 则覆盖它全部动作。
   主人恒全权（`MASTER` 不受表影响）；她自己（`SYSTEM`）同样恒全权。
   **读类**（`group.signedlist` / `group.sharelink`）与既有三个查询同族：技能层不设门槛
   （`Run` 里给了 `ALLUSER`），但基板层的 `napcat.get_group_*` 默认没授权 ⇒ **非主人实际仍取不到**；
   要放开采编到 `perms-core.jsonc`（见下）。
4. **每个 op × 谁能用（出厂默认，技能层 + 基板层）**：

| op | 技能层（本技能的 `perms.jsonc`） | 基板层（`napcat.<动作>`，默认没授权） | 出厂实际效果 |
|---|---|---|---|
| `group.list` / `group.members` / `group.member` | `Run: ALLUSER` | `napcat.get_group_*`：**未授权** | 非主人被基板那道拒（要放开得在 `perms-core.jsonc` 里给） |
| `group.signedlist` | `Run: ALLUSER`（读类，与上面同族） | `napcat.get_group_signed_list`：**未授权** | 非主人被基板拒；主人照常 |
| `group.sharelink` | `Run: ALLUSER`（读类） | `napcat.get_group_share_link`：**未授权** | 非主人被基板拒；主人照常 |
| `group.ban` / `kick` / `muteall` / `setadmin` / `setname` / `setcard` / `leave` | `Ban: ALLUSER`（现有口径，明写"谁都不给"） | 对应 `napcat.set_group_*`：**未授权** | 只有主人（与她本人 `SYSTEM`） |
| `group.tododone` / `todocancel` | `Ban: ALLUSER` | `napcat.complete_group_todo` / `cancel_group_todo`：**未授权** | 只有主人 + 要 `confirm=true` |
| `group.invitepolicy` / `memberperm` / `newmembervis` | `Ban: ALLUSER` | 对应 `napcat.set_group_member_*` / `set_group_new_member_history_visibility`：**未授权** | 只有主人 + 要 `confirm=true` |
| `group.albumunlike` | `Ban: ALLUSER` | `napcat.cancel_group_album_media_like`：**未授权** | 只有主人 + 要 `confirm=true` |
| `group.qzonesend` / `qzonedel` | `Ban: ALLUSER` | `napcat.send_qzone_msg` / `delete_qzone_msg`：**未授权** | 只有主人 + 要 `confirm=true`；发布还要过出站内容闸 |

   一句话：**边缘能力出厂默认全部只给主人**（读类也一样 —— 它卡在基板那道 `napcat.*` 上）；
   要把读类放给所有人，主人在 `perms-core.jsonc` 里写
   `["napcat.get_group_signed_list","napcat.get_group_share_link"]: ["ALLUSER"]` 即可，
   **写类与空间发布不建议放开**（它们是"改群规则"与"对外发声"，放开就绕过了本技能"非主人一律拒"的口径）。
5. **二次确认（确认闸）**：高危写类（待办完成/取消、三个成员策略、取消相册点赞、删空间说说）与
   对外发声（发空间说说）在**权限判过之后**还要一次显式确认（`confirm=true`，配置键「高危需确认」）。
   它**不是权限门槛** —— 不为任何身份开或关权限，只让"不可撤销 / 对外可见"的那一步在代码里看得见
   （与 `leave+dismiss` 同族）。判定顺序是**先权限、后确认**：没被授权的人拿到的是 `[权限阻断]` 原文。
6. **工具可见性按同一张表筛**（工具级 op `group` 放行，或任一动作级 op 放行 ⇒ 模型才看得见这把工具）：
   非主人默认什么都看不见（要特例放行）。能不能答应对方看事实块 `caller.ops`
   （这个身份能用的技能 / 动作清单；`"ALL"` = 全权、`[]` = 一个都没有）。
7. **身份不参与权限判定**：群主/管理员（事实块 `caller.role` = `owner`/`admin`）只是给她参考的事实，
   不当作门槛 —— 基板里**没有"管理员"这个身份**（只有 `user:<QQ>` / `group:<群号>` / `ALLUSER`），
   所以"可给管理员用"只能落成"给 `ALLUSER`"或"点名给 `user:<QQ>`"，两种都在 `perms-core.jsonc` 里写。
8. **解散群不另设门槛**：`leave` 且 `dismiss=true` 时把同一个 op（`group.leave`）再判一次
   （`GroupSkill.leave`，配置键「解散需主人」是这一道的开关）—— 与分支开头那次是**同一个 op、同一条判定**，
   `dismiss` 只是给同一个 NapCat 动作多带一个 `is_dismiss=true` 参数。

## QQ 空间：发出去的东西**不在 QQ 群里**

`group.qzonesend` 发的是**QQ 空间（QQ 动态）**，收件人不是群成员：

- **默认公开可见**：`ugc_right` 缺省用主人配的「空间默认可见范围」（**出厂 `1` = 所有人可见**）—— 你不用去找那个文件，要改就跟主人说。
  提示词里写死了这条口径：**这是公开可见的动态，别当群消息发** —— 只该群里知道的事、群里才懂的黑话、
  内部事实行都不要往那儿放。要收紧成"仅自己可见"把配置键改成 `64`。
- **出站纪律照样要过**：它同样只走 `h.napcat()` → 基板 `Api.call`，因此
  **自我记账头 / 内部事实行 / `[[mood:…]]` 标记族 / 出站红线**这几道内容闸会在交给 NapCat 之前判这一条，
  命中就整条拦下、拒绝原文回给模型。**本技能不复制任何一条判据**（不 import 红线、不自己写正则、
  不调 `say()`、不碰 `Sinks`）—— 旁路等于把安全级规则搬到"可开可关的技能"里。
- **图片只收 http(s)**：`images` 不在基板文件改写层认的键里，本地路径交出去跨机读不到，所以技能这一层就不收
  本地路径。空间图片 URL 约 **2 小时过期**（NapCat 侧可用 `get_rkey` 一族刷新），别把旧链接存起来复用。
- **删要凭 tid**：`group.qzonedel` 需要 `tid`（发送结果或空间列表里给的），缺了就回结构化「缺参数」。

## 输出与配置

- 所有可读文案、阈值、输出模板都在同目录的 `prompt.md`（**运行期读，改即生效**）；
  值留空 = 用技能里的结构性 ASCII 兜底，不会有写死的中文文案。
- 行式输出用全角 `｜` 分隔，字段顺序写在 `prompt.md` 的注释里（`群行`：序号｜群号｜群名｜成员数｜上限）。
- 控制台日志前缀 `[群管理]`，只有 `op=… group=… qq=… chars=…` 这类键值，便于排查；**正文与 URL 不进日志**。
- 失败口径：参数缺失 / 取值不合法 → 结构化说明（含可用取值）；动作失败 → `{op} 失败：{err}`，
  其中基板的出站拦截原文整句保留；NapCat 未连接 → 原样回「Napcat 没有连接」。

## 典型用法

```

group op=ban group=123456 qq=10001 duration=0   # 解除禁言

group op=muteall group=123456                   # 全员禁言开关（取反）
group op=setcard group=123456 qq=10001 card=小明 # 改群名片
group op=leave group=123456 dismiss=true        # 解散群（默认只有主人做得到；她本人 SYSTEM 照常）
group op=tododone group=123456 msg=1234567890 confirm=true   # 把那条待办标成完成
group op=signedlist group=123456                # 今天谁打卡了
group op=invitepolicy group=123456 policy=require_approval confirm=true  # 邀请改成要审核
group op=memberperm group=123456 upload_album=false confirm=true         # 关掉成员上传相册
group op=newmembervis group=123456 visible=false confirm=true            # 新成员看不到历史
group op=sharelink group=123456 short=true      # 取群分享链接
group op=albumunlike group=123456 album=xxx batch=112233 confirm=true    # 取消相册点赞
group op=qzonesend text="今天天气不错" confirm=true                      # 发一条空间说说（公开可见）
group op=qzonedel tid=xxxxxx confirm=true       # 删一条空间说说
```

## 与别的技能的关系

- 「待处理申请」（工具 `request`）管加群/加好友申请的审批，本技能不管申请。
- 「申请审批」是自动审批钩子；本技能是主人手动执行动作的入口。
- **群消息**发在群里（「消息发送」工具 `send`）；本技能的 `qzonesend` 发在**空间**，两者不是一回事 ——
  群里该说的用 `send`，空间动态要走 `group op=qzonesend`（且默认只有主人做得到）。
- 退群后配置里如果还有该群相关的定时/审核设置，需要自己去改对应技能的 `prompt.md`（本技能不动别人的配置）。
