# 群管理（工具 `group`：群管动作 = **E 类对外动作**，非主人一律拒）

群查询与群管动作，全部经 `h.napcat()` 发出。**未连接 NapCat 时查询与动作都返回基板话术「Napcat 没有连接」**，不抛异常、本地能力不受影响。

## op 表

| op | NapCat 动作 | 权限（E 类对外动作，按动作名判） | 说明 |
|---|---|---|---|
| `list` | `get_group_list` | `E`（非主人默认拒） | 群列表（群号/群名/成员数/上限） |
| `members` | `get_group_member_list` | `E`（非主人默认拒） | 成员列表（`prompt.md` 的「成员列表最多」截断） |
| `member` | `get_group_member_info` | `E`（非主人默认拒） | 单个成员详情（昵称/名片/角色/等级/头衔/入群时间） |
| `ban` | `set_group_ban` | `E`（非主人默认拒） | 禁言；`duration=0` = 解除 |
| `kick` | `set_group_kick` | `E`（非主人默认拒） | 踢人；`reject=true` 顺带拉黑（拒绝再加群） |
| `muteall` | `set_group_whole_ban` | `E`（非主人默认拒） | 全员禁言开关；没给 `enable` 时先 `get_group_info` 读当前状态再取反 |
| `setadmin` | `set_group_admin` | `E`（非主人默认拒） | 设置 / 取消管理员 |
| `setname` | `set_group_name` | `E`（非主人默认拒） | 改群名 |
| `setcard` | `set_group_card` | `E`（非主人默认拒） | 改群名片（空串 = 清空）；没给 `qq` = 改自己的 |
| `leave` | `set_group_leave` | `E`（非主人默认拒） | 退群；`dismiss=true`（解散）走同一个 `set_group_leave` 的 E 位判定，非主人一律拒 |

## 权限口径

1. **群管动作一律是 E 类对外动作**（禁言/踢人/改名/全员禁言/改名片/设管理员/退群解散；
   查询 op 也一样 —— 它们同样发 NapCat 动作）：每个 op 在发动作前 `h.needPlatform(<动作名>)`
   判 `E` 位，不过就返回基板的 `缺 X 位 —— [权限阻断] …` 拒绝原文、**动作不发**；技能里没有任何硬编码门槛。
   权威闸门是装在 `guardedApi` 上的 Guard（`Boot` 里那处
   `auth.allowRes(c, Res.platform(action), 'X')`），`h.needPlatform` 与它同源。
2. `ALLUSER` 默认 `E` 无（`Acl` 的 `DEF_E = NONE`）⇒ **非主人一律拒**
   （**含该群的群主/管理员**），回基板那句带 `[权限阻断]` 的原文（`prompt.md` 里让她对用户说「这得主人定」）。要放开只能由主人在账本 `data/perms.json`
   （v3 的例外条目）里写，例如 `E["User<QQ>","set_group_ban","X"]` = 只给这个人禁言的本事。
   主人恒全权（`MASTER` = 全 `RWX`）；她自己（`SYSTEM`）的 E = `RWX`（`Acl.SYS_E = Bits.ALL`）。
3. **工具可见性按 `T:X` 筛**（`ALLUSER` 默认 `T=无` ⇒ 他的工具清单为空；工具是她的手段，属 T 类、只判入口）：看不见就是 `T` 位的结果，能不能答应对方
   看事实块 `caller.bits`（五类各有什么位；`ALLUSER` 默认 `T` 无 ⇒ 非主人一把工具都用不了，要特例放行）。
4. **身份不参与权限判定**：群主/管理员（事实块 `caller.role` = `owner`/`admin`）只是给她参考的事实，
   不当作门槛；口径见同目录 `prompt.md`（非主人提的一律只回「这得主人定」；主人提的说清后果再动手；
   拿不准就问主人）。
5. **解散群不另设门槛**：`leave` 且 `dismiss=true` 时先过一次 `h.needPlatform("set_group_leave")`
   （`GroupSkill.leave`）—— 与 `act()` 里发动作前那次是**同一个平台动作、
   同一个 `E` 位判定**，`dismiss` 只是给同一个动作多带一个 `is_dismiss=true` 参数。
   没过就拒、动作不发，拒文形如 `缺 X 位 —— [权限阻断] 需要 set_group_leave 的 X 位（默认分配 NONE，当前有效位 NONE）`。
   所以"解散"不是另一档权限、也不跟好感度挂钩：非主人（含群主/管理员）一律拒，主人与她本人（`SYSTEM`）照常。

## 输出与配置

- 所有可读文案、阈值、输出模板都在同目录的 `prompt.md`（**运行期读，改即生效**）；
  值留空 = 用技能里的结构性 ASCII 兜底，不会有写死的中文文案。
- 行式输出用全角 `｜` 分隔，字段顺序写在 `prompt.md` 的注释里（`群行`：序号｜群号｜群名｜成员数｜上限）。
- 控制台日志前缀 `[群管理]`，只有 `op=… group=… qq=…` 这类键值，便于排查。

## 典型用法

```
group op=list                                  # 我加入了哪些群
group op=members group=123456                  # 群里都有谁
group op=ban group=123456 qq=10001 duration=600 # 禁言 10 分钟
group op=ban group=123456 qq=10001 duration=0   # 解除禁言
group op=kick group=123456 qq=10001 reject=true # 踢人并拉黑
group op=muteall group=123456                   # 全员禁言开关（取反）
group op=setcard group=123456 qq=10001 card=小明 # 改群名片
group op=leave group=123456 dismiss=true        # 解散群（默认只有主人做得到；她本人 SYSTEM 照常）
```

## 与别的技能的关系

- 「待处理申请」（工具 `request`）管加群/加好友申请的审批，本技能不管申请。
- 「申请审批」是自动审批钩子；本技能是主人手动执行动作的入口。
- 退群后配置里如果还有该群相关的定时/审核设置，需要自己去改对应技能的 `prompt.md`（本技能不动别人的配置）。
