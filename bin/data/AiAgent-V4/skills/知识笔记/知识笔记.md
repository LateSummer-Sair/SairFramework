# 知识笔记（工具 `note`；`note` 库是 C 类资源，写/改/删靠技能自己的归属硬判）

落在基板六库的 **`note` 库**（表 `note`：`id/ts/title/content/tags/source/extra`），只调 `h.store()`，不自己写 SQL、不自己建表。

## 四个 op

### `add` —— 记一条
- `content` 必填；`title` 不填则取正文前 24 字；`tags` 逗号分隔或数组；
- **写入查重两道**：
  1. 标题完全相同 → 覆盖旧笔记（回"已有同名笔记，已更新 #id"）；
  2. 标题**近似** → 也覆盖（回"已有近似笔记（标题相似度 0.xx），已更新 #id"）：判定用基板
     `kit/Fingerprint` 的中文 2-gram Jaccard（阈值 `相似阈值`，默认 0.85 = V3 笔记口径），
     比较前先按 `标题前缀` 剥掉 `[联网搜索]` 这来源前缀、再归一化；指纹项数不足 `指纹最短项数`
     就不做近似判定（"显卡""价格"这种短标题什么都能撞上）。命中时累加 `note:dup_hit`；
  - **只用标题做身份判定**：正文往往是模板化的搜索结果堆，用它会误并"同主题不同问题"（V3 实测）；
- 否则新增（回"已记下 #id"）；
- `source` 记为 `skill:note`，`ts` 由基板自动填；
- 上面这些阈值与全部文案都在同目录 `prompt.md` 里（每次调用重读）。**缺键口径分两种**：
  多数键缺了会明确报「缺键」；例外是 `正文长度上限`（缺省 = 不限）与 `标题前缀`（缺省 = 不剥任何前缀）——
  这两个键缺省时静默降级，不报缺键。

### `search` —— 检索
`h.store().search("note", query, limit)`：有 FTS5 就走 `MATCH`（中文 trigram），没命中或无 FTS 自动回退 `LIKE`；返回里带命中来源。

### `recent` —— 最近几条
`h.store().list("note", null, limit, "ts DESC")`，默认 10 条。

### `delete` —— 按 id 删
`h.store().delete("note", id)`；id 不存在就如实说。

## 返回样式
```
找到 2 条笔记（关键词「搜索」）：
1. #12 必应搜索语法
   用 site: 限定站点、用引号做精确匹配…
   tags: 搜索,技巧 · 2026-01-01 12:00
```

## 使用建议
- **记之前先搜**：`search` 一下关键词，已有类似笔记就 `add` 同名/近似标题覆盖（保留更完整的那份），不要重复堆。
  写入时就算标题略有差异也会被 `相似阈值` 判定为同一条并覆盖 —— 但还是建议先搜，避免把不同问题并成一条。
- 值得记：结论性知识、用户长期偏好、重要事实、常用流程。不值得记：临时闲聊、一次性口令、能从上下文直接读到的内容。
- 笔记是共用的，别把 A 群的私事记成公共知识。
- 写/改/删笔记都只有主人和她自己能做：`note` 库没有按人归属的列，非主人（`ALLUSER`）一律拒
  （`NoteSkill.noteWriteGuard` 归属硬判，拒绝文案带 `[权限阻断]` 标识）；**读口仍开放**，普通人只能查。
