# 桌面（工具 desktop）

看见并操作本机窗口。底层是 **Windows UI Automation**（PowerShell + .NET 自带，零新依赖），
引擎脚本在 data/tools/uia.ps1。

## 七个 op

| op | 干什么 |
|---|---|
| windows | 列出所有顶层窗口：pid / 类名 / 标题 / 位置 / kind（browser·console·canvas·window） |
| tree | 取一个窗口的元素树：名字 / 控件类型 / 坐标 / 可用 / 支持的 Pattern（Invoke·Value·Select…） |
| act | 按名字操作：click（Invoke 或 Select）/ set（写值）/ focus |
| read | 读窗口里的文本（元素名 + Value 值） |
| shot | 只截某个窗口或一块区域（比整屏省很多 token） |
| halt | 一键停：立刻冻结全部桌面操作 |
| resume | 解冻 |

## 为什么比看图猜坐标强

- 元素有名字：「点名叫『保存』的按钮」比「点 (743,512)」稳得多，窗口挪动也不影响；
- 读回来是结构化文本，token 远小于一张图；
- 元素自带 Pattern：能 Invoke 的就 Invoke（等价于点），能写值的直接写值。

## 已知边界（别硬猜）

| 目标 | 能做到吗 |
|---|---|
| 原生窗体（记事本/画图/大多数软件） | ✅ 完整元素树 + 按名字操作 |
| 浏览器页面里的按钮/链接 | ❌ UIA 只有窗框（实测 Chrome 只有 13 个窗框元素）⇒ 用 web 工具（CDP） |
| 控制台窗口里的文字 | ❌ UIA 只有滚动条/标题 ⇒ 用 exec 直接跑命令，或 op=shot 截图再去看图 |
| 游戏 / 自绘界面 | ⚠️ 元素树基本为空 ⇒ 退回像素：screen.capture + input |

## 纪律

- 一次一个动作，动手前先 tree（别猜名字）；
- act 回执里 done=invoke/select/setValue/focus_only 告诉你真做了什么 —— focus_only 表示它没有可点的 Pattern，那一下不算点；
- 对方说「停 / 别动 / 停手」⇒ 立刻 desktop op=halt，解锁要 op=resume；
- 审计：每次操作留一行 [desktop] 日志，出问题按它复盘。
