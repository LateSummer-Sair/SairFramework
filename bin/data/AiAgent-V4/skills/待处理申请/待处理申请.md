# 待处理申请（工具 `request`：同意/拒绝 = **E 类对外动作**，非主人一律拒）

**主人手工**处理好友申请 / 群邀请的那一半。另一半是已有技能「申请审批」——它是 `on_request` 自动策略钩子
（好友申请只通知不自动同意、白名单内的群邀请自动同意）。两者**共用同一份清单**，不各存一套。

## op 表

| op | 干什么 | NapCat 动作 | 权限 |
|---|---|---|---|
| `pending` | 列待处理清单：`kv` 前缀 `pending:` 的条目 + 「申请审批」钩子的最近记录（+ 可选实时查询） | 无（配了「系统消息动作」才查） | 读通用 kv 表（C 类的 `R` 位，默认就有） |
| `approve` | 同意（`type` = `friend` / `group`，`flag` 必填） | `set_friend_add_request` / `set_group_add_request` | **E 类对外动作**（判 `E` 位）⇒ 非主人一律拒 |
| `reject` | 拒绝（同上，可带 `reason`） | 同上（`approve=false`） | 同上：E 类对外动作 ⇒ 非主人一律拒 |

动作**成功之后**才把该条从 `pending:` 清单里移出（`kvDelete` 精确键）；失败/未连接时清单不动，可以重试。

## 清单在哪、键长什么样

| 键 | 谁写 | 内容 |
|---|---|---|
| `kv.pending:friend:<flag>` | 待处理申请的清单（可由钩子写入，见下） | 一条申请记录的 JSON |
| `kv.pending:group:<flag>` | 同上 | 同上 |
| `kv.approve_friend_last` | 「申请审批」钩子（**已有键，本技能只读**） | 最近一条好友申请：`{ts,type,qq,flag,comment,action,whitelisted}` |
| `kv.approve_group_last` | 「申请审批」钩子（**已有键，本技能只读**） | 最近一条群邀请：`{ts,type,group,qq,flag,subtype,comment,action,whitelisted}` |

记录字段名与「申请审批」的 `RequestHook.record(...)` **完全一致**（`ts/type/qq/group/flag/subtype/comment/action/whitelisted`），
所以 `pending` 能把两处来源合成一份清单，`pending:` 前缀是主清单、钩子键是兜底来源（去重按 `type+flag`）。

> **来源（与「申请审批」钩子对齐，现状）**：`RequestHook.record(...)` 每次申请都会写 `approve_*_last` / `approve_*_count`，
> **并且写 `pending:<type>:<flag>`**（键格式与字段名本技能就是按它读的，两处共用一份格式，不需要另外补条目）。
> 所以 `pending` 的主清单来自钩子，本技能只读不写；不需要用 `store_write` 手工往 `pending:...` 里补条目。

## 可选：实时系统消息

`prompt.md` 里 `系统消息动作` 留空（默认）= 不查实时；填成 NapCat 支持的动作名（要能从 `napcat` 工具的 `action=list` 动作目录里挑到，基板目录见 `Api.catalog()`）后，
`pending` 会再问一次 NapCat，把返回里的 `invited_requests`（群邀请）与 `join_requests`（加群请求）并进清单。
未连接时那一行失败原因会附在清单末尾；**清单整体为空时直接返回那句原因（例如「Napcat 没有连接」）**，不抛异常。

## 权限口径

1. **工具可见性按 `T:X` 筛**（`ALLUSER` 默认 `T=无` ⇒ 他的工具清单为空；工具是她的手段，属 T 类、只判入口）：能不能答应对方看事实块 `caller.bits`
   （五类各有什么位；`ALLUSER` 默认 `T` 无 ⇒ 非主人一把工具都用不了，要特例放行），不看工具名。
2. `pending` 只读通用 kv 表（C 类的 `R` 位）—— C 类对非主人只有 `R`（`RWX` 只有 `SYSTEM` 有），所以这一判基本只回答"库能不能读"。
3. `approve`/`reject` 是**以机器人自己的账号身份改平台状态**，属 **E 类对外动作**：
   `h.needPlatform(action)` 判 `E` 位，而 `ALLUSER` 默认 `E` 无（`Acl` 的 `DEF_E = NONE`）
   ⇒ **非主人一律拒**（回基板那句带 `[权限阻断]` 的原文），
   没有可配置的开关。**好感度不再决定任何权限** —— 好感再高也一样拒。
4. 主人恒全权（`MASTER` = 全 `RWX`）；她自己（`SYSTEM`）的 E = `RWX`（`Acl.SYS_E = Bits.ALL`），
   所以"申请审批"那个钩子才能自己同意白名单里的群邀请。

> `prompt.md` 里还留着 `仅主人: true` 这个键，但**代码已经不读它了**
> （`RequestSkill` 的配置加载只读 `启用`）：判定只看 E 类位。要收紧 / 放开请改账本，不要改这个键。

## 典型用法

```
request op=pending                                  # 有什么待处理
request op=approve type=friend flag=1234567890 remark=同事   # 同意加好友
request op=reject  type=group  flag=9876543210 subtype=invite reason=不认识  # 拒绝群邀请
```
