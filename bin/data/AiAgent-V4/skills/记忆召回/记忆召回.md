# 记忆召回（ContextProvider · 易变段）

**这个插件不给模型任何工具**（md 的 front matter 里没有工具声明，只有 `name` 与 `description`）。它做的事只有一件：
每轮在装配上下文时，把「和本轮用户话相关」的长期记忆与**本会话自己的**群聊片段拼成一段 system 注入进去
（**任何情况下都不跨群**）。
工具/扩展点的识别靠**类实现了 ext 接口**（`MemoryRecallProvider implements ContextProvider`），
基板装载时会扫这个插件的每个顶层类并自动注册，不需要在 md 里再声明一遍。

## 挂在哪

| 项 | 值 | 为什么 |
|---|---|---|
| 扩展点 | `sair.v4.ext.ContextProvider` | 只往"进去的东西"里加一段 |
| `stable()` | `false`（**易变段**） | 内容随本轮用户话变；放进稳定段会让模型服务的前缀缓存每轮失效（段位口径见 `ContextProvider` 类注释） |
| `order()` | `10` | 同序按插件名，顺序确定 = 同输入逐字节可复现 |
| `maxChars()` | `prompt.md` 的「预算」（默认 **1200**） | 基板还要再按全局 `ctxBudgetChars`（默认 6000）截一次 |

## 数字（V3 原样，见 `notes/feel-plugins.md` 第二节）

| 项 | 值 | V3 出处 |
|---|---|---|
| 记忆条数 | **8** | `QQPromptBuilder.java:695`（`searchMemories(plainText, 8)`） |
| 跨群群聊条数 | **5** | `QQPromptBuilder.java:706`（`searchGroupChatHistory(plainText, 5)`） |
| 查询门槛 | 去空白与标点后 **≥4 字** | `QQPromptBuilder.java:719-722`（`hasMeaningfulQuery`） |
| 单条截断 | **300** 字 | `QQPromptBuilder.java:700` |
| 跨群单条截断 | **160** 字 | `UnifiedQQMemoryManager.java:798` |
| 跨群行格式 | `[群{群号}] {昵称}: {内容}` | `UnifiedQQMemoryManager.java:799` |
| 标题 | `## 相关记忆` / `## 跨群相关群聊记录` | `labels/qq.md` 的 `title.related-memories` / `title.cross-group-related` |

## 数据从哪来（**只读**）

只用 `Host` 能力面：`h.store().search("memory", 本轮用户话, 8)` 与
`h.store().search("grouplog", 本轮用户话, 5)`（FTS5 优先、LIKE 回退，都在基板里）。
**不建库、不写库、不自己开库、不写 SQL**；`BuildContext.subagent()` 为真时也没有任何写路径
（这个插件整体没有副作用，不是"子 Agent 时跳过写"的那种写法）。

- `memory` 是业务表，由「记忆」插件声明；本插件只是**读**它。
- `grouplog` 是基板环境库（群聊历史）。
- 库/表拿不到（`host()` 为 null、或 `store()` 拿不到）→ 这一段不出现，不报错、不影响这一轮。
- **注入前逐条过归属硬判**（`MemoryRecallProvider.java:347` 的 `visible()`，`Store.search` 没有 filter，
  命中结果是整库的）：只留 **目标会话自己的**群聊（`grouplog.group_id == 目标群`，**任何情况下不跨群**）
  ＋**目标那个人**的 `user` 记忆＋**目标群**的 `group` 记忆＋`global`；
  **别人的 `user` 记忆一律不注入**（没有真人触发者时一条都不注入），目标群拿不到时群聊段与 `group` 记忆
  也一律不注入（只剩 `global`），认不出的作用域不注入。能不能注入由**目标会话**裁，不看权限位。

## 文案与阈值在哪

全在同目录的 `prompt.md`（`键: 值`，`#` 开头是注释）：`开关`/`条数`/`跨群条数`/`最小查询字数`/
`查询过滤正则`/`预算`/`单条上限`/`跨群单条上限`/`跨群开关`/`时间格式`/`截断尾巴`，
以及文案 `标题`/`说明`/`行模板`/`跨群标题`/`跨群说明`/`跨群行模板`/`匿名昵称`。
Java 里只留"文件读不到时的兜底默认值"，兜底值与 `prompt.md` 的出厂值一一对应。
读法是**惰性缓存 + 按 mtime 失效**：每轮不读盘，改完保存下一轮生效。

## 护栏（自己扛住，绝不让一轮对话因为本插件挂掉）

- `host()` 可能为 null、`store()` 可能为 null、库可能不存在、正则可能被改坏 ——
  每一种都**自己吞掉并降级**（返回空串 = 这一段不出现），`build()` 外层还有一层 `catch (Throwable)`。
- 超时与异常隔离由基板负责（默认 200ms 一段），本插件不阻塞、不派子 Agent、不打印日志。

## 验收（对应探针断言）

1. 先 `remember` 一条（如「主人喜欢回答简短一点」）→ 下一轮的 system 里出现 `## 相关记忆` 与那条记忆行；
2. 本轮用户话太短（去空白与标点后 < 4 字，如「嗯」「哈哈」）→ **不出现**这一段（一次库查询都不发）；
3. 条数生效：库里相关记忆多于 8 条时最多 8 行；字符预算生效：超 1200 字符被基板按段截断；
4. 关掉开关（`开关: false`）→ 这一段不出现，其它插件照常。
