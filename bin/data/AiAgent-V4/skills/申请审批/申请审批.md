# 申请审批（`on_request` 钩子技能 —— 钩子是她自己的自主行为 = `SYSTEM`，不提供工具）

基板把好友申请 / 群邀请原样交给 `on_request` 钩子；**基板自己不带审批策略**，策略全在这个技能里。删掉技能 → 申请不再被记录、也没人通知主人（基板只打一行"没有技能接管这条申请"）。

钩子派发时主体是 **`SYSTEM`**（她自己的自主行为，`E` = `RWX`（`Acl.SYS_E = Bits.ALL`），见 `Skills` 的 `dispatch(hook, payload)` → `hookActor()`），
所以自动同意 / 私聊通知这些平台动作走得通 —— **这是"她自己的自动策略"，不是权限位判出来的**，
也没有"谁触发了申请"这一层判定；`h.caller()` 只是申请人这个**事实**（给她写通知文案用）。
非主人**手动**同意/拒绝申请则是另一回事：见「待处理申请」（E 类对外动作，非主人一律拒）。

## 策略（默认保守）
| 事件 | 处理 |
|---|---|
| 好友申请 `request_type=friend` | **绝不自动同意**。把 `flag/qq/comment` 记进 `kv`（**默认只记录、不私聊主人**：`通知主人: false` 是出厂值，要通知就显式开它），让主人自己决定（可以直接用 `napcat` 工具的动作 `set_friend_add_request`） |
| 群邀请 `request_type=group` | 群号在 `prompt.md` 的 `自动同意群` 白名单里 → `setGroupAddRequest(flag, sub_type, true)` 自动同意（**同意后的告知同样看 `通知主人`，出厂不通知**）；不在白名单 → **只记录**（出厂不通知，要通知就显式开 `通知主人: true`） |
| 其它 request_type | 不处理，只进控制台日志 |

## 配置与文案在哪
全在 `prompt.md`（同目录）：
```
启用: true                # 不为 true 则整个技能不动作
自动同意群:               # 群号白名单，逗号分隔；留空 = 永不自动同意
通知主人: false           # 出厂 false = 默认只记录、不私聊主人；要用就改成 true
好友通知: …               # 占位符见下
群邀请通知: …
自动同意通知: …
```
占位符：`{name}` 申请人昵称、`{qq}`、`{group}` 群号、`{subtype}` add/invite、`{flag}`、`{comment}` 验证信息。
**文案留空、或 `通知主人` 没开，就不发那条通知**（技能里没有写死的用户文案；出厂默认 = 只记录不通知，这时记的 `action` 是 `recorded`）。

## 落库 / 观测
| 键 | 内容 |
|---|---|
| `kv.approve_friend_last` | 最近一条好友申请 JSON：`{ts,type,qq,flag,comment,action,whitelisted}` |
| `kv.approve_friend_count` | 好友申请累计条数 |
| `kv.approve_group_last` | 最近一条群邀请/加群 JSON：`{ts,type,group,qq,flag,subtype,comment,action,whitelisted}` |
| `kv.approve_group_count` | 群邀请累计条数 |
| 控制台 | `[申请审批] …` 日志（含通知发送结果、NapCat 未连接等） |

`action` 取值：`recorded`（只记录：通知文案为空 **或 `通知主人` 没开**；**出厂默认即 recorded**）、`notified`（已通知主人）、`auto_accept`（白名单内已自动同意）、`accept_failed:<原因>`（自动同意失败）、`notify_failed`（想通知但发送失败）、`offline`（NapCat 未连接，只能记录）。

## 说明
- "不落库地记进 kv" = 不进六库（不污染 `note/memory`），只用基板运行表 `kv` 存一条可查的记录。
- NapCat 未连接时无法通知主人，也不会自动同意（动作会回「Napcat 没有连接」）——此时只记录 + 控制台日志，等主人上来处理。
- 处理完置 `payload._handled = true`，表示这条申请本技能接管了。
