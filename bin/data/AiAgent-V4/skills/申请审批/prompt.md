# 本文件是「申请审批」技能的配置源：保存即生效（基板监听技能目录，自动热重载）。
# 格式：一行一条「键: 值」；# 开头的行是注释；键缺失或值留空 = 该通知不发（技能里没有写死的兜底文案）。

自动同意群-主人邀请: true

好友通知: 主人，有人申请加好友：{name}（{qq}），验证信息「{comment}」。flag={flag} —— 我没有自动同意好友申请，要同意就用 napcat 动作 set_friend_add_request。
群邀请通知: 主人，{name}（{qq}）邀请我去群 {group}（{subtype}），不在白名单里。flag={flag} —— 要同意就用 napcat 动作 set_group_add_request。
自动同意通知: 群 {group} 在白名单里，我已自动同意（flag={flag}）。

# 说明
# 自动同意群：群号白名单，逗号分隔，例如「123456,234567」；留空 = 不按白名单自动同意（默认最保守）。
# 群邀请（sub_type=invite）自动同意 = 下面三条**任意一条**成立即可，判断顺序就是这里写的顺序：
#   ① 主人亲自邀请：自动同意群-主人邀请
#   ② 邀请人好感度达标：群邀请自动同意好感度
#   ③ 群在白名单里：自动同意群
# 自动同意群-主人邀请：**默认 true** = 主人（配置里的 masterQQ）自己邀请她进群时自动同意，哪怕群不在白名单里；
#   留空/false = 关。关掉之后主人的邀请**不再用他的好感度兜一遍**（那个开关就是"别自动同意他的邀请"），
#   但仍然可以走白名单那一条。
# 好友自动同意好感度：**默认 100**（档位表 src\sair\v4\auth\Favor.java 的 levelName：
#   1000 挚友 / 700 敬重 / 500 信重 / 300 朋友 / 100 眼熟 / >0 陌生 / 0 初识 —— 上限 1000、下限 0）。
#   申请人好感度 ≥ 这个数 ⇒ 自动同意好友申请；0 或负数 = 关（= 老口径"绝不自动同意好友"，只记录）。
# 群邀请自动同意好感度：**默认 300**（朋友档）。**邀请人的当前好感度** ≥ 这个数 ⇒ 自动同意他的进群邀请
#   （好感度是现读的，技能自己不记账）；0 或负数 = 关（不看这一条，只看主人邀请 / 白名单）。
#   ⇒ 只有 sub_type=invite（邀请她进群）走这些分支；sub_type=add（别人申请进她管的群）**一律不自动同意**，只记录。
#   **上面两个好感度键留空 = 0 = 关**（最保守：它们开着就会自动放人进来，所以"没写值"绝不按默认开；
#   键整个缺失才取出厂默认值）。
# 通知主人：出厂 false = **默认不通知**（避免陌生人加好友/入群申请就直接私信主人）；
#   记录照旧写 kv（approve_*_last / approve_*_count / pending:*），要用就把它改成 true。
#   它只管"没自动同意、只记录"时的提醒。
# 同意后通知主人：**默认 true** = 自动同意之后私聊主人一条（"我把谁放进来了、为什么"）；留空/false = 不打扰。
#   与上面的「通知主人」是两个开关、互不影响；发送失败只记一行日志，**不影响审批结果**（审批已经发生）。
# 自动同意通知：旧键，白名单群自动同意后的文案；「同意群通知」留空时回落到它（老配置口径不变）。
# 同意群通知 / 同意好友通知：自动同意之后的文案（留空 = 那一条不发）。
# 占位符：{name} 申请人昵称、{qq} QQ号、{group} 群号、{subtype} add/invite、{flag} 请求标识、{comment} 验证信息、
#   {favor} 好感度值、{need} 本次自动同意的阈值（好友通知 = 好友门槛；群通知 = 只在"好感度达标"那一支给值，
#   主人邀请 / 白名单没有阈值 ⇒ 渲染成空）、{level} 好感度档位名。
