# 私聊输入态（LifecycleHook · order=50）

**这个插件不给模型任何工具**（md 的 front matter 里只有 `name` 与 `description`，没有工具声明）。
它挂在**生命周期**上，做的事只有一件：**私聊里，回合开始让机器人"正在输入"，回合结束收起这个状态**。
工具/扩展点的识别靠**类实现了 ext 接口**（`PrivateTypingHook implements LifecycleHook`），
基板装载时会扫这个插件的每个顶层类并自动注册，不需要在 md 里再声明一遍。

## 挂在哪

| 项 | 值 | 为什么 |
|---|---|---|
| 扩展点 | `sair.v4.ext.LifecycleHook` | 管的是"记账与清理"这类**回合时序**，不是"改内容" |
| `order()` | `50` | 只做状态开关，不和别的钩子抢顺序；同序按插件名，顺序确定 |
| 实现的口 | `onTurnStart(BuildContext)` / `onTurnEnd(BuildContext, String reply, String error)` | 一开一关，正好一对 |
| 不实现的 | `onSend(BuildContext)` | 发送前那一刻不需要动状态：开在回合开始、关在回合结束 |
| 调用的能力 | `b.host().typing(true / false)` | 基板的**具名能力**，一个动作一个口 |

**时序**（基板保证，见 `LifecycleHook` 的类注释）：

```
onTurnStart（装配完、还没跑） → 模型跑（可能多次工具闭环）→ onSend → 落点发出 → onTurnEnd
```

- `onTurnStart` 打开 → 整个"模型在想 + 在写"的窗口里，对方都看得到"正在输入"；
- `onTurnEnd` 收起。**成功与失败都通知一次**，所以失败那一轮也会收起（`reply` 为空串、`error` 非空），
  不会留下"说失败了但一直在输入"的半开状态；
- 钩子挂在**主回合**上：**子 Agent 不触发**（它的思考不该冒到对方面前）；
  但**后台收尾回合（`Agent.wake`）会触发** `onTurnStart` / `onTurnEnd`（基板对内部收尾回合也派生命周期，
  只是不派 `onSend`）—— 私聊里那一轮会跟着开一次、关一次状态，因为它紧接着就关，观感上是无害的一闪。

## 为什么群聊与控制台一次都不调

不是"调了让基板吞掉"，而是**本插件根本不调**：`b.group()` / `b.console()` 为真时在**读配置之前**就 `return`
（连 `prompt.md` 都不读、连 `host()` 都不碰）。群聊的理由三条：

1. **NapCat 没有这个动作的群聊形态**。`set_input_status` 是私聊语义（"我正在给你打字"），
   群里没有"某个成员正在输入"这种可展示的状态，硬发只是让基板白白做一次 no-op；
2. **观感上会串**：群里同时有好几个人在说话，一个"正在输入"挂在整个群上，指向不明确；
3. **口径要能被断言**：探针里"群聊一轮下来 `typing` 调用次数 = 0"是个干净的硬断言
   （见下面的验收 ③），而"调了但被基板吞了"没法从插件侧证伪。

`Host.typing` 自己也有一道群聊 no-op（`Boot.java` 的 `if (c.isGroup()) return;`）——
本插件把它当**兜底**，不当**依据**：插件自己的边界自己守。

## `host()` 为 null 的行为

`BuildContext.host()` 是"只读能力面"，基板按「插件名 → 该插件的 `Sk`」绑定；
**绑不上时为 null**（探针直接注册的合成实现、插件已被卸载等）。本插件的处理是**少做点事，绝不抛异常**：

```
b == null          → return（连上下文都没有）
b.group()          → return（群聊）
b.console()        → return（本地控制台会话：那不是"私聊窗口"，不去点亮主人的私聊输入态）
b.qq() <= 0        → return（拿不到 QQ 号：系统记账类回合，没有能展示的私聊对象）
b.host() == null   → return（拿不到能力面：这一次就是不放这个状态）
开关: false         → 两个钩子都 return（一轮都不调）
其余任何 Throwable → 就地吞掉（钩子外还有一层 catch，见下）
```

**为什么 `host()` 为 null 时不"再想别的办法"**：唯一的动作就是 `host().typing(...)`，
没有 host 就没有动作；而**绝不能**自己绕去 `napcat()` 发 `set_input_status` ——
`napcat()` 是**带闸门**的口，`set_input_status` 是一个 NapCat 动作（op = `napcat.set_input_status`，
按技能管控表判定：`MASTER` 与她本人 `SYSTEM` 不受表影响、恒全权，普通用户（`ALLUSER`）
表里没给授权就是不可用、会被拒，拒绝文案带 `[权限阻断]` 标识；要放开得主人在账本 `skillctl.json` 里补身份）。
基板已经把这件事收成一个具名动作（`Host.typing`：内部显式绑 `SYSTEM` 再走带闸门的 `guardedApi`，
所以不受"谁在说话"影响，口径与 `Host.say` 一致），
**插件只用这一个口**，不自己拼动作名、不自己碰管控表。

## 文案与阈值在哪

只有同目录的 `prompt.md` 里的一个键 `开关`（`true` / `false`）：

- `开关: true`（出厂值）= 私聊回合开始一次 `typing(true)`、回合结束一次 `typing(false)`；
- `开关: false` = **两个钩子直接 return**，一轮都不调（含回合结束那一半），等于没装。

Java 里只留"文件读不到 / `host()` 拿不到目录时的兜底默认值"，**兜底值与 `prompt.md` 的出厂值逐字相同（true）**。
读法是**惰性缓存 + 按 mtime 失效**：每一轮不读盘，改完保存下一轮生效，不需要重启。
本插件不产出任何"说给用户听的话"，所以 `prompt.md` 里没有文案节。

## 护栏

- 钩子外层 `try { … } catch (Throwable)`：**任何异常都不逃逸**。
  基板对每个扩展点调用本来就有护栏（异常只丢自己、`[ext] error …` 一行），但**插件不该依赖它**；
- 所有判断都在 `toggle(...)` 一个决策点上（两个钩子共用），不存在"开的那半和关的那半走不同分支"的可能；
- 群聊在**读配置之前**就返回，群聊回合不产生任何文件 I/O；
- 配置读坏（键名写错、值认不出）→ 按兜底值 `true` 处理，不会变成"关不掉"；
- **无状态**：插件不记"我给谁开过"。基板的调度器（`schedule.Lanes`）**同会话保序、不同会话并行**，
  所以同一会话里 start/end 一定成对出现，不需要计数器；而没有计数器就不会因为热重载、
  漏了一次 end 而**把状态永久卡在"正在输入"**上。

## 验收（对应探针 / 冒烟断言）

1. **私聊一轮**：`onTurnStart` → `typing(true)` **一次**；`onTurnEnd` → `typing(false)` **一次**（假 Host 计数）；
2. **失败一轮也收**：`onTurnEnd(b, "", "boom")` → 仍然 `typing(false)` 一次（不能因为失败就不收）；
3. **群聊一轮**：`onTurnStart` + `onTurnEnd` → `typing` **一次都不调**（`true`/`false` 计数都是 0）；
4. **`host()` 为 null**：两个钩子都不抛异常，也不产生调用；
5. **`开关: false`**：两个钩子都不调（总调用次数 = 0）；
6. **兜底默认值**：`prompt.md` 不存在时按 `true` 处理（一轮 = 一次 true + 一次 false），
   与出厂值逐字相同；
7. **异常不逃逸**：假 Host 的 `typing` 自己抛异常时，两个钩子都不向外抛。

## 已知边界（拿主意的地方，写下来备查）

- **`b.qq() <= 0` 也 return**：挡掉"拿不到 QQ 号"的回合（系统记账回合）。
  理由是这类回合**没有能展示状态的私聊对象**，`Host.typing` 内部本来也是 `qq <= 0` 直接 no-op ——
  插件侧先挡掉，省掉一次无意义的跨层调用，行为与"调了"完全一致。
- **控制台会话（`Caller.console/system`，`qq` 是主人号、`isGroup()` 为假）也 return**：
  `toggle(...)` 里是 `if (b.group() || b.console()) return;` —— 控制台不是"私聊窗口"，
  所以主人在**控制台**说话时**不会**去点亮他私聊窗口的"正在输入"（`BuildContext.console()` 现成）；
  注意 `Host.typing` 自己只挡了群聊与 `qq <= 0`，**控制台这一档是插件侧挡的**（插件自己的边界自己守，
  不依赖基板兜底）。
- **不做"最小停留时间"**：没有"打开后至少显示 N 毫秒"这类美化 —— 那需要一个计时线程/延时收起，
  属于给自己加状态。极快的一轮（缓存命中、秒回）可能刚开就关，对方未必看得见；
  这是可接受的：**看不见"正在输入"远好于卡在"正在输入"**。
- **不做"分段间的空档"**：只在回合边界开关，不在 `onSend` 前后反复关开。
