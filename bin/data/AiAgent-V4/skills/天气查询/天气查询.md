# 天气查询（工具 `weather`：单动作工具，op = `weather`，能不能用看技能管控表）

权限上**有门槛**：查天气这把工具是单动作工具，op 就是工具名 **`weather`**，写在账本
`skillctl.json` 的一行上 —— `Run` 白名单 = 可用、`Ban` 黑名单 = 不可用、**空 = 未授权 = 不可用**
⇒ **非主人（`ALLUSER`）默认用不了这把工具，要放行得由主人往表里写身份**
（她本人 `SYSTEM` 与主人恒全权；好感度不再决定任何权限）。
判定在动作分支开头（`h.need("weather")`），拒文原样回给模型。

用 [wttr.in](https://wttr.in) 的 JSON 接口取实时观测：

```
GET https://wttr.in/<城市>?format=j1
```
（https 失败时自动退回 `http://` 再试一次）

## 参数
| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `city` | string | 否 | 城市名；不填 = 按出口 IP 猜当前位置 |

## 返回
```
上海（China） · 观测 12:00 PM
温度 8°C（体感 6°C）｜多云｜湿度 70%｜风 SE 12 km/h｜能见度 10 km｜气压 1021 hPa
```

失败时（都以 `[weather]` 开头）：
- `[weather] 查询失败：…` —— 网络 / 超时 / 非 2xx（含具体原因与 GET 的地址）；**「返回的不是 JSON」不是独立一条，它是这一条的内容**
  （形如 `[weather] 查询失败：返回的不是 JSON：…`）；
- `[weather] 返回里没有 current_condition，取不到观测数据。` —— 响应是 JSON，但里面没有观测数据；
- `[weather] 没找到这个城市：xxx` —— 服务里查不到该地名。

## 文案在哪
本技能**暂无 `prompt.md`**：面向模型的文案（`[weather]` 开头的查询失败 / 返回的不是 JSON / 没有 current_condition /
没找到这个城市）目前**硬编码在 `WeatherSkill.java` 里** —— 改文案要改 Java，改这份 md 不生效。（收拢进 `prompt.md` 属另一笔改动。）

## 实现要点
- 只读、无副作用；超时 12 秒；任何异常都变成一句说明。
- 解析 `current_condition[0]` + `nearest_area[0]`，字段缺失就跳过，不编数字。

## 使用建议
- 用户问"今天冷不冷 / 要带伞吗"，先查再答，**不要**凭季节猜温度。
- 查不到城市就问用户换个写法（"上海"→"Shanghai"），别硬报一个不存在的温度。
- 这是实时观测，不是预报；用户问未来几天时要说清"本站只取了实时观测"。
