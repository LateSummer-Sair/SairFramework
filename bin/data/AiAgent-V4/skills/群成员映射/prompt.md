# 群成员映射 · 文案与阈值
# 本文件是本插件唯一的配置源：标题、说明、行模板、角色词、角色标记、条数、缓存窗口、预算全在这里。
# 格式：`键: 值` 一行一条；`#` 开头的行是注释（`## 配置` 这种分节标题也是注释）；
#       行内第一个冒号（半角 `:` 或全角 `：`）是分隔符，值里可以再带冒号（后面的冒号都算值）。
# 读法：惰性缓存 + 按文件 mtime 失效 —— 每轮不读盘，改完保存下一轮生效，不需要重启。
# Java 里只留「文件读不到 / host() 为 null 时的兜底默认值」，兜底值与下面各行的出厂值一一对应。
#
# ⚠ 这一段是**稳定段**（stable()=true）：同输入必须逐字节不变，否则模型服务的前缀缓存每轮失效。
#   所以：模板里**没有**时间戳类占位符（{ts}/{age} 之类故意不提供），也别把本轮正文塞进来；
#   渲染层只认下面「占位符」一节列出的键，写了别的（比如 {time}）也只会原样留在文本里 —— 这是有意的：
#   与其"配错就悄悄波动"，不如让它显形。
#   改本文件会让"同输入"变成"输入变了"（配置本来就不是输入的一部分），代价是下一次装配前缀全变，属正常。

## 备注（不解析，只给人看）
# 开关：false = 本段这一轮不出现（不查 NapCat、不出这一段）。
# 动作名：OneBot v11 动作，参数固定 {"group_id": <群号>}，取响应里的 data 数组
#   （每项读 user_id / nickname / card / role）。出厂默认 get_group_member_list 就够了；
#   留空或写错 = 查不到 = 这一段安静消失（不报错、不影响这一轮）。
# 人数上限：本群最多印几个人（V3 是 20，见 QQPromptBuilder.java:311 的 `if (nc >= 20) break;`）。
#   排序是「角色 → QQ」，所以截断丢掉的永远是"角色最低、QQ 最大"的那些人。
# 全局昵称上限：跨群那段最多印几条（V3 是 15，见 QQPromptBuilder.java:354 的 `if (pc >= 15) break;`）。
# 全局昵称开关：false = 不出「跨群昵称映射」那段（只出本群的）。
# 缓存秒：同一个群多少秒内不重复查 NapCat（默认 60，与 V3 getGroupNicknameMap 的 60s 短缓存同量级）。
#   查询走插件自己的后台守护线程：冷缓存那一轮先不出这一段，数据回来后的下一轮就出；
#   过期时先出旧快照、后台换新（stale-while-revalidate）—— 这一段的字节因此在一个缓存窗口内是常量。
# 失败缓存秒：查失败（权限阻断 / 未连接 / 超时 / 响应不是 JSON）也进缓存，压住不立刻重试。
#   最坏情况 = 每群每 30 秒一次查询（不轰炸 NapCat）。
# 单名上限：一个称呼最多印多少字（防一张超长群名片把整段预算吃光）；<=0 = 不截。
# 预算：本段的字符上限，也是 maxChars() 的返回值（默认 800）。
#   注意：maxChars() 拿不到 Host，所以它用的是「上一次 build 读到的预算」，首次调用前是 800。
#   超预算时从**尾部整行丢**（先丢跨群、再丢本群）：一行的最小单位是"一个人"，绝不切半行。

# 占位符（{键} 字面替换；**没有**时间类占位符，见上面的稳定段说明）：
#   行模板：{name} 群名片（空则昵称，再空则「无名占位」）、{card} 群名片、{nickname} 昵称（{nick} 同）、
#           {qq} QQ 号、{role} 角色中文名（「角色名」表）、{role_raw} 角色原名（owner/admin/member）、
#           {mark} 角色标记（群主 👑 / 管理员 🔧；普通成员为空）
#   说明：**没有 ⭐主人标记** —— V4 没有"主人 QQ 清单"的只读口（V3 有 AiConfig.getMasterQQs()），
#   而用"说话人是不是主人"去标会让同一段在不同人说话时字节不同（主人一开口，前缀缓存废一次）。
#   稳定段纪律优先：这一段的字节只由「群 + 成员快照 + 本文件」决定，与谁在说话无关。
# 全局行模板：同上（跨群那段只记名字、不记角色，所以 {role} 一律是「成员」；
#   想要 V3 那种"只有名字→QQ"的形状，把它改成 `- {name} (QQ {qq}){mark}` 即可）。
#   标题 / 说明 / 全局标题：留空 = 不打这一行（说明只在"本群那段有行"时才打）。
#   角色名：`owner=群主,admin=管理员,member=成员`（逗号分隔；表里没有的角色名原样印，不发明新词）。

# 数据从哪来（只读，绝不写）：
#   ① 群成员表：h.napcat().call("get_group_member_list", {"group_id": 群号}) → data[]。
#      这是**带闸门**的接口：每次调用按动作自己的 op（napcat.get_group_member_list）过技能管控表
#      （空 = 未授权 = 不可用；MASTER 与她本人 SYSTEM 恒全权，不受管控表影响），
#      拿不到数据时返回的是 [权限阻断] … / Napcat 没有连接 这类文本 ——
#      本插件一律当"拿不到"处理（返回空串，这一段不出现），不抛异常、不重试轰炸。
#   ② 跨群昵称：插件自己的内存（被动累积：每次真查到一批群成员，就记下 QQ → 最近一次的称呼）。
#      不额外查 NapCat、不建表、不落盘、不写库。V3 的对应物是 group_nicknames 表（V4 无此表）。
#   ③ 缓存在插件内存里（ConcurrentHashMap，按群 + TTL），进程重启即清空 —— 没有任何持久化。
