# 用户画像（ContextProvider · 稳定段）

**这个插件不给模型任何工具**（md 的 front matter 里没有工具声明，只有 `name` 与 `description`）。它只做一件事：每轮装配上下文时，把
「这个人是谁、对他的印象、好感档、对他的态度」拼成一段 system 注入进去。
工具/扩展点的识别靠**类实现了 ext 接口**（`UserProfileProvider implements ContextProvider`），
基板装载时会扫这个插件的每个顶层类并自动注册，不需要在 md 里再声明一遍。

## 挂在哪

| 项 | 值 | 为什么 |
|---|---|---|
| 扩展点 | `sair.v4.ext.ContextProvider` | 只往"进去的东西"里加一段 |
| `stable()` | `true`（**稳定段**） | 内容只由「谁 + 库里已有的印象 + 好感度」决定，**同输入逐字节不变** → 排在同一条系统提示词之后、事实块之前，和它们一起构成可复用的前缀（段位口径见 `ContextProvider` 类注释） |
| `order()` | `20` | 同序按插件名；顺序确定 = 同输入逐字节可复现 |
| `maxChars()` | `prompt.md` 的「预算」（默认 **600**） | 基板还要再按全局 `ctxBudgetChars`（默认 6000）截一次 |
| `appliesTo()` | `b.qq() > 0` | 没有具体的人（没有调用者）就没有"画像"可言，这一段不出现（正常跳过，不是异常） |

**稳定段的纪律（这个插件刻意守的）**：不放时间戳、不放随机数、不放本轮正文、不读 `b.text()`。
`prompt.md` 里也**没有**时间类占位符 —— 想加也加不了，避免"改个模板就把前缀缓存打散"。

## 数字出处（V3 原样，见 `notes/feel-plugins.md` 第二节）

| 项 | 值 | V3 出处 |
|---|---|---|
| 五维 | emotionStability / interests / speakingStyle / honesty / imageHabit | `modules/tasks/impression-distill.md` 的「分析维度」 |
| 行模板 | `- {label}: {value}` | `modules/context/impression-person-line.md` 原样 |
| 标题 | `## 对该用户的印象` | `modules/labels/qq.md` 的 `title.user-impression`（`PromptManager.heading` 补 `## `） |
| 五维短标签 | 情绪状态 / 兴趣爱好 / 说话风格 / 虚实态度 / 图片习惯 | `modules/labels/impression.md` 的 `field.*`（这里当**别名**收下） |

## 数据从哪来（**只读**）

只用 `Host` 能力面：

1. **印象**：`h.store().list("memory", {scope:"user", scope_id:"<本人QQ>"}, 60, "ts DESC")`，
   再在 Java 侧按 `source`（默认 `印象蒸馏`）或 `tags`（含「印象标签」）筛出印象行。
   每行正文按「标签: 值」解析成五维 / 态度 / 补充（约定写在 `prompt.md` 的备注里）。
2. **好感档**：`h.favor()`（只读视图）→ `of(qq)` + `levelName(v)`。**主人默认不显示好感行**。
3. **态度**：印象行里标签命中「态度键」的那条（第三批的「情绪」插件将来往 `memory` 写一条就能被读到）。

不建库、不写库、不自己开库、不写 SQL；`BuildContext.subagent()` 为真时同样没有任何写路径
（这个插件整体没有副作用，不是"子 Agent 时跳过写"的那种写法）。
读 memory 前按 ACL 的 C 类 `R` 位判一次（主体 `h.subject()`，无主体按 `Caller.systemActor()`）—— 被拒即整段静默消失。
库拿不到（`host()` 为 null / `store()` 为 null）、**既没有印象行、好感行也不显示**（主人 / 零好感）时 → 这一段不出现，不报错、不影响这一轮。
（只读到位、好感 > 0 的非主人：即使一条印象行都没有，也会出一行好感档 —— 见验收第 4 条的口径。）

## 文案与阈值在哪

全在同目录的 `prompt.md`（`键: 值`，`#` 开头是注释）：`开关`/`维度`/`维度别名`/`态度键`/`印象来源`/
`印象标签`/`印象取样条数`/`印象条数`/`预算`/`主人显示好感`/`显示零好感`/`无名对象`，
以及文案 `标题`/`对象行`/`行模板`/`原文模板`/`好感档模板`/`态度行模板`。
Java 里只留"文件读不到时的兜底默认值"，兜底值与 `prompt.md` 的出厂值一一对应。
读法是**惰性缓存 + 按 mtime 失效**：每轮不读盘，改完保存下一轮生效。

## 护栏

- `host()` 可能为 null、`store()` 可能为 null、`favor()` 可能为 null、库可能不存在、
  印象正文可能是任意形状 —— 每一种都**自己吞掉并降级**（返回空串 = 这一段不出现），
  `build()` 外层还有一层 `catch (Throwable)`。
- 超时与异常隔离由基板负责（默认 200ms 一段）；本插件不阻塞、不派子 Agent、不打日志。

## 验收（对应探针断言）

1. 写一条 `memory(source=印象蒸馏, scope=user, scope_id=本人)`，正文如
   `情绪稳定: 冷静\n兴趣: 打游戏` → 下一轮的 system 里出现 `## 对该用户的印象` 与对应两行；
2. **稳定段逐字节不变**：同一份库、同一个人、连续两轮的这一段完全相等（没有时间戳/随机/正文）；
3. **主人不显示 favor**：主人自己的画像里没有「好感」行（`主人显示好感: false`）；
4. 零好感的新人不出现好感行（`显示零好感: false`）；库里没有任何印象行且好感为 0 → 整段不出现。
