# 情绪（状态表 · on_message 累积 · on_timer 衰减 · ContextProvider 注入）

**这个插件不给模型任何工具**：front matter 里只有 `name` / `description` / `hooks`，
没有工具声明，所以它不注册工具，技能管控表 `data/skillctl.json` 里没有它的 op；
钩子按 `SYSTEM`（她自己的自主行为）跑 —— 没有 op 可判，也就不需要授权。
它做的事只有三件，全是"体感"：

| 挂在哪 | 什么时候 | 干什么 |
|---|---|---|
| `sair.v4.skill.Skill#declare` | 装载期（实例化之后、注册工具之前） | 声明自己的 `emotion` 表 |
| `sair.v4.skill.Hooked` · `on_message` | 每一条入站 QQ 消息 | 命中词表 → 怒气/伤心/亲疏/情绪标签/恋爱状态累积 |
| `sair.v4.skill.Hooked` · `on_timer` | 基板唯一 tick（`conf.tickMs`，出厂 20 秒） | 按「衰减分钟」结算衰减（V3 是每分钟 −2.0 怒 / −1.5 悲） |
| `sair.v4.ext.ContextProvider` | 每一轮装配上下文 | 注入**一行**「当前态度 + 语气」（易变段） |

钩子与扩展点的识别靠**类实现了接口**（`EmotionSkill implements Skill, Hooked`、
`EmotionProvider implements ContextProvider`）：基板装载时会扫这个插件的**每个顶层类**并自动注册，
不需要在 md 里再声明一遍；`hooks:` 仍然要写（钩子名字面量没有类型信息）。

## 表：`emotion`（自己声明、自己写）

一行 = **一个「人在一个场合」**：

| 列 | 类型 | 说明 |
|---|---|---|
| `id` / `ts` | 基板统一补 | `ts` = 最后一次写入毫秒 |
| `scope` | TEXT | `private`（私聊）/ `group`（群聊） |
| `scope_id` | TEXT | 私聊 = `<QQ>`；群聊 = `<群号>:<QQ>`（**按人按群隔离**就靠这一列） |
| `group_id` / `qq` | INTEGER | 冗余出来的两个号，便于按人/按群排查 |
| `angry` / `sad` | REAL | 那台 0~100 的状态机（V3 的 anger / sadness） |
| `affinity` | INTEGER | 亲疏（V3 的 affection，−100~1000，日积月累，不随时间衰减） |
| `last_emotion` | TEXT | 对方**最近一条消息**的情绪标签（V3 的 `lastEmotionByUser`） |
| `romance` / `romance_id` | TEXT / INTEGER | 恋爱状态 `none/lover/betrayer/ex` 与那个人（V3 的恋爱系统） |
| `day` | INTEGER | 上次"当天交流"的日期（`yyyyMMdd`）——V3 的「每天首次 +2~3」 |
| `hits` / `extra` | INTEGER / TEXT | 累计命中规则数、最近命中的规则名（诊断） |
| `decay_ms` | INTEGER | 衰减结算游标（见下） |

索引：`idx_emotion_scope(scope, scope_id)`、`idx_emotion_ts(ts)`、`idx_emotion_qq(qq)`。
**不建全文索引**：这张表是状态不是文本，没有检索用法（`LibSpec` 里没有 `fts(...)`）。

## 只写自己的库

写路径只有 `emotion` 这一张表（`h.store()` 的通用 CRUD，走的是插件自己的声明）。
`memory` / `dialog` / `grouplog` / `favor` **一个字节都不写**：要读别的库走 `Store.list` —— 只读，不改别人的数据。
**本插件也不读基板的好感度**（没有任何一处调 `Host.favor()`）：注入行里的「亲疏」是它自己那份
`affinity`，与基板好感档是两回事。

读写自己的库是插件自己的事（没有工具、也就没有 op 可授权）：钩子与扩展点跑在 `SYSTEM` 主体上恒放行，
**真正在管隔离的是本插件自己的归属硬判** —— 它只碰自己的 `emotion` 表。

## 按人按群隔离

| 谁在哪说话 | `scope` | `scope_id` |
|---|---|---|
| 私聊里的某个人 | `private` | `<QQ>` |
| A 群里的某个人 | `group` | `<A群号>:<QQ>` |
| B 群里的同一个人 | `group` | `<B群号>:<QQ>`（**另一行**） |

于是 A 群被骂出来的怒气**不会**出现在 B 群，也不会出现在私聊里。
V3 的怒气是**全局一个值**，它自己被这件事咬过（`EmotionStateManager.noteUnfriendlyGroup` 的注释：
群氛围能把全局怒气顶到 100 并钉死，于是 AI 在所有群和私聊里都暴躁）；
V4 按场合分开存，**不做全局情绪** —— 这是刻意的差异，不是漏做。

## 衰减

V3 用一条 60 秒的守护线程，每分钟 `怒 −2.0 / 悲 −1.5`。V4 没有插件自己的线程，
挂在基板唯一 tick 上：`decay_ms` 记住"上次结算到哪"，每次 tick 算
`(now - decay_ms) / (衰减分钟 × 60000)` 得几份就补几份。

- 长期速率与 V3 逐字一致（tick 快慢都不影响）；
- **消息来的时候先结算再累加**（等价于 V3 那条线程一直在跑）；
- 只处理"怒气或伤心 > 0"的行，两个条件分别查一次（`Store` 的过滤是 AND，没有 OR）；
- 一次最多处理「衰减批量」行，避免 tick 变慢。

## 注入（一行段）

`stable() = false`（**易变段**）：态度随消息变，放进稳定前缀会让模型服务的前缀缓存每轮失效。
`order() = 90`（同序按插件名，顺序确定 = 同输入逐字节可复现）；`maxChars()` = 主人配的「预算」（**出厂 1000**）—— 你不用去找那个文件。

**档位层（离散 6 态）生效时注入的是「情绪块」**（**最多 7 行**），上面那一行降为**兜底**（只在 `prompt.md` 的
`情绪开关: false`、或档位层整块产不出来、或 `prompt.md` 读不出来时用）——**同一轮永远只有一个语气源**：

```
mood: {"state":"calm","since":"…","trigger":"被骂","level":3}   ← 首行还**可选**带 "them"/"themRead" 两格（见下）
【此刻情绪：平淡】<语气-calm>
例：<范例-calm>
<边界-calm>
<自报-提示>
【时机】…（可选第 7 行，见下）          ← 三条否决全过就出现（2026-09-27 起：不再由白名单判）
【本轮语气以本段为准】…（覆盖句）
```

首行 `^mood: \{` 与末行 `【本轮语气以本段为准】` 是**两条逐字锚点**（探针按字面断言）。
★ 2026-09-24 本批实测（`tmp\v6-real\batch6\K4-moodcue\`）：6 行最坏 569 字符
（`trigger` 名最长的「重复问同一件事」那一档、`angry` 态六行全在，预算 1000，余量 431）；
平淡 + 第 7 行 = 400 字符（余量 600）。
**「每 20 分钟重置到平淡」的口径**（固定网格 + 懒结算 + provider 只读 ⇒ ≤1 个 tick 的窗口）
逐字写在 `prompt.md` 的「档位配置」那一段的注释里；一句话版：看 `kv` 里那一行的 `slot` 字段，
`slot` 已是当前格而 `state` 还是 `angry` 才是 bug。

### 「对方最近一条消息的情绪标签」那一格（`them` + 读法；2026-09-27 批 17 L1）

甲方口径（逐字）：「**为什么不把语境语义这些东西交给AI自己分析呢？我们提供这个情绪状态机就好了呀。**」
与「**基板内的基础东西，安全类的允许写死，像工具，状态机，聊天，这些东西是我们要引导AI正确使用才对，
我们要铺好正确的路，一步一步引导AI去使用我们的东西达到我们想要的效果。**」

状态机每轮**已经算出**了这个标签（`emotion.last_emotion`），但**批 17 之前它只被 `cue()` 的否决②读**
（当"此刻不许发"的判据），**从不给她看** —— 这正是"提供了东西却没给她"的活标本。
本批把它还给她，**提供 + 引导**两件一起落、都落在**已经存在的那一行**里：

| 件 | 住哪 | 她看到什么 |
|---|---|---|
| **提供**（事实） | `EmotionMood.factLine(c, m, lastEmotion)`；值 = `EmotionProvider.build()` 里那**一次** `EmotionState.peek(...).lastEmotion`（与否决②**同一个值**） | 首行多一格 `"them":"难过"` |
| **引导**（读法） | `prompt.md` 的 **`标签读法`**（唯一文案源 —— **面向她的文案 100% 住在 `prompt.md`**；Java 里新增的只有**配置键名**（`"标签读法"` 新增、`"平静标签"` 从 `EmotionProvider.legacy` 搬到 `EmotionMood.themTag`，同键同义），**没有一句中文字面文案**） | 同一行再一格 `"themRead":"…"` |

  ★ 与改前的差异（措辞已按磁盘校正）：**判据一致，但不是逐字节等价** —— `themTag` 比旧写法**多做一次 `trim()`**

## 护栏

- `payload` / `h` / `h.store()` 都可能是 null（钩子的宿主绑不上、装配期的 provider 宿主为 null）：
  每一种都自己吞掉并**少做点事**（这一段不出现 / 这一次不累积），绝不抛异常；
  `Hooked.on` 与 `ContextProvider.build` 各自还有一层 `catch (Throwable)`。
- 词表、正则、条件、模板全在 `prompt.md` 里，**写坏了只让那一条规则作废**（解析失败就跳过），不会崩。
- `prompt.md` 读不出来时：**标量**（预算、衰减分钟与幅度、上下限、每日亲疏、衰减批量、平静标签、
  无名对象）回落到 Java 里的兜底默认值，与出厂值一一对应；**三张表（效果规则 / 档位）没有 Java 兜底** ——
  那一刻它们为空：不累积、注入行里没有心情/态度/语气/关系（模板与数字仍在）。
- 不派子 Agent、不调 NapCat；常态不打印日志（`日志: true` 时 on_timer 每结算到东西才打一行 dim；
  另外"钩子异常"与"情绪库读/写不了"这两类**会无条件**打一行 dim，那是留痕不是噪音）。

## 验收（对应冒烟断言）

1. 连骂 → 怒气上升，且有上限（100）；
2. 到点（tick 的 ts 往后推）→ 怒气按「怒气衰减」递减；
3. 同一状态两次注入逐字节一致；不同状态注入行不同；
4. `host()==null` 时 `build` 不抛异常（这一段不出现）、`on_message` 不抛异常；
5. 改 `prompt.md`（mtime 变了）→ 词表/数值下一条消息就生效；
6. 群 A / 群 B / 私聊三条消息 → 三行状态，互不串味；
7. 跑完以后 `memory` / `dialog` / `grouplog` 一行都没多（只写自己的表）。
