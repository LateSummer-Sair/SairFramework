# 好友管理（工具 `friend`：平台动作 = **E 类对外动作**）

好友列表 / 用户资料查询 + **机器人自己账号**上的动作（删好友、拉黑、点赞、戳一戳、改昵称/签名）。
平台动作全部经 `h.napcat()` 发出；
**未连接 NapCat 时一律返回基板话术「Napcat 没有连接」**，不抛异常。
唯一的例外是 `block` / `unblock` / `blocklist`：**本地黑名单完全不依赖 NapCat**，未连接也照样生效。

## op 表

| op | NapCat 动作 | 权限（E 类对外动作，按动作名判） | 说明 |
|---|---|---|---|
| `list` | `get_friend_list` | `E`（非主人默认拒） | 好友列表（QQ/昵称/备注），「好友列表最多」截断 |
| `info` | `get_stranger_info`（无 group）/ `get_group_member_info`（有 group） | `E`（非主人默认拒） | 陌生人资料 / 群成员详情 |
| `delete` | `delete_friend` | `E`（非主人默认拒） | 删除好友（同样是 E 类动作，没有额外的主人专属键） |
| `block` | 本地 `kv:block:<qq>` ＋ `prompt.md` 的「拉黑动作」 | 归属硬判（非主人一律拒）＋ 平台动作走 `E` | 拉黑：**先写本地黑名单**，再尽力发平台动作 |
| `unblock` | 删本地 `kv:block:<qq>` ＋「解除拉黑动作」 | 同上（归属硬判非主人拒；平台动作走 `E`） | 解除拉黑（本地删掉即恢复触发） |
| `blocklist` | **无平台动作**（纯本地读） | 归属硬判（非主人一律拒，拒绝文案里不带名单内容） | 看本地黑名单里有谁（NapCat 侧看不到这份名单） |
| `like` | `send_like` | `E`（非主人默认拒） | 点赞，「默认点赞次数」缺省 |
| `self` | `get_login_info` | `E`（非主人默认拒） | 机器人自己的账号（QQ/昵称） |
| `poke` | `group_poke`（有群号）/ `friend_poke`（无群号） | `E`（非主人默认拒） | 戳一戳：群里带 group_id，私聊只带 user_id |
| `rename` | `set_qq_profile`（只发 nickname） | `E`（非主人默认拒） | 改机器人自己的 QQ 昵称（E 类：非主人默认拒、她本人 SYSTEM 照常；可按人写账本 E 例外） |
| `signature` | `set_self_longnick` | `E`（非主人默认拒） | 改机器人自己的个性签名（同上） |

## 两套"拉黑"：本地是权威，平台是尽力（重要）

**为什么要有本地那一套**：QQ 层面的拉黑/删好友**管不到群内互动** ——
NapCat 没有"群内屏蔽某人"这类动作，对方被你在 QQ 上拉黑了，**照样能在群里 @ 机器人**。
所以本地黑名单补的就是这一刀：

| | 本地黑名单（权威） | 平台动作（尽力） |
|---|---|---|
| 存哪 | kv 键 `block:<qq>`（存在且值非空 = 已拉黑；值 `{reason,at,by}`） | NapCat 动作，名字读 `prompt.md` |
| 谁读 | **基板入站网关**（`QqGateway.blocked`）＋ 本技能 `blocklist` | QQ 客户端 |
| 效果 | 这个人的消息**不触发 AI**（私聊与群内**一视同仁**）；消息本身**照旧记进 grouplog** 留痕，日志里写明「本地黑名单：已拉黑，不触发」 | 尽力让 QQ 侧也拉黑（对方视角） |
| 失败了怎么办 | 写失败时返回「本地黑名单没写进去…这一条没生效」，并且**不发平台动作**（别做半套） | 没配动作名 / 不支持 / 没连接 → **不回滚本地**，原因原样拼进 `{act}` |

```
拉黑动作: set_friend_block        # 你的 NapCat 构建支持什么就填什么；留空 = 只做本地
解除拉黑动作: set_friend_block
```

- **先写/删本地黑名单，再发平台动作**；返回文案里的 `{act}` 就是平台那一步的结果
  （「平台动作已执行」/「未配置，跳过」/ NapCat 原样错误）。
- NapCat 的 OneBot v11 动作目录里**没有**"屏蔽好友"这一类动作（`Api.catalog()` 也没有），
  所以动作名是配置项；出厂值 `set_friend_block` 只是命名上最接近的猜测。
- 想知道本地到底拉黑了谁：`friend op=blocklist`（**只有这条路能看到**，QQ 那边看不到本地名单）。

## 权限口径

1. **工具可见性按 `T:X` 筛**（`ALLUSER` 默认 `T=无` ⇒ 他的工具清单为空；工具是她的手段，属 T 类、只判入口）：能不能答应对方看事实块 `caller.bits`
   （五类各有什么位；`ALLUSER` 默认 `T` 无 ⇒ 非主人一把工具都用不了，要特例放行），不看工具名。`friend` 的每个 op 都要发 NapCat 动作，所以一律走
   **E 类对外动作**判定（发动作前 `h.needPlatform(<动作名>)`，查 `E` 位；权威闸门 =
   `Boot` 里 guardedApi 上那条 `Res.platform(action)` 的 `X` 位）。
2. `ALLUSER` 默认 `E` 无（`Acl` 的 `DEF_E = NONE`）⇒ **非主人默认一律拒**，
   回基板那句带 `[权限阻断]` 的原文（技能不自己编）；要放开只能由主人在账本
   `data/perms.json`（v3 的例外条目）里写，例如 `E["User<QQ>","send_like","X"]` = 只给这个人点赞。
   主人恒全权（`MASTER` = 全 `RWX`）；她自己（`SYSTEM`）的 E = `RWX`（`Acl.SYS_E = Bits.ALL`）。
3. `block` / `unblock` / `blocklist` 另有一道**归属硬判**（`FriendSkill.ownerDeny` /
   `FriendSkill.readOwnerDeny`：`MASTER` 与 `SYSTEM` 照常放行，`ALLUSER` 一律拒）：本地黑名单是一份
   **全局共享**的名单（kv 键 `block:<qq>` 里只有"被拉黑的人"，没有"谁拉的"这一维度），
   而 C 类对非主人只有 `R`（写被位拦下）⇒ `h.needDb` 拦得住普通用户的写。**"非主人写一律被位拦下"这条防线
   回来了**；归属硬判仍然保留（代码里的硬判没删），隔离不只靠权限位，也靠技能自己硬判（归属判定，不是权限位）。
4. 本地那一半落在通用 kv 表（C 类运行时数据）：写前仍过一次 `h.needDb("kv",'W')`，
   但它现在只回答"库能不能写"，不回答"这是不是你能碰的数据"。
5. `rename` / `signature` 改的是机器人自己的账号资料，`delete` / `like` / `poke` 同样是对外动作
   —— 都走上面同一条 E 类判定，没有额外的主人专属键。

## 配置与文案

全在同目录 `prompt.md`（运行期读，改即生效）：`启用`、`默认点赞次数`、`好友列表最多`、`黑名单最多`、
`时间格式`、`拉黑动作`、`解除拉黑动作`，以及全部输出文案与模板（含 `{act}` 平台动作结果占位）。
值留空 = 用技能里的结构性 ASCII 兜底。

## 典型用法

```
friend op=list                       # 好友列表
friend op=info qq=10001              # 陌生人资料
friend op=info qq=10001 group=123456 # 这个人在群里的名片/角色
friend op=self                       # 我自己的账号
friend op=like qq=10001 times=10     # 点赞
friend op=delete qq=10001            # 删好友（非主人默认拒；她本人 SYSTEM 照常）
friend op=block qq=10001 reason=广告 # 拉黑：本地黑名单（权威）+ 尽力发平台动作
friend op=blocklist                  # 本地黑名单里有谁（仅主人与她本人 SYSTEM）
friend op=unblock qq=10001           # 解除拉黑（本地删掉即恢复触发）
friend op=poke qq=10001              # 戳一戳（当前群）
friend op=poke qq=10001 group=123456 # 戳某个群里的人
friend op=rename name=椰羊            # 改机器人昵称（非主人默认拒；她本人 SYSTEM 照常）
friend op=signature signature=你好呀   # 改机器人签名（同上）
```
