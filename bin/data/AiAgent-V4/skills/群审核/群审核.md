# 群审核（`on_message` 钩子 + 工具 `moderation`；写配置另有归属 / 角色硬判）

每条入站消息都会被基板派发到 `on_message`；本技能**逐条**判定（不等被 @），命中就处置。技能删掉 → 审核能力彻底消失。

## 配置与文案在哪

| 层 | 位置 | 管什么 |
|---|---|---|
| **全局默认** | 技能自己的 `prompt.md` | 启用 / 违规词 / 禁言秒数 / 跳过群 / 豁免角色 / 豁免QQ / 警告文案 / 规则说明（**出厂 `违规词` 为空 = 默认不审**） |
| **按群覆盖** | `kv` 的 `modcfg:<群号>`（一行 JSON） | 同一个群的开关/词表/时长/豁免/文案，**只覆盖给了的键** |
| **改的入口** | 工具 `moderation` 的 `op=config`（读谁都能看；写要主人、她本人（SYSTEM）或本群群主/管理员）或直接改 `prompt.md` | 运行期改策略 |

**生效值 = 全局默认 → 被 `modcfg:<群号>` 里给了的键覆盖**。没有该群的 `modcfg` 键 = 完全走全局默认；出厂全局词表为空 ⇒ 既没配全局词、也没配 `modcfg:<群号>` 的群**一条都不审**（不是"宽松审"，是根本不进判定）。
改完 `prompt.md` 每次判定即时重读（机制不是热重载 —— 目录监听的热重载管的是 `.java` 的重编译与重装）；改 `modcfg` 立刻生效（每次命中现场读）。

```
# prompt.md（全局默认）
启用: true                      # 没写或不为 true → 这些群不动作
违规词:                        # 出厂为空 = 默认不审；要审就填，例如 加群,扫码（逗号分隔，命中任意一个即违规）
禁言秒数: 600                   # < 60 会被抬到 60
跳过群:                          # 这些群完全不审核（全局口径；按群用 on: false）；出厂留空 = 所有群都审
豁免角色: owner,admin           # 群主/管理员不审核
豁免QQ:                          # 白名单：这些 QQ 号不处理；出厂留空 = 没有豁免的个人
警告文案: {name} 这条消息里有「{word}」，先安静 {mute} 秒。
规则说明:                        # 群规说明，给人/模型看，不参与判定
```

```
# kv: modcfg:<群号>（按群覆盖，JSON；工具 moderation op=config 写的就是它）
# 下面是**示例**：出厂没有任何按群配置，要审某个群才写它
{"v":2,"on":true,"words":["加群","代发"],"mute":1800,
 "roles":["owner","admin"],"users":[10001],"warn":"…","note":"…",
 "updated":1699999999999,"by":10001}
```

### 与 V3 的键对齐（`modcfg:<群号>`）

V3 落在 `app_state` 的键就是 `modcfg:<群号>`（一个群一条）。**键名沿用，值改成 JSON（V4 新口径）**，
字段一一对应：

| V3 字段 | V4 键 | 说明 |
|---|---|---|
| `autoMonitorEnabled` | `on` | 这个群审不审 |
| `customViolationKeywords` | `words` | 违规词（大小写不敏感） |
| `violationMuteDuration` | `mute` | 禁言秒数（< 60 抬到 60） |
| `whitelistUsers` | `users` | 豁免 QQ（白名单） |
| `ruleDescription` | `note` | 群规说明（不参与判定） |
| （V3 无对应字段） | `roles` | 豁免角色（V3 把群主/管理员硬写在判定里，V4 可配） |
| `monitorIntervalSeconds` / `messagesPerCheck` / `spamCheckEnabled` / `adCheckEnabled` | **无对应** | V4 是逐条 `on_message` 判定，没有轮询取样，也没有刷屏/广告检测器；这些字段不搬 |

## 处置流程（严格按这个顺序）
1. 只处理群消息；私聊、空文本直接跳过；
2. **现场算出生效配置**：`prompt.md` 全局默认 + `modcfg:<群号>` 覆盖 → 不启用 / 词表为空就结束；
3. 跳过：全局 `跳过群` 命中、`豁免角色` 命中、`豁免QQ` 命中、主人（`caller.master`）→ 直接放过；
4. 命中违规词 → 记录（`kv.mod_last` 存一条 JSON，`kv.mod_count` 计数）+ 控制台日志；
5. **执行前先判定机器人自己在群里有没有执法权**：
   ```java
   h.selfIsGroupAdmin(e.groupId())
   ```
   不是管理员（或 NapCat 未连接）→ **只记录，不执法**；
6. 有执法权且 NapCat 已连接 → `h.napcat().setGroupBan(group, qq, 秒数)`；
   禁言成功才发警告（`h.napcat().sendGroupMsg`），失败只记录；
7. NapCat 未连接 → 只记录日志（`napcat: disconnected` 时基板本来也发不出动作）；
8. 命中并处理完 → `payload._handled = true`，基板不再自动回复这条消息（不跟违规内容纠缠）。

## 工具 `moderation`（`op=config`）

```
op=config                     读：当前会话所在群（或 group 指定的群）的生效配置
op=config group=123456        读：指定群
op=config group=123456 words=加群,代发 mute=1800
                              写：只改给了的键，其余继续用全局默认
op=config group=123456 clear=true
                              写：删掉该群的按群配置，回到全局默认
```

- **读**：`op=config` 的读只读通用 kv 表（C 类的 `R` 位）与 `prompt.md` —— 谁问都给看；
- **写**：另过一道**归属 / 角色硬判**（`ModCfg.writeDeny`）：主人（`MASTER`）与她自己的
  自主行为（`SYSTEM`）照常；`ALLUSER` 只能写**自己所在的那个群**、且必须是该群**群主 / 管理员**，
  **跨群一律拒**（拒绝文案带 `[权限阻断]` 标识）。所以"谁问得出来"和"谁改得动"是两拨人；
- 输出里带**来源**（`prompt.md` 或 `modcfg:<群号>`），一眼看出这个群是在吃全局默认还是有自己的配置；
- 所有话术在 `prompt.md` 的「文案」一节，**缺键 = 明确回 `prompt.md missing text: 键名`**，没有兜底话术。

## 为什么用"机器人自己的身份"而不是违规者的身份
钩子是由**基板**触发的（有人发了条消息），执法动作是**机器人自己**做的：
审核一个普通成员时，"机器人在不在群里当管理员"才是能不能禁言的关键，
而不该问"这个违规者有没有权限去禁言自己"。
所以基板在派发 `on_message` 时绑的主体是**她自己**（`SYSTEM`，见 `Skills` 的 `dispatch(hook, payload)` → `hookActor()`），动作闸门按 `SYSTEM` 判；
`h.caller()` 仍然是**发言者**，供技能做策略判断（豁免、记录、文案变量）。

## 落库 / 观测
| 键 | 内容 |
|---|---|
| `kv.mod_last` | 最后一条命中记录 JSON：`{ts,group,qq,name,word,action,text,mute,cfg}`（`cfg` = 这次用的配置来源） |
| `kv.mod_count` | 累计命中次数 |
| `kv.modcfg:<群号>` | 该群的按群配置（没有这个键 = 走全局默认） |
| 控制台 | `[群审核] …` 日志（命中词、处置结果、配置来源、跳过原因） |

`action` 取值：`muted`（已禁言+警告）、`denied`（机器人无执法权或未连接，只记录）、`offline`（NapCat 未连接）、`failed:<原因>`（NapCat 报错）。

## 部署
`<数据目录>/skills/群审核/` 下五个文件：`群审核.md`、`prompt.md`、`ModerationSkill.java`（入口类：钩子转发 + 工具 `moderation`）、`ModerationHook.java`（`on_message` 判定与执法）、`ModCfg.java`（全局默认 + 按群配置的读取口径）。
改 `prompt.md` = 改全局策略（**每次判定即时重读，不用重载**）；改 `modcfg:<群号>`（或让 AI 调 `moderation op=config`）= 改某个群（同样即时生效：每次命中现场读）；改 `.java` = 改逻辑（**要重建/重载才重编译**：`skill_write op=reload` 或重建部署）。
