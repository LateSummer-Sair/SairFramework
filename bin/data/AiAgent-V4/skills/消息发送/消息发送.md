# 消息发送（工具 `send`，每个 op 都是 E 类对外动作）

一个技能一件事：**往外发**（外加"把自己的话收回来"）。八个 op 覆盖 V3 那批"发消息 / 发文件 / 发语音 / 转发 / 转告"的碎工具，
出口只有一个，权限口径也只有一套。

## op 表

| op | 干什么 | 必需参数 | 落点 | 实际动作 | 权限判定 |
|---|---|---|---|---|---|
| `group` | 群发，可 @ 或 @全体 | `text` | `group` 缺省=当前群 | `send_group_msg` | `send_group_msg`（E `X`） |
| `private` | 私聊发一句 | `text` | `qq` 缺省=当前私聊对象 | `send_private_msg` | `send_private_msg`（E `X`） |
| `file` | 把文件发到**当前会话** | `file` | 当前会话 | `upload_group_file` / `upload_private_file` | 同名动作（E `X`） |
| `fileto` | 把文件发给**指定的人** | `file` `qq` | 指定 QQ | `upload_private_file` | `upload_private_file`（E `X`） |
| `record` | 发语音 | `file` | `qq`/`group` **显式优先**，都没给才用当前会话（控制台给了目标也照发） | `send_group_msg` / `send_private_msg` + `record` 消息段（**没有**"发语音"这个独立动作） | 同名动作（E `X`），另加 `can_send_record` 风控预检 |
| `forward` | 历史消息 → 带出处的文本 → 发 | `ids` | `group`/`qq` 缺省=当前会话 | `get_msg`（+`get_forward_msg`）+`send_*_msg` | `get_msg` / `get_forward_msg` / 发送动作（E `X`） |
| `relay` | 把一句话转告给某人 | `qq` `text` | 指定 QQ（私聊） | `send_private_msg` | `send_private_msg`（E `X`） |
| `recall` | **撤回自己发的消息**（按范围批量） | 范围三选一：`message_ids` / `last` / `within`（`since`/`until`） | `scope`（`group:群号` / `user:QQ号`）缺省=当前会话；只给 `message_ids` 时可以不给 | `get_group_msg_history` / `get_friend_msg_history`（挑消息）+ `get_msg`（核发送者）+ 逐条 `delete_msg` | 拉历史动作 / `get_msg` / `delete_msg`（都是 E `X`；`delete_msg` **每一条都单独判一次**） |


## 语音 vs 文件（两条路，别混）

| 想要的效果 | 用哪个 op | 走什么 |
|---|---|---|
| 对方**点开就能听**的语音条 | `record` | `send_private_msg` / `send_group_msg` + `record` 消息段，即 `[{"type":"record","data":{"file":"…"}}]`（等价于 CQ 串 `[CQ:record,file=…]`） |
| 把**文件本身**发过去（对方下载/另存） | `file`（当前会话）/ `fileto`（指定人） | `upload_group_file` / `upload_private_file` |
| 把历史消息整理成文字 | `forward` | `get_msg`（+`get_forward_msg`）读、`send_*_msg` 发 |

- **mp3 不等于"能当语音发"**：`record` 那条路要求 NapCat 能把这段音频当语音处理（一般是它能转的格式）；
  转不了时**不会**悄悄变成文件发出去 —— 而是明确回一句"语音没发出去"并把平台原始回执带上。
  要保底就两条都发：先 `record`，失败了再 `fileto`。
- 两条路的文件参数都给**本地绝对路径**即可 —— 中转 URL / `file:///` 的改写由基板 `Api.call` 统一做，技能不拼 URL。
- `record` 的落点：**给了 `qq`（或 `group`）就发给它**，一个都没给才回落到当前会话。
  所以本地控制台里"发给某个 QQ 一段语音"是能发出去的（`send {op:record, file:"D:\\x.mp3", qq:1284688456}`）。

## `recall`：按范围撤回（只撤她自己发的）

**范围至少给一个**，三选一：

| 给什么 | 什么意思 | 细节 |
|---|---|---|
| `message_ids`（或 `message_id` 单条） | 点名撤这几条 | 数组 / 逗号分隔串都认；给了它就**不拉历史**，逐条核发送者再撤 |
| `last` | 最近 N 条**她自己发的** | 上限 100；不填 = 不按条数限（看时间窗圈出多少） |
| `within` | 时间窗（秒） | 默认 120 秒；`since` / `until`（毫秒时间戳）能精确指定窗口，给了这两个就不看 `within` |

- **落点**：`scope`（`group:<群号>` 或 `user:<QQ号>`）；不填 = 当前会话。
  从本地控制台发起且没给 `scope` 时会明确回「缺会话」并给出正确用法；`group` / `qq` 两个参数也当**兼容写法**收，但推荐直接用 `scope`。
  **只给 `message_ids` 时不需要落点**（按 id 撤，不必先知道在哪个会话）。
- **怎么找**：拉历史 —— 群 `get_group_msg_history`、私聊 `get_friend_msg_history`
  （`count = max(撤回历史条数, last*3)`，不超过 100），从返回里取每条消息的 `message_id` 与发送者，
  **只留她自己发的**（发送者 QQ == `conf.selfId()`），再按 `last` / 时间窗筛，最后按时间从新到旧取。
- **`last` 与时间窗是"都要满足"**：`last` 只数条数、时间窗只圈时间，两个都给就都要满足（窗口内、且最多 N 条）；
  **只给时间窗、不填 `last`** 时取窗口内她自己发的**全部** —— 主人说的"给定一个范围就批量撤"要的就是这个，
  条数由单次上限（`撤回最多条数`）兜底，超出的在回执里报"还有 N 条没撤"。
  时间拿不到的消息**不算窗外**（判不了就不替调用方判），但会照样计入候选。
- **别人的消息一条都不碰**：历史里不是她发的（发送者 ≠ `selfId()`）直接跳过，并在回执里说明跳过了哪几条；
  **哪怕她是群管理员、哪怕调用方点名要求撤别人的，这条路也不做** —— 遇到就回「只能撤我自己发的」。
  `message_ids` 那条路会先 `get_msg` 核实发送者，不是她的就跳过；核实不了（没权限 / 取不回 / 认不出发送者）
  会**如实标注"未核实"**之后照撤（主人点名要撤的），绝不假装核实过。
- **限额与节流**：单次最多撤 `撤回最多条数` 条（默认 20）；超了**不报错**，撤到上限，并在回执里说"还有 N 条没撤，再调一次接着撤"。
  条与条之间睡 `撤回间隔毫秒`（默认 300ms），避免连着撤触发平台风控。
- **回执**：`requested`（这次要撤几条）/ `recalled`（真撤掉几条）/ 逐条 `failed`（带平台原始 `retcode`/`status`/`message`）/
  逐条 `skipped`（带原因），最后一行是结构化的
  `撤回汇总 requested=… recalled=… failed=… skipped=… others=… capped=…`
  （`skipped` = 点名里跳过的不属于自己的条数；`others` = 历史里别人发的、一条没碰；`capped` = 超单次上限没撤的）。
  整批都失败时明确说"一条都没撤掉"，平台/账号层面的限制（QQ 对"自己的消息"有撤回时限、超时或没权限会被平台拒）
  **照样原样回报，绝不假装成功**。

### `recall` 回执长什么样

```
已撤回 3 条（群 888888），另有 1 条没撤掉
10003 撤不掉：retcode=1200 status=failed message=消息不存在或不在可撤回时间内
10004 跳过：只能撤我自己发的消息 —— 这条是 10086 发的，我自己的 QQ 是 12345；别人的消息我不撤，哪怕是管理员也不撤
（历史里另有 2 条不是我发的（10086、10087），一条都没碰）
这次最多撤 4 条，还有 1 条没撤 —— 再调一次（同样的范围，或者带上 last）就接着撤
撤回汇总 requested=4 recalled=3 failed=1 skipped=1 others=2 capped=1
```

### 例子

- 群里刷屏了，撤她自己刚发的那几条：`send {op:recall, last:5}`（当前群 + 默认 120 秒窗口）
- 换个群撤、时间放宽到 10 分钟：`send {op:recall, scope:"group:888888", last:10, within:600}`
- 私聊里撤回：`send {op:recall, scope:"user:1284688456", last:2}`
- 从控制台精确点名撤（不需要落点）：`send {op:recall, message_ids:[10001,10002]}`
- 只撤某一段时间窗里的：`send {op:recall, scope:"group:888888", since:1700000000000, until:1700000600000}`

## 动作名以 `Api.catalog()` 为准（禁止猜接口名）

- 支持与不支持哪些动作，**唯一答案**是基板 `src/sair/v4/qq/Api.java#catalog()`；
  模型侧的等价物是 `napcat` 工具的 `action=list`（只列出该主体有 E `X` 位的动作）。
- 本机版本目录里**没有** `send_record`、也没有 `send_group_record` / `send_private_record`
  —— 真机拿 `send_record` 去调 `napcat` 工具，拿回的是
  `{"status":"failed","retcode":1404,"message":"不支持的Api send_record"}`（白绕一圈）。
  目录里跟语音有关的是 `get_record`（取语音文件）与 `can_send_record`（能否发语音·风控状态）。
- 也**没有** `send_group_file` / `send_private_file` 这类别名：文件上传的真实动作名就是
  `upload_group_file` / `upload_private_file`。
- 撤回用的是目录里现成的 **`delete_msg`**（参数就一个 `message_id`），拉历史用 **`get_group_msg_history`** /
  **`get_friend_msg_history`**（`group_id` / `user_id` + `count`），核发送者用 **`get_msg`** —— 都不需要新动作，也没有别名可猜。
- 结论：**发消息 / 发文件 / 发语音 / 撤回一律从本技能（`send`）走**，别去 `napcat` 工具里手拼动作名。

## 权限：每个 op 都按 E 类（对外）的 `X` 位判定

八个 op 一律把"要做的那个平台动作"交给基板判（`h.needPlatform(动作)` → `Res.platform(动作)` 的 `X` 位）：
`send_group_msg` / `send_private_msg` / `upload_group_file` / `upload_private_file` /
`get_msg` / `get_forward_msg` 都是 **E 类对外动作**。按类默认分配：
`MASTER` 全 `RWX`、`SYSTEM`（她自己的自主回复）E = RWX（`Acl.SYS_E = Bits.ALL`）、`ALLUSER` **E 无** ——
所以普通用户默认**发不出去**（技能先按 E 位判一道、基板 `h.napcat()` 闸门再判一道，
拒绝文案带 `[权限阻断]` 标识）；
要放开得主人在账本 `data/perms.json`（v3）里写**例外条目**（`perm` 工具的授权 op），改 md 无效。
`forward` / `relay` 没有额外的 op 级复核：它们的判据就是上面那几个动作的 E 位。
`record` 多发一次 `can_send_record`（也在 `Api.catalog()` 里）—— 那是**风控预检**，不是新闸门：
它被拒或查不动时**照样发**，只有平台明确回 `yes=false` 才提前收手并说明原因。
`recall` 的判据是 `delete_msg` 的 E `X` 位（拉历史 / `get_msg` 各自再判一道），并且**每撤一条都重判一次**：
非主人整把被拒，ACL 的拒绝原文原样回给模型。
工具可见性按 `T:X` 筛（`ALLUSER` 默认 `T=无` ⇒ 他的工具清单为空；她的手段属 T 类、只判入口）；能不能答应对方，看事实块 `caller.bits`（五类各有什么位；`ALLUSER` 默认 `T=无` ⇒ 非主人一把工具都用不了，要特例放行）。

## 四条纪律

> 现在是五条：前四条管"发"，第五条管"撤"（`recall`）。

1. **复核再动手**：每个 op 先 `h.needPlatform("<动作>")`（E 类 `X` 位判定），
   不过就把那句拒绝文案原样返回（技能里没有硬编码门槛：判定只看账本 `perms.json` 的例外条目，
   一条都没命中就按类默认分配）。
   `h.napcat()` 那层还有一道闸门（同一个 E 类判据），两道都要过。
2. **未连接不硬发**：参数校验与权限复核之后、真正发之前查一次连接；
   未连接一律返回基板的 `Napcat 没有连接`，不做任何"先记下来以后再发"的小动作。
3. **取不回就说清楚**：`forward` 逐条 `get_msg`，取不回的**明确列出**是哪一条、为什么（错误串）；
   一条都取不回时整条不发，只回"取不回"的说明 —— 绝不把空消息发出去。
   `recall` 同理：拉不到历史就回"撤不了 + 平台错误"，撤不掉的**逐条列出**，整批失败就明说"一条都没撤掉"。
4. **失败要说清是谁拒绝的**：平台回执里的 `retcode` / `status` / `message` 原样带给调用方
   （例如 `retcode=1404 status=failed message=不支持的Api send_record`）；
   发语音还会先过 `can_send_record`（账号风控）并把结论说明白 ——
   绝不把"发不出去"糊成一句没有线索的话，也绝不说成"发出去了"。
5. **撤回只撤自己的**（`recall` 独有）：历史里只挑发送者 == `conf.selfId()` 的消息，
   别人的消息即便她是管理员、即便调用方点名也不碰（回"只能撤我自己发的"）；
   核不实发送者的条目照撤但会标注"未核实"，不假装核实过。

## `forward` 的转述文本

```
<text 里的附加说明，可省>
转述 群里的张三 的 2 条消息：
08-14 20:11 张三(10001)：明天下午三点评审
08-14 20:12 李四(10002)：收到，我拉个会
（另有 1 条取不回：10003 get_msg 失败 Napcat 没有连接）
```
- 行格式 / 头 / 出处缺省 / 时间格式 / 分隔 / 各种消息段占位符**全在 `prompt.md` 的 `## 配置`**；
- 图片、语音、表情、文件、卡片只留占位符（不下载、不转存）；
- 消息本身就是合并转发时，顺手用 `get_forward_msg` 展开一层（同样受 `最多转述条数` 约束）。

## 边界与取舍

- **不自己解析 CQ 码语义**：字符串消息里的 `[CQ:xxx,...]` 与消息段数组都归一到同一套占位符；
- **落点只认参数与当前会话**：`group` / `private` / `record` / `forward` / `recall` 都是"**显式参数优先，其次当前会话**"，
  技能不会替模型"猜一个群"；控制台没有 QQ 会话，所以从控制台发起时**必须**把 `qq`（或 `group`）指明
  （`recall` 用 `scope`，或者直接给 `message_ids`）；
  `file` 是唯一例外 —— 它按定义只发**当前会话**，要发给指定的人用 `fileto`；
- **撤回不是"删别人的话"**：`recall` 的能力边界就是"把她自己刚说的话收回来"，
  定位全靠拉历史 + 比 `selfId()`；历史接口返回的消息数组形状在不同实现里不一样
  （`data.messages` / `data` 数组 / 单个消息对象都认），认不出形状时回执会带上**原始返回片段**，不硬猜；
- **本地文件只传绝对路径**：`file` / `fileto` / `record` 的本地文件交给 `h.napcat()` 时**直接给本地绝对路径**即可 ——
  NapCat 在别的机器上时，基板在 `Api.call` 里统一把它改写成"文件外链中转"的 URL；没开中转则退回本机 `file:///`。
  技能不拼 URL、不起服务、不 base64（详见 `docs/skills.md` §4.1）；
- **发文件与发消息同一类**：`upload_group_file` / `upload_private_file` 和
  `send_group_msg` / `send_private_msg` 一样都是 **E 类对外动作**（真实动作名就是 `upload_*`，
  目录里没有 `send_*_file` / `send_*_record` 这类别名），一律按 E 的 `X` 位判定 ——
  所以 `file` / `fileto` 与 `private` **同口径**：普通用户默认没有 E 位、用不了，
  `MASTER` 与她自己的自主回复放行；
- **删掉即消失**：技能目录整体删掉，`send` 工具就没了，基板照常运转；
- **撤回的配置全在 `prompt.md`**：`撤回最多条数`（默认 20）、`撤回间隔毫秒`（默认 300）、
  `撤回默认时间窗秒`（默认 120）、`撤回历史条数`（默认 50）—— 改 md 即可，Java 里只有结构性上限（100 / 100）。
