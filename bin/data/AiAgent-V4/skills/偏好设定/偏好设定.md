# 偏好设定（工具 `pref` —— 每个人都有偏好设定的权力；能不能用看技能管控表的 op，越权靠技能自己的归属硬判）

把"偏好/约定"当成 key/value 存起来，**三个作用域**分开放：

| 作用域 | `scope` | `scope_id` | 典型内容 |
|---|---|---|---|
| 个人 | `user` | QQ | 这个人喜欢多长的回答、叫他什么 |
| 群 | `group` | 群号 | 这个群的规矩、别聊的话题 |
| 全体 | `global` | 空 | 全机器人通用的口径 |

落在六库的 **`pref` 库**（`id/ts/scope/scope_id/key/value/importance/extra`），只有 `h.store()`，不自己写 SQL。
`extra` 里记 `{"by":谁改的,"by_name":…,"updated":时间}`。

## 三个 op

### `set` —— 写（存在就覆盖）
- `key` + `value` 必填；`scope` 默认 `user`；`scope_id` 不填 = 当前的人 / 当前的群；
- 同一个 `(scope, scope_id, key)` 只有一行：命中就覆盖，返回"已更新"，否则"已新增"；
- `value` 超长（`prompt.md` 的「值长度上限」）直接拒绝；
- `importance` 不给就**按身份取三段定式**（不看好感度）：`MASTER`（主人）= `MAX`、
  `SYSTEM`（她自己的自主行为）= `HIGH`、`USER`（= `ALLUSER`：群 + 普通个人）= `LOW`。
  **三个数值只写在 `prompt.md`** 的 `重要度-MASTER` / `重要度-SYSTEM` / `重要度-USER`
  —— Java 里没有任何档位默认值；**缺键或值不是整数 = 明确拒绝这一笔写入并点名缺的键**
  （`[偏好设定] prompt.md 缺键：重要度-XXX`），不猜、不兜底（只影响写：读 / 列既有数据不看这张表）。
  显式给了 `importance` 的写入直接用给的值（越界夹到 `0..10`），不查这三个键 —— 行为同改动前。
- **为什么要分档**：三层偏好（本人的 `user` + 当前群的 `group` + `global`）每一轮合并成一份清单注入
  系统提示词，同一个 `key` 只留一条 —— 先看 `importance`（大的赢），打平才看作用域具体度。
  所以要保证 **主人 > 她本人 > 群里 / 普通人**：主人定下的口径要压得住任何人的个人偏好，
  她自己的自主行为写下的判断次之（**`SYSTEM` 允许有自己的偏好**：定时维护、钩子、她主动记下的东西
  不是"某个普通用户"写的，优先级高于任何群与个人，但低于主人），全体用户与群最低。
  身份判定：主人标志（含本地控制台）> 显式 `SYSTEM` 标志（`kind()==SYSTEM`）> 其余一律 `USER`；
  取不到调用者 ⇒ 按 `USER`（最低档，fail-closed）。

### `get` —— 读
- 给了 `scope`：只查那一层；
- **不给 `scope`**：按 `user(本人)` → `group(本群)` → `global` 逐层找，命中哪层就说哪层 —— 这样"这个人有没有特别设定"一次调用就能问清；
- 没命中如实说"没有这个偏好"，不编。

### `list` —— 列
列某个作用域下的全部条目（`key` 升序），默认列本人的 `user` 作用域。

## 归属硬判（每个人都有偏好设定的权力，但只能动自己的那一层）

本技能三个 op 写在技能管控表（数据根 `skillctl.json`）里：`pref.get`（读一个）、`pref.set`（写一个）、
`pref.list`（列一个作用域）；`MASTER` 与她本人 `SYSTEM` 恒全权，`ALLUSER` 按表判（`Run` = 可用、
`Ban` = 不可用、**空 = 未授权**）。**但 op 授权只回答"能不能用这个动作"**，回答不了"这是谁的数据" ——
数据隔离仍靠归属硬判（读口与非本人行都靠它），判的是**代码里的显式归属**：

| 作用域 | 非主人（`ALLUSER`） | 代码位置（符号名） |
|---|---|---|
| `user`（本人） | 放行（`scope_id == 自己 QQ`） | `PrefSkill.guardWrite` / `PrefSkill.guardRead` |
| `user`（别人） | **拒**（读与写都拒） | `PrefSkill.guardWrite` / `PrefSkill.guardRead` |
| `group`（本群） | 放行：**只能动自己当前所在的那个群** | `PrefSkill.guardWrite` / `PrefSkill.guardRead` |
| `group`（别的群） | **拒** | `PrefSkill.guardWrite` / `PrefSkill.guardRead` |
| `global` | **写拒**；读放行（全体口径人人可读） | `PrefSkill.guardWrite` / `PrefSkill.guardRead` |

主人（`MASTER`）恒全权；她自己的自主行为（`SYSTEM`）照常。身份（群主/管理员）不再是判据。
要放开"非主人也能写"，是两件事一起做：给这个身份放行 `pref.set`（技能管控表），
并按需改归属口径（后者不在本轮范围）。
拒绝文案统一带 `[权限阻断]` 标识（**值同** `Acl.DENY_PREFIX`；技能里用常量 `DENY` 钉住，不随配置变）：
**前缀**由代码保证，**理由句**由归属硬判自己拼（`PrefSkill.blocked(...)`），不走 `prompt.md`。

## 设了之后谁看得到

写进去的偏好不是"躺着等人来查"：三层（`global` + 本人的 `user` + 当前群的 `group`）会在**每一轮**
被合并成一份清单注入模型的系统提示词（同一个 `key` 只留一条，`importance` 大的赢、打平则
`user` > `group` > `global`；条数与字符都有预算，超了先丢 `importance` 最小的）。
正因为"同一个 `key` 只有一条会活下来"，写的时候才要按身份分档（主人 `MAX` > 她 `HIGH` >
普通人 / 群 `LOW`）—— 否则随便一个人给自己写一条，就能把主人设的全局口径顶掉。
所以"以后都这样"这类要求，写进来就是真的以后都这样。

## 什么时候用哪个
- 只想对一个人生效 → `user`；
- 一个群的约定 → `group`；
- "以后对所有人都这样" → `global`（主人与她本人可写；普通用户与群拒）。
- 要记**事实/经历**用 `memory` / `note`；这里放的是**设定**（"以后照这个来"），别把两者混着写。
