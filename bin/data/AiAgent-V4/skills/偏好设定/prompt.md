## 文案
# 这些是技能面向用户/模型说出来的话；占位符由 Java 替换。某一行删掉时，技能只回结构性结果（不会崩）。
文案-命中: {key} = {value}　（{scope}:{id}，重要度 {importance}，{time} 记的）
文案-无此偏好: 没有找到 {key} 这个偏好（本人 / 本群 / 全局都没写过）。
文案-已新增: 已记住：{scope}:{id2} 的 {key} = {value}（#{id}，重要度 {importance}）
文案-已更新: 已更新：{scope}:{id2} 的 {key} = {value}（#{id}，重要度 {importance}）
文案-列表头: {scope}:{id} 下有 {n} 条偏好：
文案-列表行: - {key} = {value}　（重要度 {importance}，{time}）
文案-该作用域为空: {scope}:{id} 下还没有任何偏好。
文案-作用域非法: 作用域只能是 user / group / global（收到「{scope}」）。
文案-缺作用域号: 这个作用域需要 scope_id（user 填 QQ，group 填群号）。
文案-值太长: 值太长了（上限 {limit} 字），拆短一点再写。
文案-写入失败: 写不进 pref 库（六库写入失败）。
文案-无库: 拿不到六库接口，技能不可用。
文案-未知op: 不支持的 op：{op}（只支持 get / set / list）
文案-执行异常: 执行异常：{error}

## 备注（不解析）
# 默认作用域：set 不给 scope 时写哪一层（user = 写自己的）。
# 列表默认作用域：list 不给 scope 时列哪一层（user = 列自己的）。
# 列表条数：list 不给 limit 时最多列几条。
# 重要度（三段定式，按身份、不看好感度）：set 不给 importance 时按主体身份取档 ——
#   重要度-MASTER（主人）= MAX、重要度-SYSTEM（她自己的自主行为）= HIGH、重要度-USER（= ALLUSER：群 + 普通个人）= LOW。
#   三个数值只写在这里（Java 里没有任何档位默认值）；缺键、或值不是整数 = 明确拒绝这一笔写入并点名缺的键
#   （[偏好设定] prompt.md 缺键：重要度-XXX），不猜、不兜底；只影响写，读/列既有数据不看这张表。
#   显式给了 importance 的写入直接用给的值（越界夹到 0..10），不查这三个键（行为同改动前）。
#   身份怎么定的：主人标志（含本地控制台）> 显式 SYSTEM 标志（kind()==SYSTEM）> 其余一律 USER；
#   取不到调用者 ⇒ 按 USER（最低档，fail-closed）。
#   为什么要分档：三层偏好（本人的 user + 当前群的 group + global）每一轮合并成一份清单注入系统提示词，
#   同一个 key 只留一条 —— 先看 importance（大的赢），打平才看作用域具体度。所以要保证
#   主人 > 她本人 > 群里/普通人：主人定下的口径要压得住任何人的个人偏好，她的自主行为次之，全体用户与群最低。
#   为什么 SYSTEM 也有自己的一档：她的自主行为（定时维护、钩子、她自己主动记下的东西）不是"某个普通用户"
#   写的 —— 优先级高于任何群与个人，但低于主人。
# 值长度上限：value 的最大字符数；超了直接拒绝（六库不是大文本仓库）。
# 时间格式：回执与列表里的时间格式。
