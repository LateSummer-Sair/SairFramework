# 修正记录（工具 `correct`；`note` 库是 C 类资源，写/改/删靠技能自己的归属硬判）

把"AI 被纠正"这件事沉淀成可复用的教训：**原话 → 纠正后 → 原因**。
落在基板六库的 **`note` 库**（`id/ts/title/content/tags/source/extra`），只调 `h.store()`，不自己写 SQL。

## 两个 op

### `add` —— 记一条纠正
| 参数 | 说明 |
|---|---|
| `original` | 必填。AI 原来那句（说错的） |
| `corrected` | 必填。正确的说法 |
| `reason` | 可选。为什么要改 |
| `title` | 可选。默认取「纠正后」前 N 字（N = prompt.md 的「标题字数」） |
| `tags` | 可选。额外标签；纠错标签（`prompt.md` 的「纠错标签」，当前值 `纠错`）总是会被加上；`prompt.md` 读不到时 Java 退回 ASCII 兜底 `correction` |

- **先查重**：同一作用域内，「原话」或「纠正后」归一化后相等，**或短的一边 ≥「查重最短长度」且被长的一边包含**
  → 都算同一条，命中已有行只把 `extra.hits` 加一，不重复堆；
  原来没写原因而这次写了，就把原因补进去（正文一并刷新）。
- 行内容：
  - `source` = `修正记录`
  - `tags` = 纠错标签 + 调用方标签
  - `extra` = `{"original":…,"corrected":…,"reason":…,"hits":n,"by":QQ,"by_name":名字}`
  - `content` 按 `prompt.md` 的 `## 内容模板` 渲染（模板改了，之后记的条目就跟着变）
  - `ts` 由基板自动填

### `list` —— 查记录
- 不给 `query`：`store.list("note",{source:修正记录}, limit, "ts DESC")`；
- 给 `query`：走六库 `search`（FTS5 → LIKE 回退），**先在库侧多取、再在 Java 侧按 `source` 过滤**（`Store.search` 没有 filter 参数）。

## 权限与归属
- `note` 是 **C 类资源**（按类默认分配：C 类对非主人只有 `R`，`RWX` 只有 `SYSTEM` 有）—— **非主人写一律被位拦下**；`note` 又是共享知识库、行里没有归属列，
  所以归属硬判仍然存在、仍是隔离的主要手段：**非主人（`ALLUSER`）写/改/删一律拒**（`CorrectSkill.noteWriteGuard`），**读口仍开放**；
  主人（`MASTER`）与她自己的自主行为（`SYSTEM`）照常。
- 要放开只有主人写**例外条目**那一个入口（数据根 `perms.json`，或她用 `perm` 工具的授权 op）。
- 拒绝文案统一带 `[权限阻断]` 标识（**值同** `Acl.DENY_PREFIX`），技能不自己编。

## 配置与文案
全部在 `prompt.md`：`## 配置`（纠错标签 / 列表条数 / 标题字数 / 查重最短长度 / 时间格式）、
`## 内容模板`（条目正文逐行模板）、`## 文案`（每一句面向模型/用户的话）。改完即生效，不用重启。

## 用法建议
- 只在"用户明确纠正"时记；用户随口说的猜测不用记。
- 原话尽量**照抄**，别改写成 AI 自己的总结 —— 以后要拿它比对同类错误。
- 同一个纠正反复出现时不要重复 add，让 `hits` 自然累加，它能说明这条错得多频繁。
