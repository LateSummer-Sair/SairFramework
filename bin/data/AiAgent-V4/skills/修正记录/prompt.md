# 修正记录 · 配置与文案
# 本文件是「修正记录」唯一的配置源：标签、阈值、正文模板、面向模型/用户的文案全在这里。
# 保存即生效（技能每次调用都重读本文件，不需要重启、不需要重载技能）；Java 只留**读不到配置时的兜底值/兜底文案**，
# 阈值与口径一律以本文件为准（读不到本文件时才落回 Java 里那份兜底，如 纠错标签 → ASCII 兜底 correction）。
# 格式：`键: 值` 一行一条；`#` 开头的行是注释；行内第一个冒号（或全角冒号）是分隔符，值里可以再带冒号。
# 只读 `## 配置` / `## 内容模板` / `## 文案` 三个分节；分节外的内容随便写，不会被解析。

## 配置
纠错标签: 纠错
列表条数: 10
标题字数: 24
查重最短长度: 6
查重取样条数: 200
时间格式: yyyy-MM-dd HH:mm

## 内容模板
# 条目正文逐行模板：占位符 {original} {corrected} {reason_line} {caller} {time}。
# 渲染后为空的行会被丢掉 —— 所以「没写原因」时 {reason_line} 那一行自然消失。
原话：{original}
纠正：{corrected}
{reason_line}记录人：{caller}　{time}

## 文案
# 这些是技能面向用户/模型说出来的话；占位符由 Java 替换。某一行删掉时，技能只回结构性结果（不会崩）。
文案-已记录: 已记下 #{id}：{title}
文案-重复: 这条纠正已经记过了（#{id}），只把命中次数加到 {hits}。
文案-写入失败: 写不进 note 库（六库写入失败），这条纠正没落下。
文案-条目头: 纠错记录最近 {n} 条：
文案-条目头查: 纠错记录里匹配「{query}」的 {n} 条：
文案-条目行: {i}. #{id} {title}
文案-原话行: 　原话：{original}
文案-纠正行: 　纠正：{corrected}
文案-原因行: 　原因：{reason}
文案-条尾行: 　{time}　标签：{tags}
文案-无条目: 还没有任何纠错记录。
文案-没有匹配: 纠错记录里没有匹配「{query}」的条目。
文案-无库: 拿不到六库接口，技能不可用。
文案-未知op: 不支持的 op：{op}（只支持 add / list）
文案-执行异常: 执行异常：{error}

## 备注（不解析）
# 纠错标签：每条纠错都会带上的标签（note 库 tags 列，逗号分隔）。
# 列表条数：list 不给 limit 时返回几条。
# 标题字数：add 没给 title 时，取「纠正后」正文前多少字当标题。
# 查重最短长度：归一化后短的一边至少有这么多字，才允许用「包含」判定为同一条（防止几个字就误判重复）。
# 查重取样条数：查重时先从 note 库取多少条本技能写的行来比。
# 权限不在这里配：管数据隔离的是技能自己的归属硬判（不是权限位）—— note 是 C 类、共享知识库
#   且行里没有归属列 ⇒ 非主人写/改/删一律拒，读口仍开放（CorrectSkill.noteWriteGuard）。主人与她本人照常。
#   要放开只有主人写例外一个入口：perms.json，或她的 perm 工具授权 op；拒绝文案带 [权限阻断] 标识。
