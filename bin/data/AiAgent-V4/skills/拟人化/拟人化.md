# 拟人化（OutboundStage · order=10）

**这个插件不给模型任何工具**（md 的 front matter 里没有工具声明，只有 `name` 与 `description`）：它不注册工具，
权限账本 `data/perms.json` 里没有它的行。它挂在**出站管线**上，位置是
**分段之后、发送之前**，对**每一条**要发出去的正文做三段清洗 —— 这就是 V3 `postProcessReplyText`
的插件版。工具/扩展点的识别靠**类实现了 ext 接口**（`HumanizeStage implements OutboundStage`），
基板装载时会扫这个插件的每个顶层类并自动注册，不需要在 md 里再声明一遍。

## 挂在哪

| 项 | 值 | 为什么 |
|---|---|---|
| 扩展点 | `sair.v4.ext.OutboundStage` | 改"发出去的东西" |
| `order()` | `10` | 排在 `@提问者`（order=20）之前；同序按插件名，顺序确定 |
| 实现的口 | `transform(Outbound)` | **逐条**看这一条长什么样；`null` = 不改（"没意见"的默认） |
| 不实现的 | `veto` / `extra` / `finish` | 本插件只洗正文：不否决、不追加、不动整批 |

## V3 原样（照抄，见 `notes/feel-plugins.md` 第二节 1）

`QQAgentBridge.postProcessReplyText`（`QQAgentBridge.java:239-247`）：

```java
String t = text.trim();
t = t.replaceAll("(?i)^(作为\\s*AI|作为人工智能|根据我的理解|希望以上信息对你有帮助)[，。:：\\s]*", "");
t = t.replaceAll("(?i)(希望以上信息对你有帮助|如果还有问题可以继续问我|有其他问题随时问我)[。！!\\s]*$", "");
t = t.replaceAll("\\n{3,}", "\n\n").trim();
// 不再硬截断超长回复：分段发送负责完整拆条，确保「有多少输出多少」
```

三条一字不改地落在 `prompt.md` 的 `去头套话正则` / `去尾套话正则` / `最大连续空行: 2`。
**不做**的事（V3 的要点）：不改写语气、不硬截断（180/1000 那条尺子在分段那边，不在本插件）、
不按群/私聊分叉（V3 那个 `group` 参数在函数体里根本没用到）。

## 文案与阈值在哪

全在同目录的 `prompt.md`（`键: 值`，`#` 开头是注释）：`开关`、三条规则（`去头套话正则` /
`去尾套话正则` / `最大连续空行`），另有可选的 `套话正则`（可多行，一行一条，**额外**的全文替换，默认没有）。
Java 里只留"文件读不到时的兜底默认值"，兜底值与 `prompt.md` 的出厂值逐字相同。
读法是**惰性缓存 + 按 mtime 失效**：每条消息不读盘，改完保存下一条生效。

## 护栏

- `m.host()` 可能为 null（探针直接注册的合成 stage 就是 null）→ 用兜底默认值，绝不抛异常；
- 正则被改坏（如少了个括号）→ **这一条规则跳过**，另外两条照常，正文原样发出；
- 洗完之后跟进来时一模一样 → 返回 `null`（"不改"），不制造假改动；
- 洗成空串 → 交给基板按"这一条不发"处理（这是基板口径，本插件不越权 veto）；
- `transform()` 外层还有一层 `catch (Throwable)` → 返回 `null`，一条发送都不会因为它挂掉。

## 验收（对应探针断言）

1. 送一条正文 `作为AI，希望以上信息对你有帮助` → 出站后头尾套话都被剥掉（这条会变空 → 不发）；
2. 送 `你好\n\n\n\n在吗` → 出站后变成 `你好\n\n在吗`（3 个以上连续换行压成 2 个）；
3. 送 `  正常回复  ` → 出站后首尾空白被去掉；送一条本来就干净的正文 → 原样发出（`transform` 返回 null）；
4. 把 `去头套话正则` 改坏（例如 `(?i)^(作为AI`）→ 这一条规则不生效，正文照常发出，不报错。
