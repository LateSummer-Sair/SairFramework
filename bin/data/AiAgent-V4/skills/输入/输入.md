# 输入（工具 `input`）

computer use 的"动手"那一半。实现是 **JDK 自带的 `java.awt.Robot`**，零依赖。

## ⚠️ 这是本基板**最危险**的能力，先读这七条护栏

| # | 护栏 | 落在哪 |
|---|---|---|
| 1 | **只认主人与她本人**：不是 MASTER / SYSTEM 一律拒 | `call` 开头的"主体闸" |
| 2 | **群里的回合一律不接**：`caller.isGroup()` 直接拒 —— 防"群友诱导她操作主人电脑" | 同上 |
| 3 | **总闸**：技能自己的 `prompt.md` 写 `总闸: on` 才动；**读不到文件 = 关**（fail-closed） | `Cfg.load` |
| 4 | **动作级 op**：`input.move/click/type/key/scroll` 各判各的（可以只放开"看图"不放"动手"） | `h.need("input."+op)` |
| 5 | **每分钟预算**（60 次/分钟，可在技能自己的配置文件里改） | `spend()` |
| 6 | **坐标越界一律拒**，**不静默夹到边界**（静默夹取会让她以为点到了） | `inside()` |
| 7 | **每次动作前再查一次总闸与预算**（不是每轮开头查一次） | 循环里逐次 `spend()` |
| 8 | **画面不可用拒**：上次截图是纯色（远程桌面断开 / 锁屏）⇒ 拒，别盲点盲打 | `recheck`/`lastCapture` |
| 9 | **陈旧坐标硬拒**：当前屏幕尺寸 ≠ 上次截图尺寸 ⇒ 拒（远程桌面分辨率会变） | 同上 |
| 10 | **动手后复核**：再抓一张比指纹，画面没变就告诉她「这次可能没生效」 | `recheck()` |

## 黑屏自救（`op=recover`）

**只在这一个条件下用**：`screen` 的 `capture` 回了 `desktop=unavailable`（抓到的是一张纯色空画面）。
画面好好的时候调它，会被拒（"画面是好的，不用进桌面"）。

### 协议（四步，一步都不能跳）

| 步 | 谁做 | 内容 |
|---|---|---|
| 1 | **她** | **自报家门**：如实说「我现在看不见屏幕 —— 抓到的是一张纯色空画面」，不要猜、不要装作能看见 |
| 2 | **她** | 调 `input(op=recover)`（**不带 confirm**）⇒ 技能回一段**风险披露** |
| 3 | **她** | 把那段风险**转述给主人**，并问「要不要我试一次」 |
| 4 | **她** | **只有主人明确回「可以」**，才调 `input(op=recover, confirm="yes")` 真正执行 |

### 技能会告诉主人的风险（原样）

1. 会掐断你当前的远程桌面连接，你需要重新连一次 RDP（会话本身不丢，还登录着）；
2. 物理屏幕会显示那个已登录、未锁定的桌面，现场能看到屏幕内容；
3. 可能失败：控制台被别的用户占用、会话正处在锁屏安全域、或权限不足 —— 失败会如实说，不假装成功；
4. 也可能无效：黑屏原因若不是「会话没被渲染」（比如显示器关了），搬过去也不一定恢复。

### 它到底怎么做的

触发一个**以主人自己为属主、`RunLevel=Highest`** 注册的计划任务（默认名 `AiAgent-RDP-to-Console-Now`，
可在 `prompt.md` 的「进桌面任务:」里改）。任务执行 `tscon <会话> /dest:console`，
把那个**已登录**的会话接到物理控制台 —— **不需要任何密码**。

为什么是这个形状：技能进程没有 `SeTcbPrivilege`、也启动不了 SYSTEM 任务（实测都是拒绝访问），
但**能启动"属主是自己 + Highest"的任务**（实测通过，且实测以 High 完整性运行）—— 这就是那条"不用 UAC 的提权路"。

执行走基板的 `exec` 工具（`h.call`），所以**除本 op 外还要过 `exec.cmd` 那道 ACL**（权限双层）。

### 执行后

技能**重抓一张画面**当唯一判据，事实行回 `screenBefore=unavailable(...) screenAfter=ok|unavailable`：

- `screenAfter=ok` ⇒ 真恢复了，她可以继续；
- `screenAfter=unavailable` ⇒ 搬过去也没恢复（可能不是这个原因），**如实说，别假装**。

## 两条必须让主人知道的副作用

- **她会和你抢鼠标**：这个基板**没有**"主人正在用电脑"的检测。她在动的时候你也在动，结果不可预期。
- **`type` 会改你的剪贴板**：Robot 敲不出中文，所以 `type` 走"写剪贴板 → Ctrl+V"。你原来剪贴板里的东西会被覆盖。

## 它不做什么

- 不做"看屏幕"（那是 `screen` 技能）；不做"判断该点哪"（那是模型自己的活）。
- 不绕过基板权限：`h.need("input.<op>")` 不过就原样回权限阻断原文。

## 循环里怎么用它

它是 computer use 的**第三步**，不是第一步也不是最后一步：

```
screen(capture) ──► screen(see) 看清 ──► input（本技能）──► screen(capture) 复核
```

- **坐标从画面里来**：先 `screen(op=see)` 说清屏幕上有什么，再决定点哪；不要凭空猜坐标。
- **动完就复核**：一次动作之后回去看一眼，确认真的生效了，再决定下一步。
- **连着两次没效果就停**：换个思路，或者如实告诉主人"我点了但没反应"。
