# 表情包（工具 `sticker`，库是六库里的 `sticker` 表，钩子 `on_timer`）

库就是基板六库里的 **`sticker`**（表 `sticker`：`id/ts/file/hash/scene/source/uses/extra`）——
不新建表、不自己写 SQL，一切走 `h.store()`。

## op 表

每个动作在分支开头各判一次自己的 op（技能管控表：**空** = 未授权 = 不可用，**Ban** = 不可用，
`Run` = 可用）；判不过就把基板的拒绝原文原样回给模型。

| op | 干什么 | 关键参数 | 复核 |
|---|---|---|---|
| `sticker.send` | 按语境挑一张发到**当前会话** | `scene`（可省）、`id`/`hash`（指定某张） | 自己的 op（没有归属维度：发给当前会话） |
| `sticker.collect` | 收藏一张（URL / fileid / 本地路径 + 语境） | `file` `scene`（可省，缺省用 `默认语境`） | 自己的 op + 归属硬判（过了 op 也不能改别人收的条目） |
| `sticker.list` | 看库里有什么（可按语境过滤） | `scene` `limit` | 自己的 op |
| `sticker.remark` | 按 `hash`（支持前缀）或 `id` 改语境/备注 | `hash`/`id` + `scene`/`note` | 自己的 op + 归属硬判（`ALLUSER` **拒**；主人与她本人照常） |
| `sticker.clear` | 清空整库 | — | 自己的 op + 归属硬判（`ALLUSER` **拒**；主人与她本人照常） |
| `sticker.cf_list` | 取 **QQ 侧**自定义表情详情 / 列表 | `count`（默认 48） | 自己的 op + 归属硬判（`ALLUSER` **拒**） |
| `sticker.cf_add` | 把库里一张（`id`/`hash`）或一个**本机文件**加进 QQ 自定义表情 | `id`/`hash`/`file`、`desc`、`emoji_id`、`package_id` | 自己的 op + 归属硬判（`ALLUSER` **拒**）+ 幂等两道 |
| `sticker.cf_del` | 从 QQ 自定义表情里删一条 | `id`/`hash` 或 `res_id`/`md5` + **`confirm`** | 自己的 op + 归属硬判（`ALLUSER` **拒**）+ 二次确认 |
| `sticker.cf_desc` | 改一条 QQ 自定义表情的描述 | `desc` +（`emoji_id`/`res_id`/`md5` 或 `id`/`hash`） | 自己的 op + 归属硬判（`ALLUSER` **拒**）+ 内容闸 |

> `on_timer`（TTL 清理与自动收集）是**她自己的维护动作**：钩子入口判一次技能级 op（`sticker`，
> 判定主体是 `SYSTEM` ⇒ 恒放行），照旧写这一句让口径统一。

## QQ 侧自定义表情（`cf_list` / `cf_add` / `cf_del` / `cf_desc`）

**先说清关系：这不是"表情包库"，是 QQ 账号侧的真实资源，两边不并库。**

| | 表情包库（`sticker` 表） | QQ 侧自定义表情 |
|---|---|---|
| 一条的身份 | 我们这边的 `id` + `file` + `hash` | `emoji_id` + `res_id` + `md5`（QQ 侧） |
| 谁改得动 | 本技能（`h.store()`） | 只有 NapCat 4.18.5+ 的四个动作 |
| 落点 | `v4.db` 的 `sticker` 表 + `files/sticker/` | QQ 账号（她的号） |
| 两者之间 | ← **只有一条桥**：`cf_add` 把库里的一行推上去，成功后把 QQ 侧的标识记进**那一行的 `extra.cf`** |  |

⇒ **不改 `sticker` 表结构、不新建表**（改结构 = 迁移 = 不允许）：QQ 侧的记账就放在那一行的
`extra.cf = {emoji_id, res_id, md5, desc, ts}` 里。库里那一行删不删，与 QQ 侧那条在不在，是两件事。

### 权限边界（硬）

四个 `cf_*` 动作**一律只给主人（`MASTER`）与她本人（`SYSTEM`）**，`ALLUSER` 一律拒 ——
**读也一并收紧**（`cf_list` 也拒）：一条表情"在不在 QQ 侧"是账号侧的事实，不是提问者的事实。
两道各判一次（少一道也拒）：

1. 技能分支开头的 `h.need("sticker.cf_<动作>")`（同一份 `perms.jsonc` 里四个 op 各一行 `Ban[ALLUSER]`）；
2. `ownerDeny` 归属硬判（`MASTER` / `SYSTEM` 放行，其余拒）。

删类动作另有**二次确认**：`confirm` 必须是 `true` / `yes` / `确认` 之一，否则回 `cf_need_confirm`
且**一次 NapCat 都不打**。

### 每个动作的口径

- **`cf_list`**：`count`（默认 48，夹到 1..500）⇒ `fetch_custom_face_detail`。回一行事实
  `sticker_cf_list count=… faces=…` + 原始返回（截断）。`faces` 是"响应里第一条数组的长度"，
  拿不到就是 `-1`（**只是可观测的数字，不是判据**）。
- **`cf_add`**：目标 = 库里的 `id`/`hash`（取其 `file`）或直接给的 `file`。
  **必须是本机文件**（`File.isFile()`）：URL / fileid 形态回 `cf_need_local` ——
  NapCat 的 `add_custom_face` 要的是它能读到的本地表情文件，不交一个"也许能懂"的值过去。
  我们自己算好 `md5` / `file_size` / `file_name` 一起传（`emoji_id` 未给传空串、`package_id` 未给传 0，照上游契约）。
  - **幂等①（本地账，永远生效）**：那一行的 `extra.cf.md5` 与本次 md5 相同 ⇒ `sticker_cf_exists`，
    **一次 NapCat 都不打**。
  - **幂等②（远端账，尽力而为）**：`自定义表情查重: on`（默认）时先问一次清单，命中同一个 md5 ⇒
    `sticker_cf_exists_remote`。拿不到清单 / 解析不了 ⇒ **跳过这一判**（只可能"多问一次"，
    不可能"因此拒加"）。
  - 可选 `desc`：添加动作本身不吃描述；拿到 `emoji_id` + `res_id` 就顺手 `set_custom_face_desc` 一次，
    回执行里写 `desc=set` / `desc=fail(…)`；拿不到标识就写 `desc=pending`（改用 `cf_desc`）。
- **`cf_del`**：只认 `res_id` 与 `md5`（上游 `delete_custom_face` 的字段就是
  `res_id` / `id` / `ids` / `md5`，**没有 `emoji_id`**）。库里那一行没记过 `extra.cf` ⇒
  `cf_not_linked`（**不拿 md5 猜一个值去删**）；两个都没有 ⇒ `cf_missing_target`。
  删成功后只把那一行的 `extra.cf` 摘掉，**本地那一行与盘上的图都留着**。
- **`cf_desc`**：`emoji_id` + `res_id` + `md5` 三个上游必填项缺一不可（从 `extra.cf` 补齐，补不齐 ⇒
  `cf_missing_target`）。`desc` 非空且 ≤ 200 字（超了 ⇒ `cf_desc_too_long`）。

### 描述文本要过内容闸（两层，判据同源）

1. **技能本地先判**（`StickerSkill.cfDescBlock`，与出站那一层**同一套判据**，不写第二套）：
   标记族（`MoodMarks.strip`）→ 内部事实行（`InternalFacts.fact`）→ 红线（`Redline.veto` /
   `Redline.replace`，**可替换类目在这里也拦下**——描述是要写进 QQ 侧的一句话，写一个被换过词的
   残句不如让主人重说一遍）；判据抛异常 ⇒ `judge_error`（**fail-closed**）。
   命中 ⇒ `cf_desc_blocked reason=…`，**一次 NapCat 都不打**。
2. **出站那一层照旧**：`desc` 经 `Api.call` 的参数遍历，还过自我记账头 / SILENT / 标记族 / 事实行 /
   红线那几道闸（`Api.contentFactAny`）—— 所以**技能这一层只可能更严，不可能更松**，
   两层都不绕。

### 出站纪律：没有一条绕过既有的闸

四个动作都走 `h.napcat()`（`Boot` 那份**带 Guard** 的 `Api`），所以：

- `napcat.<动作名>` 的 ACL 与罢工闸照判（`MASTER` 免 ACL，罢工照判；`send_*` 那一族豁免与本技能无关）；
- 本地文件参数（`file`）会被基板改写层按 `Api.rewrite` 处理（`FILE_KEYS` 覆盖**任何动作**的
  `file`）：**中转在跑 ⇒ 换成外链 URL；没跑 ⇒ 原样透传并告警**；
- 所有字符串叶子过内容闸与自我记账头闸。

> **如实交底（只有真机能证）**：`add_custom_face` 的上游契约写的是"**本地表情文件路径**"，
> 而基板的改写层在中转就绪时会把 `file` 换成 `http://…/…` 的外链 URL。
> **NapCat 是否接受 URL 形态的 `file`，离线无法证**（见 `REPORT.md` §6）。同机部署
> （中转没跑，或 `NapCat` 与本机同机）时交出去的就是裸本机路径。

### 失败一律是结构化错误（不抛异常穿透）

每个 `cf_*` 分支的失败都回**结构化令牌**（`msg()` 的兜底串；`prompt.md` 的中文文案里
也逐字嵌着同一个码）。码表：

| 码 | 什么时候 |
|---|---|
| `cf_missing_target` | 没给 `id`/`hash`/`file`（add），或没给 `res_id`/`md5`（del）、`emoji_id`+`res_id`+`md5`（desc） |
| `cf_need_local` | `cf_add` 的目标不是本机文件（URL / fileid / 文件不在盘上） |
| `cf_need_confirm` | `cf_del` 没带 `confirm` 真值 |
| `cf_not_linked` | 指定了库里的行，但那一行没有 `extra.cf`（不知道它在 QQ 侧的标识） |
| `cf_missing_desc` / `cf_desc_too_long` | `cf_desc` 没给描述 / 描述超 200 字 |
| `cf_desc_blocked` | 描述没过内容闸（`reason=mood_mark` / `internal_fact` / `redline:<类目>` / `redline_replaceable` / `judge_error`） |
| `sticker_cf_exists` / `sticker_cf_exists_remote` | 幂等命中（本地账 / 远端账） |
| `sticker_cf_*_fail` | NapCat 回了失败（`action=… error=…`，用的是基板 `Api.error` 的原文） |

成功一律回一行**可观测事实**：`sticker_cf_list …` / `sticker_cf_added …` /
`sticker_cf_deleted …` / `sticker_cf_desc_set …`，同一行同时写进 `h.out()`（日志）与回执。

## 挑图口径（`send`）

1. 给了 `id` 或 `hash` → 就用那一张；
2. 给了 `scene` → 先精确匹配 `scene` 列（命中多张时同一套挑选口径）；
3. 精确没有 → 用基板检索（`scene`/`file`/`source` 的 LIKE）模糊找；
4. 还是没有 → 退化为**最常用**（`uses DESC, ts DESC`），`挑选方式: 随机` 时在候选池里随机一张；
5. `scene`/`id`/`hash` 都没给、且 `发图心情匹配: on`（默认）→ 先按**当前心情与现状**匹配索引内容
   （见文末「发图」一节），匹配不到则**随机**；
6. 库里一张可用的都没有 → 明说"库是空的"，让模型先 `collect`。

发出成功才 `uses + 1`（失败不加），所以统计是"真的用出去过几次"。
本地文件被磁盘账清掉时，自动**回退 `extra.url`**（与「随机表情包」的三层取图口径一致）。

## `on_timer`：TTL 清理

每个 tick 都进来，但绝大多数 tick 什么都不做：

1. 读 `prompt.md` 的 `## 配置`；`启用清理` 不是 on 就直接返回；
2. **节流**：闸门是 kv `sticker:cleanup:last`（上次真正跑清理的毫秒时间戳），
   间隔不到 `清理间隔小时` 就返回 —— 不会每个 tick 都扫库；
3. 过一遍技能级 op `h.need("sticker")`（钩子判定主体是 `SYSTEM` = 她自己的维护动作，恒放行；
   判不过就**不删**且留一行日志）；
4. 先落闸门时间戳，再动手（异常也不会变成每 tick 重扫）；
5. **超龄**：`ts` 早于 `now - 保持天数`（默认 15 天）的**可**删 —— 但先数一遍全库"可用"数，
   删到"可用数 = `最低保有量`（默认 15 张）"就停；不足就一张都不删（保住最老的）；
6. **超上限**：总数超过 `最多张数` 时，按 **`ts ASC`（最旧的先走，纯滚动）** 删到刚好不超过；
7. 状态写 kv `sticker:cleanup:status`（JSON：`{ts,aged,over,count,keep_days,max,min_keep,usable}`），日志走 `h.out()`。

> 同一个 tick 里，**自动收集的批量段先跑**（见下一节），再跑这里的 TTL。

## 自动收集（单段：只由 `on_timer` 消费候选行）

**群与私聊里的图**都**不会**自己进库：`collect` 仍然只能由模型在对话里调。自动化这条线**只有一段** ——
**入站那一侧不归本技能**（甲方 2026-09-17 急令原话："表情包收集是跟着看图手走的，是在看图时的一个顺带，
而不是主动自动去监听每一个消息"）⇒ 本技能**不再挂 `on_message`**、**不再对任何入站消息做判断**。
候选由**看图手 `辅助识图`** 在看图时顺手写下（跨技能接口键），本技能只在 `on_timer` 里消费它：

```
   辅助识图（看图手 = 入站那一侧的责任方）              表情包（本技能，消费侧）
   看图时写一行候选 ──► kv sticker:cand/<md5> ──► on_timer 逐条：读到即删键 → 判定 → 查 hash →
                        （md5 = Fs.md5(Utf8(url 非空 ? url : file))）  下载 → 复核 → 写索引 → 入库 → 磁盘账
```

`收集开关` / `收集范围` / `收集私聊` 三个键**保留在下面的 `prompt.md` 里照旧可读、状态 kv 照旧写**
（便于回头看"当时配的是什么"），但**不再决定收不收**：入站判断整条归**生产者**（看图手 `辅助识图`）。

### 她自己的图永不入库（技能侧三道防线）

| # | 判据 | 落在哪 |
|---|---|---|
| ① | 事件是 `message_sent`（`Ev.isMessageSent()`，= 她自己发出去的消息） | **生产者**（`辅助识图` 的看图手）在写候选行**之前**判（它才看得见入站事件） |
| ② | 事件里带"这是她自己"的标记：`extra.self=true` / `extra._self=true` / `_self=true`（也认通知钩子挂在 `payload._record` 上的整行） | **消费侧仍在**：`StickerCollect.consumeCandidates` 每一行候选都调它，命中就跳过 + 删键 + 一行日志 |
| ③ | 结构性：`user_id == self_id`（发送者就是本机账号） | **生产者**同①在写候选行之前判 |

三条都在**任何 kv / 文件写入之前**：⇒ **候选行一行都不写、`sticker:collect:seen:*` 前缀键一个都不写、
`sticker` 表零新增**。①③ 这两条**不依赖本技能**：基板 `QqGateway.onEvent` 在入队之前就丢了 `message_sent`
（`src\sair\v4\QqGateway.java:163-170`），生产者自己再挡一次 —— 上游改口径不该变成"她的图进库"。

- **入站那一侧（原来的"第一段 `on_message`"，已按甲方令停用）**：零成本的三道闸 ——
  `sub_type ∈ {1,2,3,4,7}`（表情/热图/斗图/智图/贴图，照 V3 `isStickerImage` 的口径）、
  `file_size ≤ 最大体积MB`（体积闸在下载**之前**）、
  L1 已见闸（kv `sticker:collect:seen:<srcMd5>`，同一 URL 转发刷屏连候选都不进），
  以及"她自己的图永不入库"的①③ —— **现在都由生产者 `辅助识图` 在看图时做完**，做完才写候选行。
  本技能里那份 `capture` 只剩一个恒 `return`（签名留着，免得别处引用编译不过），
  **不读事件、不写 kv、不写任何队列文件**；`StickerSkill.on()` 里那条 `on_message` 分支已整条删除。
- **本技能这一段（唯一的 `on_timer`）**：读候选行（kv `sticker:cand/<md5>`，**读到即无条件删键**）
  → 丢掉超 **24 小时**的（`CAND_TTL_MS`；候选行里那份下载 URL 带 NapCat `rkey=` 签名会过期，硬撑没意义）
  → 只处理最多 `每轮上限` 条 → 逐条下载（基板 `kit\Http.download`，过 SSRF 闸门、失败不留半截文件）
  → 复核体积与**魔数** → **L3 内容去重（按内容 MD5 查 `sticker.hash` 现成索引）**
  → 判定（`safe` + `一张` + `文字 < 15`，判定随候选行给入 ⇒ **消费侧零视觉调用**）→ 写索引内容 → 入库；
- **落盘位置** `<dataDir>/files/sticker/`（**新目录**，与 V3 遗留的 `files/stickers/` 分开、不碰存量），
  文件名 = **内容 MD5 前 16 位** + 后缀（后缀取自魔数，兜底 URL 扩展名）；
  同一张图换 URL / 换群 / **换会话（群 ⇄ 私聊）** / 换发送人 ⇒ **只留一行**，命中时只补 `extra`
  （且**不再重复花钱审查**）；
  下载件先落在 `dl-<src16>.part`，**体积/魔数/内容哈希/审查全过了才改名成正式名**
  ⇒ 被拒的图在盘上不留孤儿；
- **`extra.url` 存原始链接**：它是本地件被磁盘账清掉后唯一的退路（`send` 会本地优先、本地没了回退 URL），
  而且重复来源**只补不覆盖**（保留首个 URL：后来的链接可能已经过期）；
- **`scene` 从哪来**：视觉描述（最可检索）→ 否则用该消息的上下文截断 → 再否则用 `默认语境`；
  **三者都空就不收**（`scene` 是检索面，空 `scene` 的图永远挑不出来，这条会写日志，不静默）。
  所以想让"只有图、没有文字、又没描述"的表情也收进来，把 `默认语境` 填上一行即可；
- **`source` = `auto:sticker-collect`**（手工收的是 `skill:sticker`）⇒ 不加列也能分账：
  `store.list("sticker", {source:"auto:sticker-collect"})`；
- **自动收的图 `uses` 从 0 起** ⇒ 不会一上线就淹没手工精选的那批；
- **状态在 kv `sticker:collect:status`**（JSON：`{ts,scope,collect_private,private_note,review,queue_in,queue_left,expired,trimmed,added,
  dup,failed,oversize,not_image,no_scene,rejected,review_off,disk_bytes,disk_cap,disk_freed,last}`）
  ——灰度期看它一眼就知道收得怎么样（`scope` 是群那一档、`collect_private`+`private_note` 是私聊那一档）。

### 入库硬闸门：视觉审查（默认 on，唯一花钱的一步）

甲方的规则逐条落在 `StickerCollect.applyVerdict`：

| 判定 | 收 / 不收 | 原因码 |
|---|---|---|
| 有且**仅有一张脸** + 文字 **< 15 字** + 安全正常 | **收** | — |
| 纯文字图（没有脸、只有字） | 不收 | `text_only` |
| 图中文字 ≥ 15 字 | 不收 | `text_too_long(n)` |
| 超过一张脸 | 不收 | `multi_face` |
| 没有脸 / 判不出 | 不收 | `no_face` |
| 违规（软色情 / Cos 图 / 政治敏感 / 色情 / 黄赌毒 / 暴力血腥 / 游戏截图） | 不收 | `unsafe(词)` |
| 判定词不认 / 没有安全判定那一行 | 不收（保守） | `unsafe_unknown` |
| `ai()` 打不通 / 返回不可解析 | **不收也不崩**，日志点名 | `review_unavailable` |
| `ai()` 抛异常 | **不收也不崩**（异常绝不等于"合格"），日志点名 | `review_error` |
| 图大到送不进视觉（>3MB） | 不收（照 V3 的 3MB 口径） | `vision_oversize` |

- **一次调用拿五项**（表情数量 / 图中文字 / 内容描述 / 标签 / 安全判定），照 V3 的经验 P9
  （一张图只调一次模型，别为同一张图调多次）；
- 结果按**内容 MD5** 缓存进 kv `sticker:collect:vision:<contentMd5>`（同图只花一次钱）；
- **索引内容必须落库**（甲方："每张图是都有索引内容的"）：判定结果写进
  `extra.index = {faces,text_len,is_sticker,safe,desc,tags,verdict}`，**不许加列**；
  **没有索引内容的行不许入库** —— 这在结构上成立：插入只发生在审查通过之后。
  所以把 `收集审查` 关掉 = 自动收集不入库（手工 `collect` 不受影响），这是刻意的。

### 淘汰与保有量（甲方：15 天超时 + 可用不得少于 15 张 + 60 张上限纯滚动）

| 账 | 配置键 | 出厂默认 | 口径 |
|---|---|---|---|
| 年龄账 | `保持天数` | **15** | 超龄的可淘汰，**但删到"可用数 = 最低保有量"就停**（不足就一张都不删，保住最老的） |
| **保有量** | `最低保有量` | **15** | 年龄账的底；"可用"= `send()` 真能挑出去的那一行（见 `prompt.md` 说明） |
| **池子上限** | `最多张数` | **60**（甲方 2026-09-16 拍板） | **行数账**：总数超过它就按 **`ts ASC`（最旧的先走）** 删到刚好不超过。**这是"库里能存多少"的硬上限**，不受保有量约束（60 > 15，两者不冲突）。`uses` **不参与淘汰顺序**（只影响"发图选中谁"） |
| 磁盘账 | `磁盘上限MB` | 256 | 超了就删**文件**（行保留）：孤儿 → 对应行 `ts ASC`（同口径）→ 文件时间兜底 ⇒ **永不超上限**。60 张 × 平均 512KB ≈ 30MB，远在帽下 |
| 队列账 | `队列上限` | 500 | 超了丢最旧 |
| 每轮账 | `每轮上限` | 5 | 单次 tick 最多处理几条 |

**三条硬规则同时成立时的优先级（同一个 tick 内的执行顺序）**：

1. **收集段**（`on_timer` 的 sweep）：下载 → 审查 → 入库；段末跑**磁盘账**（只在磁盘真的超 `磁盘上限MB` 时才动，行保留）；
2. **年龄账**：`ts` 超 `保持天数` 的可淘汰，但**本轮最多删「全库可用数 − 最低保有量」张**（不足就一张都不删）；
3. **行数账**：总数超 `最多张数`（60）时按 **`ts ASC`** 删到刚好不超过 —— 不受保底约束，因为 60 > 15 恒成立。

构造性口径（都可断言）：
① **20 张可用 + 5 张超龄 ⇒ 删到剩 15 张就停**（年龄账的底）；
② **池子行数在任何一次 tick 结束时 ≤ 60**：塞 80 张候选、跑一轮 ⇒ **正好 60 张，且留下的是 `ts` 最大的那 60 张（最近收进来的那批）**；
③ **收新图时也 ≤ 60，而且新图留得住**（同一个 tick 内先收集、后裁剪；纯滚动下被裁的是**最旧**的那张）。

> **容量后果（写清楚，不许含糊）**：实测入站约 1,051 张/天、过完便宜闸门约 585 张/天。
> 在"过审通过率未知"的前提下，**60 张的池子在 585 张/天的候选里会被持续滚动替换**
> （全过审的极端假设下约 **2.5 小时**滚一遍）。
> ⇒ 甲方选了"**纯滚动（最旧先走）**"之后：**池子 = 最近被收进来的 60 张**，
> 不再冻结在"被用过的那批"上；`uses` 只决定**发图选中谁**（以及"最常用"那条兜底挑选）。
> `保持天数: 15` 仍然是**年龄上限**（老图可淘汰），**不等于"一张图能存 15 天"**。


### 发图：按心情匹配索引内容，匹配不到则随机

`send` 没给 `scene`（也没给 `id`/`hash`）时，先按**当前心情与现状**去匹配索引内容：

1. 精确匹配 `scene` → 2. 基板检索（`scene`/`file`/`source` 的 LIKE）→ 3. 匹配 `extra` 片段
（索引内容里的标签）→ 4. 都没有 ⇒ **随机一张**（照 V3 的发图机制：本地优先 → 回退 `extra.url`）。

情绪事实的来源是**唯一能被读到的那一面**：`情绪` 技能写的 `emotion` 表
（`scope`/`scope_id` 定位到"这个人在这个场合"那一行），取词顺序 = `last_emotion`（对方此刻的情绪标签）
→ 由 `angry`/`sad`/`affinity` 派生的粗档心情词（生气/难过/亲近）→ `romance` 的关系词（亲密）。
**拿不到时**（情绪技能没跑、表里没这一行、控制台会话）⇒ 直接走随机，并记一行 `h.out()` 日志点名降级原因。
匹配全是**字面匹配**（不做模型判断，与 `send` 的一贯口径一致；要判断就由模型先决定 `scene` 再调）。
`发图心情匹配: off` 就回到今天的老口径（最常用 / `挑选方式: 随机`）—— 一行配置，不改代码。

### 本机图外发：绝不把盘符路径交给 NapCat（`本机图外发: 中转`，默认）

**问题**：自动收的图 `file` 是本机绝对路径（`C:\…\files\sticker\<内容MD5>.jpg`），而 **NapCat 常常在另一台机器上**
（线上实测它在 `192.168.1.197`）—— 盘符路径它读不到。

**基板本来就有转换口**（技能**没有**绕过它，只是"交什么值"由技能决定）：

| 环节 | `file:line` | 行为 |
|---|---|---|
| 技能交值 | `StickerSkill.send` → `h.napcat().sendGroupImage(to, file)` | `Api.sendGroupImage`（`src\sair\v4\qq\Api.java:529`）→ `call(...)` |
| 基板改写 | `Api.call` → `rewrite`（`Api.java:372`）→ `rewriteMessage`（`:394`）→ **`rewriteLocalFile`（`:505-524`）** | **中转在跑** ⇒ `Relay.urlFor(path)` 换成 `http://<relayPublicHost>:<port>/<token>/<绝对路径>`；**中转没跑** ⇒ **只记一行告警、原样透传**（那时交给 NapCat 的就是裸 `C:\…`） |
| 中转本体 | `Relay.running()` / `urlFor` / `mediaParam`（`src\sair\v4\qq\Relay.java:254 / 308 / 333`）；`Api.relay()`（`Api.java:122`，**公开**） | 技能可以问一句"现在能不能转" |

**技能的规则**（`本机图外发`，默认 `中转`）：

1. `file` 是**本地路径**（盘符 / `file:` / 绝对路径）且**中转就绪** ⇒ 交本地件（基板会转成外链 URL）—— **本地优先成立**；
2. 本地路径但**中转没就绪** ⇒ **改用 `extra.url`**（原始链接，NapCat 自己能取）；
3. 连 `extra.url` 都没有 ⇒ **跳过不发**，回 `prompt.md` 的「本机图发不出去」文案（带可执行的下一步：开中转，或改 `本机图外发: 本机路径`）；
4. `file` 不是本地件（URL / fileid）⇒ 原样交给基板（`extra.url` 那条回退照旧只管"本地件不在了"）。

⇒ **默认口径下，发给 NapCat 的值里绝不会出现 `C:\…` 这种盘符路径。**
`本机图外发: 本机路径` 是**显式**保留的老口径（只适合同机部署）：写了它才会直接交本地路径。
中转停掉时同一行会自动走回退（探针 §27 两条路都钉住了）。


## 边界与取舍

- **不算"语境"的语义**：匹配就是字面匹配 + 基板 LIKE，不做模型判断（要判断就由模型先决定 scene 再调）；
- **图片本体**：**手工 `collect` 不搬运** —— `file` 原样存（链接就是链接，fileid 就是 fileid）；
  **自动收集会搬运**（`on_timer` 把图下到 `files/sticker/`，`file` 存本地路径、`extra.url` 存原链）——
  因为腾讯图 URL 带 `rkey=` 签名**会过期**（实测过 `HTTP 400 … download url has expired`），
  只存链接的库迟早会空。两边的去重口径都是 `hash`：
  手工 `collect` 是"本地文件取 `Fs.md5(文件)`，否则取 `Fs.md5(字符串)`"（不变）；
  自动收集一律以**下载后的内容 MD5** 为 `hash`（同一张图换 URL 只留一行）；
- **归属靠技能自己硬判**（与 op 判定是两件事：op 回答"这个动作给不给他用"，归属回答"这会动到谁的数据"）：`collect` 的 op 可以由主人放行给任何人（收表情是正常用法），
  只有"改**别人收的**条目"那一支才拒（按行里的 `extra.added_by` 判归属）；`remark` / `clear` 对 `ALLUSER` 一律拒，
  主人与她本人（`SYSTEM`）照常。
  拒绝文案带 `[权限阻断]` 标识（**值同** `Acl.DENY_PREFIX`）—— 技能自己硬判的那句以它开头，基板 `h.need` 的原文也是同一前缀。
  工具可见性按同一张表筛（工具级 op `sticker` 或其任一动作级 op 放行 ⇒ 模型才看得见它），
  能不能答应对方看事实块 `caller.ops`（这个身份能用的技能 / 动作清单；`"ALL"` = 全权、`[]` = 一个都没有）；
- **删掉即消失**：技能目录整体删掉，`sticker` 工具、TTL 清理与自动收集一起没了；
  已经收的图还留在库里，自动收集落盘的图也还留在 `files/sticker/`（**删技能不会删盘上的图**；
  要"删目录即消失"就自己把那个目录一起删掉 —— 盘上那份与库里的 `file` 是一一对应的）；
- **本地文件交给 NapCat 的路径写法**（批 16 / 2026-09-27 改正：本句原写"只传绝对路径"，批 15 起
  `send` 的 `file`/`fileto`/`record` 都**认数据根相对路径**，那句已经不准了）：技能交给平台的是
  **能定位到文件的那串路径** —— 相对路径（如 `files/x.txt`）由 `send` 那条线按数据根解析成绝对路径，
  绝对路径与 `http(s)://` / `base64://` / `file:` 原样透传；**跨机时由基板 `Api.call` 统一改写成
  "文件外链中转"的 URL**（没开中转则退回本机 `file:///`）。技能不要自己拼 URL、不要自己起服务、
  不要把大文件塞 base64，详见 `docs/skills.md` §4.1。
