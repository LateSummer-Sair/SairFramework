# 群印象 · 文案与阈值
# 本文件是本插件唯一的配置源：开关、节流、蒸馏阈值、词表、以及注入出去的每一句话全在这里。
# 格式：`键: 值` 一行一条；`#` 开头的行是注释（`## 配置` 这种分节标题也是注释）；
#       行内第一个冒号（半角 `:` 或全角 `：`）是分隔符，值里可以再带冒号（后面的冒号都算值）。
# 读法：惰性缓存 + 按文件 mtime 失效 —— 每轮不读盘，改完保存下一轮生效，不需要重启。
# Java 里只留「文件读不到 / host() 为 null 时的兜底默认值」：**数值**兜底与下面各行一一对应；
#   但「话题词表」与三条「氛围-*」文案的兜底与出厂值**不同**（文件读不到时话题只剩 2-gram）——要改文案请改本文件。
#
# ⚠ 这一段是**易变段**（stable()=false）：它随群里的消息累积而变，所以不放进稳定前缀
#   （放进去会让模型服务的前缀缓存每轮失效）。段位口径见 ContextProvider 的类注释。
#
# 数字出处（V3 原样，见 notes/feel-plugins.md 第一/二/四节）：
#   友好度区间 -100~100、「氛围差」门槛 -30、活跃度分档 5000/500/50 → 极高/高/中/低，
#   全部照抄 sair.aiagent.model.GroupImpression；节流两道闸门照抄
#   EmotionStateManager.noteUnfriendlyGroup（每群 10 分钟最多联动一次 + 单次幅度封顶）。

## 备注（不解析，只给人看）
# 启用：不为 true 就整个技能不动作（钩子直接 return，这一段也不出现）。
# 预算：这一段的字符上限，也是 maxChars() 的返回值（默认 500）。基板还要再按全局 ctxBudgetChars 截一次。
#   maxChars() 拿不到 Host，所以用的是「上一次读到的预算」；appliesTo 先被基板调到，所以第一轮就是对的。
#
# ── 回写（on_message 累积）：两道闸门，照 V3 的 noteUnfriendlyGroup ──
# 回写节流分钟：同一个群多久最多回写一次库（默认 10，与 V3「每群 10 分钟最多联动一次」同值）。
#   窗口内的每条群消息**只当"这个群刚动了一下"**，一个字节都不写库；0 = 不节流（只建议手工调试时用）。
# 回写最大幅度：一次回写最多把友好度推 ±N（默认 3）。V3 那边是「此来源最多把怒气推到 40」——
#   同一件事：群氛围可以影响它自己的分，但一次推不到极端。
#
# ── 蒸馏（on_timer）：基板唯一 tick，默认 20 秒一次，绝大多数轮什么都不做 ──
# 蒸馏间隔小时：同一个群两次"真正更新印象"之间的最小间隔（默认 6，支持小数，0 = 不节流）。
# 最少消息数：自上次蒸馏以来至少累计这么多条消息才值得更新一次（默认 30）。
#   判据是 activity - distill_msgs（activity = 这个群这辈子累计条数，与 V3 的 messageCount 同口径）。
# 取样条数：一次统计最多看这个群最近多少条群聊（默认 400）——统计是规则/词表**不调模型**，这里只管内存与耗时。
# 每轮群数：一次扫描最多真蒸馏几个群（默认 3，防一个 tick 拖长）。
# 候选群数：一次扫描最多取几行来挑（默认 20，按 last_seen 新的在前）。
# 扫描间隔分钟：tick 很密（默认 20 秒），扫描降到这个量级（默认 10 分钟，0 = 每个 tick 都扫）。
#
# ── 信号怎么算（规则/统计，没有模型）──
# 每人信号上限：同一个成员在窗口里最多计几分（默认 3）——**一个人刷屏不算"很多人"**。
#   成员分 = clamp(该成员正面命中 - 该成员负面命中, ±每人信号上限)；
#   信号分 = 各成员分相加 → 所以"群内多个成员印象变差"才会把群印象压下去（V3 的联动口径）。
# 信号饱和分：信号分到这么多就吃满「最大幅度」（默认 6）。
# 蒸馏最大幅度：一次蒸馏最多把友好度推 ±N（默认 25）。
# 被@负面加权：这条消息 @ 了机器人**且**命中负面词时，该成员**多算 (这个值 − 1) 分**（默认 2 = 多算 1 分，1 = 不加权）；只在该成员本窗口已有负面命中时生效。
#   （只有 on_message 的事件里带 @ 信息；grouplog 里没有，所以这条只对刚到的消息生效。）
# 友好度差门槛：**低于或等于它** = 氛围差（V3 FRIENDLINESS_LOW = -30）→ 多出一行「态度行-差」。
# 友好度好门槛：**高于或等于它**就用「氛围-好」那句（只影响氛围描述，V3 没有正向态度行，这里也不发明）。
# 活跃极高/高/中：活跃度**分档**的门槛，按累计条数（V3 activityLabel：5000 / 500 / 50）。
# 时间格式：{time} 占位符的格式（只在模板里写了 {time} 时才用得上）。
#
# ── 词表（子串命中，大小写不敏感）──
# 负面词 / 正面词：语气信号。注意是**子串**命中："滚"会命中"滚烫"这类词，
#   词表按群的实际情况调；宁可漏也别把中性词放进来（它会一直往下压友好度）。
# 话题词表：话题优先从它里面挑（命中一次按「话题权重」计分）。
# 话题停用词：2-gram 兜底时丢掉的词（语气词、代词、口水词）。
# 话题上限：最多印几个话题词（用「、」连接）。
# 话题权重：话题词表命中一次的计分倍数（默认 2，让它在 2-gram 之上）。
# 话题最少次数：2-gram 兜底要求的最少出现次数（默认 3，压住"只出现一次的偶然词"）。
#
# 占位符（{键} 字面替换；写了不认识的键只会原样留在文本里 —— 有意如此，配置错就让它显形）：
#   行模板 / 行模板-无话题：{group} 群号、{name} 群名（本插件不猜群名，一般空着）、
#     {friendliness} 友好度（-100~100 的整数）、{activity} 活跃度**标签**（活跃-* 那几个词）、
#     {activity_n} 累计条数、{topic} 最近话题（连接好的字符串）、{rounds} 蒸馏轮次、
#     {time} 上次见到消息的时间、{msgs} 上次蒸馏的取样条数、{members} 上次蒸馏的发言人数。
#     话题为空时自动改用「行模板-无话题」（那条模板里别再写 {topic}）。
#   氛围行：{atmosphere} 氛围短句（下面「氛围-差/平/好」渲染出来的整句）、{friendliness}、{activity}、{topic}。
#   氛围-差 / 氛围-平 / 氛围-好（按友好度三选一）：{friendliness}、{msgs} 取样条数、
#     {participants} 发言人（去重）、{negative} 负面命中数、{positive} 正面命中数、{topic}。
#   标题：留空 = 不打这一行（默认 `## 群印象`）。
#
# ── 数据从哪来（只有只读两条）──
# ① grouplog（基板写的群聊历史，本插件**绝不写**）：条数用 count、窗口内容用 list（只取样「取样条数」条）；
# ② on_message 的事件（只在内存里用）：判群号/发言人、判有没有被 @、判"这个群刚动了一下"。
# 写库只有一处：自己的 group_impression（每群一行），并且只在「回写节流分钟」到点时写一次。
