# @提问者（OutboundStage · order=20 + on_message 记账 + onTurnStart 钉住触发）

**这个插件不给模型任何工具**（md 的 front matter 里没有 `tool:`）。它挂在**出站管线**上，在**整批收尾**那一步
决定两件事、并且**只在这一处**决定：

1. **要不要 @ 触发人**（`[CQ:at,qq=<提问者QQ>] `，末尾一个空格）；
2. **要不要引用触发人那条消息**（`[CQ:reply,id=<触发消息的 message_id>] `）。

首条最终形状：`[CQ:at,qq=…] [CQ:reply,id=…] 正文`（**先 @ 再引用**，理由见下）。

## 三个类，三件事（谁决定、谁记账）

| 类 | 身份 | 干什么 |
|---|---|---|
| `AtAskerStage` | `OutboundStage`（order=20，走 `finish`） | **唯一决定者**：读钉住的触发、算重要不重要、算时差、拼前缀。只读不写。 |
| `AtAskerHook` | `Hooked`（md 里 `hooks: on_message`）+ `LifecycleHook`（order=60） | **只记账**：入站时记一条（谁/何时/message_id/@ 没 @ 她/是不是主人）；回合开始时把"这一轮的触发消息"钉住。 |
| `AtAskerCfg` / `AtAskerMemo` | 普通类（不是扩展点） | 配置面（`prompt.md` 键值表，mtime 失效）与状态面（kv 键名、TTL、清理、JSON 编解码）。 |

**为什么必须记账**：出站 stage 里**拿不到入站时刻与触发消息号** —— `Outbound` 的字段只有
`text/session/group/target/caller/echo/index/total/host`，而 `BuildContext.state(...)` 在出站路径上
`turn == null`、恒返回兜底值。所以时差只能在**看得见入站事件的地方**记，再由 stage 读回来算。

**为什么必须钉住**：群是活的 —— A @ 了她之后、她开口之前，群里可能又来了别人的消息。
stage 里"最近一条入站"很可能**不是这一轮的触发消息**（那会算错时差，还会引用错人）。
所以在回合开始那一刻按"本轮输入"把它钉住，stage 读的是钉住的那一条。

| 键（`kv` 表） | 内容 | 生命周期 |
|---|---|---|
| `atasker:in:<群号>` | 本群最近 `保留条数`（默认 5）条入站，JSON 数组 | 每来一条消息追加；超 `记录有效期` 的条目在读出时丢掉 |
| `atasker:t:<群号>` | 本轮钉住的触发（JSON 对象），每群一条 | 每个回合开始时覆盖写；stage 只读它 |
| `atasker:sweep` | 上次清理的时刻 | 只为限频；清理按 `清理间隔秒` 扫 `atasker:` 前缀，删很久没动过的行 |

**不许靠 static**：热重载 = 新类加载器 + 新静态字段，static 里的东西会成孤儿。所以两个面都只写库。
**不自起线程**：一切周期行为要么挂在钩子上，要么按需触发（这里没有周期行为）。

## R1 —— @ 分情况

**要 @（任一成立）**：

1. 触发消息 **@ 了她**（群内点名）—— 来自 `on_message` 记的账；
2. 触发者是**主人** —— 出站 stage 里直接可得（`m.caller().master()`），不依赖记账；
3. 本轮**做了实事** —— ⚠ **拿不到**，见下面「拿不到的判据」；
4. 回复**正文长度 ≥ `重要长度`**（默认 40 字符，不是一句应付）。正文 = **整批**分段（已按基板口径
   `MarkerTags.strip` 去掉控制标记），不是只看第一条。

**不 @**：普通群聊搭话、未点名、非主人、短回复、无工具调用。

### ⚠ 拿不到的判据：「本轮她调用了工具」

这不是"没找对 API"，是**基板口径决定拿不到**：

- 发送类工具（`send/sendimage/sticker`）成功 ⇒ `Turn.spoke()`，而 `Agent.java:183-187` 在
  "本回合已经对外发过"（`spoke()` 或 `sent` 台账里本回合已有发往此会话的记录）时
  **根本不走这条出站管线** ⇒ **stage 能跑起来，就说明本回合没有成功发出过东西**；
- 非发送类工具（查库、上网、记忆维护……）在基板里**不留任何 stage 可读的痕迹**：
  `Turn` 的 state 只有 `media` / `chat_window` / `subagent` 三个键，而出站 stage 连 `Turn` 都拿不到。

**替代判据（本轮采用）**：模型自己在回复里写的控制标记 `<at>`（键 `重要标记`，默认 `at`）。
它在 `MarkerTags` 的白名单里**本来就有**、今天**没有任何消费者**，而且剥除发生在 outbound stage
**之后**（`Sinks.java:168-171`：先 `stage(...)`、再逐条 `MarkerTags.strip`）⇒ 插件读得到、用户看不到，
**零新增语法**，语义正好是"她自己判定这条重要"。

**代价说清**：今天提示词没教她写这个标记 ⇒ 这条判据平时不生效，真正兜底的是第 4 条（长回复）。
要让它生效，需要在人设/工具索引里加一句"重要的回复可以写 `<at/>`"—— 那要动 `data\prompts\**`，本轮没动。

## R2 —— 按时差决定是否引用触发者

`dt = 她发出回复的时刻（出站 stage 执行的那一刻）− 触发消息的入站时刻`（`on_message` 记的真入站毫秒）：

| 时差 | 引用吗 |
|---|---|
| `dt < 3 秒`（`秒回不引用`） | **绝不引用** |
| `3 ≤ dt ≤ 10` | 只有"重要"（**与 R1 同一套判据**）才引用 |
| `dt > 10 秒`（`慢回必引用`） | **必须引用** |

### 为什么先 @ 再引用

首条 = `[CQ:at,qq=…] [CQ:reply,id=…] 正文`，理由两条：

1. **保住既有判据**：`已at前缀` 判的是"首条是否以 `[CQ:at,` 开头"（V3 逐字口径）。引用码若插在最前，
   这条判据立刻失效 —— 模型自己 @ 过就认不出来，会出现两个 at；
2. 两个都是 CQ 码，同一条消息里按段解析，顺序不改变段的类型与内容。

## 降级（拿不到记账时）

| 情况 | @ | 引用 |
|---|---|---|
| 完全没有记录（钩子没跑 / 权限面拒 / 库不可用 / 记录超期） | **保持旧口径：照加** | **不引用** |
| 有记录但 `message_id <= 0` | 照判（能判到的判据照用） | 不引用 |

理由：拿不到记账 = 连"这条是不是点名/主人"都不知道。这时把"该 @ 的仍然 @"改成不 @，
等于用一个**不存在的证据**去取消一个既有行为（记账面出问题 ≠ 这条不重要）。
引用是全新行为、要的是**精确的那一条 message_id 与精确的时差**，猜错就是引用错人
（V3 当年放弃引用回复正是怕这个）⇒ 取不到就**绝不猜**。

## 范围与护栏

- 私聊 / 定时任务落点（`caller()` 为 null）/ 提问者 `qq <= 0` → 返回 `null`（不改）；引用**不**外扩到私聊；
- 首条已经以 `[CQ:at,` 开头（模型自己 @ 了）→ 不重复加 @；**引用照样可以加**；
- 返回的是**新表**（不改基板给进来的那个 List），只动首条那一个元素，其余原样；
- stage 里**只读**状态：一律 `Host.selfDb("kv", …)`（自主入口，判定主体钉死 `SYSTEM`）。
  出站 stage 的判定主体是**当轮调用者**（`ExtRegistry.java:780-793`），普通群友对 C 类库几乎没有位，
  走 `h.needDb` 会被当场拒掉；读不到 = 当作"没有记录"，绝不猜。**stage 不写库、不发消息**；
- `m.host()` 可能为 null（探针直接注册的合成 stage 就是）→ 走上面的降级，绝不抛异常；
- `finish()` 外层还有一层 `catch (Throwable)` → 返回 `null`，一条发送都不会因为它挂掉。

## ⚠ 覆盖缺口（必须知道）

**她若自己调发送类工具（`send` / 表情包 / `napcat` 直发），那条路完全绕过出站管线**
（`SendSkill` → `h.napcat()` → `Api.call`），本插件的 @ 与引用对那条路 **0 覆盖** ——
这不是本插件写得不对，是"出站改写"型插件共同的边界（`Agent.java:183-187`）。
要覆盖它得动基板（给发送动作加"结构段前缀"口），本轮没动，理由与代价写在 `tmp\r12\REPORT.md`。

## 验收（对应探针断言）

`probe\ProbeAtQuote.java`（本插件的新行为，逐条钉住）：

1. R1 四种"要 @"：① 点名 ② 主人 ③ 重要标记 ④ 长度 ≥ 40；
2. R1 三种"不 @"：未点名 + 非主人 + 短 + 无标记（普通群聊搭话）；以及各自的单变量对照；
3. R2 三段时差：`dt=1s` 不引用、`dt=5s` 分"重要/不重要"两例、`dt=30s` 必引用；
   边界：`2999ms` 不引用、`3000ms` 进中间档、`10000ms` 仍中间档、`10001ms` 必引用；
4. 降级：没有记录 → 照加 @ 且不引用；`message_id=0` → 不引用；记录超期 → 同"没有记录"；
5. 拼接顺序：`[CQ:at,qq=…] [CQ:reply,id=…] 正文`（@ 在前）；已有 at 时不重复加 @ 但引用照加；
6. 集成：真 `Skills.dispatch(on_message)` 记账 → 真 `onTurnStart` 钉住 → 真 `runStages`/`QqSink` 出站；
7. 单一产法：`引用开关=false` 只影响引用；`开关=false` 两者都没有。

`probe\ProbeS4`（既有口径不许被破坏）：群聊首条加 at（**记账缺失时**照旧）、已有 at 不加、私聊不加、
`caller==null` 不加、分段两条只加首条。
