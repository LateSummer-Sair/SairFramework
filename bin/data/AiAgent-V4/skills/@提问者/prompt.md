# @提问者 · 文案与阈值
# 本文件是本插件唯一的配置源：@ 的前缀模板、引用的模板、以及 R1/R2 的阈值都在这里。
# 格式：`键: 值` 一行一条；`#` 开头的行是注释（`## 配置` 这种分节标题也是注释）；
#       行内第一个冒号（半角 `:` 或全角 `：`）是分隔符，值里可以再带冒号（CQ 码里就有）。
# 读法：惰性缓存 + 按文件 mtime 失效 —— 每条消息不读盘，改完保存下一条生效，不需要重启。
#       （注意：改本文件**不用** reload；改 .java 或 md 的 front matter 必须 reload。）
# Java 里只留「文件读不到 / m.host() 为 null 时的兜底默认值」：与下面各行的出厂值一一对应 ——
#   唯一的例外是 `首条模板` / `引用模板`：下面那行的值两端会被去掉、留不住尾随空格，
#   插件会自己补上"末尾一个空格"（V3 口径：[CQ:at,qq=…] 后面必须有一个空格）。
# ⚠ 值两端的空格会被去掉，所以模板**不用**（也留不住）写尾随空格。

## 配置（@）
开关: true
首条模板: [CQ:at,qq={qq}]
已at前缀: [CQ:at,

## 配置（R1：重要吗）
# 重要长度：用户可见正文（整批、已剥控制标记）达到这么多**字符**就算"不是一句应付" ⇒ 要 @。
#   计数是 Java String.length()（中文 1 字 = 1，emoji 代理对 = 2）。<=0 = 关掉这条判据。
重要长度: 40
# 重要标记：模型自己在回复里写这个控制标记 = 她自己判定"这条重要"（要 @；3~10 秒档还会因此引用）。
#   标签名要在基板的 MarkerTags 白名单里（at / quote / reply …），且**剥除发生在出站 stage 之后**，
#   所以插件读得到、用户看不到（零新增语法）。逗号分隔可写多个。留空 = 关掉这条判据。
#   ⚠ 今天提示词没教她写这个标记 ⇒ 这条判据平时不生效，兜底靠「重要长度」。
重要标记: at

## 配置（R2：引用触发者）
引用开关: true
# 引用模板：占位符 {id} = 触发消息的 message_id；也可用 {qq} / {group} / {session}。
#   出厂值就是 OneBot 的引用码形状（与 @ 的先后顺序：先 @ 再引用 —— 见插件的类注释）。
引用模板: [CQ:reply,id={id}]
# 秒回门槛：时差 < 这么多**秒** ⇒ 绝不引用（秒回的人不会特意点"回复"）。
秒回不引用: 3
# 慢回门槛：时差 > 这么多**秒** ⇒ 必须引用（隔这么久，对方已经不知道你在回哪句）。
慢回必引用: 10
# 中间档（秒回门槛 ≤ 时差 ≤ 慢回门槛）不在上面两条里：只有"重要"（与 R1 同一套判据）才引用。

## 配置（记账）

记录有效期秒: 600
# 保留条数：每个群在入站环里最多留几条（旧的挤掉）。
保留条数: 5
# 清理间隔：多久（秒）扫一次 `atasker:` 前缀、把很久没动过的行删掉（避免库无限增长）。
清理间隔秒: 3600

## 备注（不解析，只给人看）
# 开关：false = 这一批不加 @、也不引用（等于没装）；两个钩子同时一条账都不记。
# 首条模板：加在首条最前面的字符串。占位符（{键} 字面替换）：
#   {qq}    提问者的 QQ（= 本轮调用者的 QQ）
#   {group} 群号（出站落点，可能为 0）
#   {session} 会话键（group:123 / qq:123 / console）
#   {id}    触发消息的 message_id（拿不到时是空串）
#   出厂值 [CQ:at,qq={qq}] 与 V3 逐字相同（V3 的 QQAgentBridge.buildAtPrefix），尾随空格由插件补。
#   留空 = 不加 @（等于关掉 @ 这一半）。
# 已at前缀：首条以这个字符串开头时**不重复加 @**（V3 是 "[CQ:at,"，见 QQAgentBridge.sendHumanizedReplies）。
#   留空 = 不做这个判断（不建议：模型自己 @ 过就会出现两个 at）。引用不受它影响。
#
# V3 原样行为（QQAgentBridge.buildAtPrefix + sendHumanizedReplies）：
#   1. 只有**群聊**加；私聊不加（本插件在私聊/定时任务落点直接返回 null = 不改，引用也不外扩）；
#   2. askerQQ <= 0 不加 —— 拿不到提问者就不 @，宁可没有也不 @ 错人；
#   3. 前缀 = "[CQ:at,qq=" + askerQQ + "] "，**末尾一个空格**；
#   4. 只加在**首条**最前面；首条已以 "[CQ:at," 开头就不重复加；
#   5. V3 当年明确**放弃**"引用回复"（怕"A 提问却回复到 B"）。本插件按甲方 2026-09-16 的要求
#      把引用加回来了，但**只用"这一轮真正触发的那条消息"的 message_id**（在回合开始那一刻钉住，
#      不是"最近一条入站"），并且只在时差足够大时才引用 —— 就是为了不重犯当年那个错。
#
# 为什么走 finish（整批收尾）而不是 transform（逐条）：
#   "首条"必须是**真正会发出去**的那一条。逐条口看不到后面哪条会被别的 stage 丢掉或洗空
#   （比如「拟人化」把某一条洗成了空），@ 就会挂到一条根本没发的消息上。
#   基板在 extra（追加消息）之后调 finish，所以追加的表情包也算在 parts 里 ——
#   这里取的仍是 parts 里第一个非空白元素，与 V3 的 out.get(0) 同义。
#
# 记账（时差从哪来）：
#   on_message 钩子记"本群最近几条入站"（谁、何时、message_id、@ 没 @ 她、是不是主人）；
#   回合开始（LifecycleHook.onTurnStart）把"这一轮的触发消息"钉住；出站 stage 只读钉住的那条，
#   算 dt = 现在 − 入站时刻。stage 里**拿不到**入站时间（Outbound 没有它），所以必须这么记账。
#   记账缺失（权限面/库不可用/钩子没跑）⇒ @ 保持旧口径（照加）、引用一律不做（绝不猜）。
#   ⚠ 需求里的"本轮她调用了工具"在出站 stage 里**拿不到**（发送类工具一旦成功，基板就不走这条
#   出站管线；非发送类工具在基板里不留 stage 可读的痕迹）⇒ 用「重要标记 + 重要长度」替代判据，
#   细节见 AtAskerStage 的类注释。
