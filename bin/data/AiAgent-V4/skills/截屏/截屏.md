# 截屏（工具 `screen`）

两个 op，各判各的闸：

| op | 干什么 | 权限 op | 副作用 |
|---|---|---|---|
| `capture` | `java.awt.Robot.createScreenCapture` → 存 `<files>/screen/screen-<时间戳>.png` | `screen.capture` | 落一个文件（**不含任何按键/鼠标动作**） |
| `see` | 读图 → base64 → `data:image/...` → `h.ai().vision(Msg.userWithImages(...))` | `screen.see` | 一次模型调用 |

## 纪律

- **只用 JDK 自带的 `java.awt.Robot`**，不引入任何原生载荷或第三方依赖。
- **不返回图片本体**（base64 不进上下文）：`capture` 只回路径 + 尺寸 + 字节数，避免炸上下文。
- **4 MiB 是硬上限**：与基板 `mediaAttachMaxBytes` 出厂值一致；超了自动转 JPEG(q0.7)。
  实测 1440×900 的无损 PNG 只有 824 KB ⇒ 这条通常不触发，是给 4K 屏留的安全路径。
- **`see` 尊重图片能力总闸**：`mediaVision` 为 `no`/`off` 时如实拒绝，不偷偷出图。
- **越界屏幕号退回主屏**，但会如实写在事实行的 `screen=` 里 —— 不静默截别的屏。

## 循环姿势（computer use 的用法）

```
capture ──► see ──► （要不要动手？）──► input ──► capture（复核）──► …
   ▲                                                          │
   └──────────────── 直到达成目标 / 没进展就停 ◄──────────────┘
```

**什么时候停**（三条，任一条命中就停并如实说）：

1. 目标达成（复核的那张图证明做到了）；
2. **连续两张画面没变化** —— 说明操作没生效，再点也是白点；
3. **同一个动作连着两次没效果** —— 换路子或直接告诉主人，别连点。

**别空转**：每一步都要能说清"我在等什么、下一步看什么"；说不清就停。
