# 出站红线（本技能现在只负责那条"上一条被拦"的提示）

## ★★ 2026-09-22「基板提炼批」：判据与词表已经搬进基板 ★★

| 问题 | 事实（搬完之后） |
|---|---|
| 红线的**判据**在哪？ | `src\sair\v4\term\Redline.java`（唯一实现）。本技能的 `.java` 不持有任何词表、不做任何"命中判断"，只调 `Redline.veto(...)` / `Redline.replace(...)`。 |
| 红线的**词表**在哪？ | `data\prompts\redline.md`（唯一来源，**mtime + 字节数热读**：改完保存，下一条消息生效，不用重编译、不用重启）。本目录的 `prompt.md` **不再持有任何词表**。 |

| 那本技能还剩什么？ | 只剩一件**不是门限**的事：被拦时往**本会话** context 槽写一行"上一条被拦"（给她看的礼貌回执），以及出站时把那行清掉。 |

## ★ 本技能的 `开关` 现在只管那条提示

`prompt.md` 里只剩一个键 `开关`：

- `开关: true`（默认）⇒ 被拦时写那条提示（仅当有会话可挂：空会话/控制台落点**不写**，见下面口径 4）；
- `开关: false` ⇒ **只**不写那条提示；**红线本身照旧生效**（判据在基板，不受任何技能开关影响）。

⚠ 搬走之前不是这样：那时候 `开关: false` = 整族红线失效。**口径变了，别按老记忆改。**

## 挂在哪（注册口径，已核过 `ExtRegistry`）

| 问题 | 事实 |
|---|---|
| 类靠什么被登记为出站 stage？ | `sair.v4.hot.Skills#registerExt`：把这个技能编出来的**每个顶层类**（跳过含 `$` 的）`Class.forName` 之后问 `ExtRegistry.isExtClass(k)` —— 它认 `ContextProvider` / **`OutboundStage`** / `TriggerVoter` / `LifecycleHook` 四个接口；认了就 `ext.register(<技能文件夹名>, k.newInstance())`。**md 里不需要声明**。 |
| 顺序怎么定？ | `order()` 小的在前（`ExtRegistry.stages()` 排序后给 `runStages`）。本插件 `order()=80`，情绪 `MoodStage.ORDER=90` ⇒ **红线先跑**。 |
| 每个 stage 拿谁的宿主？ | `runStages` 每条消息对每个 stage 调 `m.host(hostOf(e.owner, …))` —— **owner 是技能文件夹名** ⇒ 我这边拿到的宿主，`skillDir()` 就是 `data\skills\出站红线`。 |
| 与情绪的关系 | **零依赖**：本插件的 `.java` 不 import 情绪的任何类；配置读取器仍各写一份（见 `RedlineCfg` 的注释）。 |

## 文件

| 文件 | 干什么 |
|---|---|
| `RedlineStage.java` | `implements OutboundStage`：`order()=80`；`veto` = 调基板 `Redline.veto` 命中 ⇒ 整条否决 + 一行 warn +（按 `开关`）写会话 context `redline_veto`；`transform` = 清掉那行提示 + 调基板 `Redline.replace` 换词，其余一律 `null` |
| `RedlineCfg.java` | 本插件**自己的**配置读取器：读同目录 `prompt.md`，惰性缓存 + mtime + 字节数失效。现在只服务一个键（`开关`） |
| `prompt.md` | 本插件**唯一配置源**，现在只有一个键：`开关`（那条提示要不要写）。**词表不在这里** |

## 行为口径

1. **常开族**（`禁词常开` 列的类目）**不需要 caller、不需要场合**：定时任务/闹钟落点
   （`Sinks.TaskSink`，`caller` 恒为 null）也要拦得住 —— 这一条现在由基板 `Sinks.gate` 保证。
2. **不可替换的类目**（`禁词不替换`：`威胁` / `自伤`）命中 ⇒ **整条否决**（哪怕配了替换串）。
3. **配了 `禁词替换-<类目>` 的类目**（`隐私` / `机密键`）⇒ **不否决**，把命中词换成替换串放行。
4. **否决要留痕**：一行 warn（`[出站红线] 出站否决：…`，**与 `开关` 无关，拦了就要留痕**）
   + 按 `开关` 往本会话 context 写 `redline_veto`。**空会话/控制台落点一个字都不写**
   （`Inject.put` 会把空场合映射成全局 `*` ⇒ 提示污染所有会话）。**不占用情绪那个 `emotion_veto` 键。**
5. **异常一律吞掉、绝不抛**（与情绪同一个纪律）：出站兜底不许拖垮一条发送。

## 护栏

- `m` / `m.host()` / `h.out()` / `h.inject()` 都可能是 null：每一种都自己吞掉并"少做点事"，绝不抛异常。
- 词表写坏了只会**少判几个词**（基板 `Redline` 解析失败跳过坏行），不会崩；表整个读不到时
  基板会在启动/状态变化时打一行 **err**（静默失败比失败更贵）。
- 不写任何库、不建表、不派子 Agent、不调 NapCat；常态不打日志（只有"否决了"那一条 warn 是留痕）。
