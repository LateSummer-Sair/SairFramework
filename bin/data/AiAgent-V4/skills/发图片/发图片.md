# 发图片（工具 `sendimage`：单动作工具，op = `sendimage`，能不能用看技能管控表）

往**当前会话**发图：群消息就发群，私聊就私聊（落点由 `h.caller()` 决定，技能自己不改落点）。

## 参数
| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `image` | string | 二选一 | 图片 URL / 本机绝对路径 / `base64://…`（原样交给 NapCat） |
| `text` | string | 二选一 | 非空则用 Java2D 渲染成 PNG 再发；与 `image` 同时给会发两张 |

## 行为
1. **NapCat 未连接 → 直接返回 `Napcat 没有连接`**（基板统一话术，不做任何渲染与发送）；
2. 本地控制台调用 → 没有可发送的 QQ 会话，返回一句说明；
3. `image` 有值 → `sendGroupImage` / `sendPrivateImage`；
4. `text` 有值 → 渲染 PNG 到 `<数据目录>/files/text_<时间戳>.png` 再发；
5. 返回一段结果说明（发到哪、成功什么、失败什么），失败原因取自 NapCat 的 `error` 字段。

## 文字渲染
- Java2D 离屏绘制，**不需要图形界面**（headless 也能跑）；
- 字体按可用性挑选：微软雅黑 → SimHei → SimSun → Noto Sans CJK → SansSerif，中文不会画成方块；
- 自动换行（中文按 2 个宽度算），行高 44px，最长边留白，图片宽度上限 1600px、行数上限 120 行（超出以 `…` 收尾）；
- 文件落在数据目录的 `files/` 下（基板规定的"下载与中转文件"位置），不写别处。

## 权限说明
权限只管控技能（op）：本工具是**单动作工具**，op 就是工具名 **`sendimage`**，写在账本
`skillctl.json` 的一行上 —— `Run` 白名单 = 可用、`Ban` 黑名单 = 不可用、**空 = 未授权 = 不可用**；
`MASTER` 与她本人（`SYSTEM`）恒全权，`ALLUSER` 按表判。判定在动作分支开头（`h.need("sendimage")`），
拒文原样回给模型。发图本身是**对外动作**，平台侧还有基板给 NapCat 装的那道闸门兜着
（她自己的自主行为是 `SYSTEM`，定时推送、钩子回调照常能发）；她读事实块时看的是 `caller.ops`
（这个身份能用的技能 / 动作清单；`"ALL"` = 全权、`[]` = 一个都没有）。（好感度不再决定任何权限。）

## 使用建议
- 长文本、代码、表格、带对齐全角排版的内容，渲染成图片比刷屏好；
- **要发给"指定的人"**（不在当前会话里）：本工具只发**当前会话**，没有收件人参数 ——
  从控制台 / 子 Agent 发起时改走 `send` 的 `fileto`（发文件）或 `record`（发语音），别在这里绕；
- 图片 URL 必须是**直链**（以 .png/.jpg 结尾那种），网页地址发过去是网页不是图；
- 本地路径只能发本机存在的文件，路径写错会在返回里看到 NapCat 的报错。

## 本地路径怎么交给 NapCat（基板负责，技能不用管）
把**本地绝对路径**直接交给 `h.napcat()` 就行：NapCat 与插件不在同一台机器时，基板在 `Api.call` 里
统一把它改写成"文件外链中转"的 URL（跨机可取）；没开中转时改写成本机 `file:///`（同机口径）。
**不要**在技能里自己拼 URL、自己起 HTTP 服务、或把大图塞成 base64 —— 详见 `docs/skills.md` §4.1。
