# 文件（工具 `file`；五个动作各判自己的 op —— 路径不被技能限定，能不能碰由技能管控表判）

一个工具管住"文件"：**读、看目录、找、下载、写**。技能**不限定**路径落在哪儿 —— 相对路径按基板数据根
（`conf.root()`，生产环境就是 `data/AiAgent-V4/`）解析，绝对路径原样采用，**能不能碰由 op 判定决定**：
工具不自己设一道比授权更低的上限。于是数据根以外的文件（例如 `D:\Share\MP3音乐文件\x.mp3`）也进得来：
主人读它不必改用 `exec`（那等于把"读文件"换成最高权限的操作），技能管控表给这个 op 放行就真能用得上。

授权只看**技能管控表**（`data/skillctl.json`，一行一个 op）：
- 五个动作各有一个 op：`file.read` / `file.list` / `file.find` / `file.download` / `file.write`，
  每个动作分支开头判一次（`h.need("file.read")` 等），判不过就把拒绝原文原样回给调用方；
- `Run` 白名单 = 可用；`Ban` 黑名单 = 不可用；**空**（没这一行，或写了没给身份）= 未授权 = 不可用；
  优先级 `Ban > Run > 空`；
- 表里写工具名 `file` 覆盖它全部动作，写 `file.write` 只管那一个动作；
- `MASTER`（主人）与她本人 `SYSTEM` **恒全权**、不受表影响；
- 事实块 `caller.ops` = 这个身份能用的技能/动作清单（`"ALL"` = 全权、`[]` = 一个都没有）。
**被拒时回执就是拒绝原文**（形如 `[权限阻断] 「file.write」没有授权给你（未授权 = 不可用）`），
技能不另造一句 —— 调用方要靠这句话判断要不要换别的工具。

## 五个 op

### `read` —— 读文本（只读）
| 参数 | 说明 |
|---|---|
| `path` | 必填；相对路径按数据根解析，**也可直接写绝对路径**（数据根以外也认，能不能碰由 ACL 判，见下） |
| `offset` | 起始行（1 起），默认 1 |
| `limit` | 最多返回行数，不传时用主人配的「默认读取行数」（**出厂 200**），上限「最多返回行数」（**出厂 2000**）—— 你不用去找那个文件，要改就跟主人说 |

- 超过 `最大读取字节` 直接拒绝（先确认再读，别把上下文撑爆）；
- 内容含 NUL 字节判定为二进制，不支持阅读；
- **编码自动探测**（基板 `kit/Text`）：BOM → 严格 UTF-8 → GBK → GB18030 → 强制 UTF-8 兜底。
  GBK/ANSI 的 txt 不再整篇乱码；非 UTF-8 时控制台会打一行 `[文件] 按 GBK 解码：路径`。
  `find` 的内容匹配走同一口径（GBK 文件里的中文同样能被搜到）；
- 返回带行号：`3| 这一行的内容`，头部写明"共 N 行，显示 a-b"，被截断时末尾提示还有多少行。

### `list` —— 列目录（只读）
默认列数据目录本身：`[D] 子目录/`、`[F] 文件名  大小 字节  修改时间`，最多 `最多列出行数` 项。

### `find` —— 递归找（只读）
- 文件名包含关键词，或文件内容包含关键词（单文件 ≤ `最大扫描字节` 才搜内容）；
- 深度 `扫描深度`、最多扫 `最多扫描文件` 个文件、最多返回 `最多命中` 条；
- 内容命中的给出首次命中的行号与片段。

### `download` —— 下载到 `files/`
- 只接受 **http/https**（`file:`、`ftp:` 之类一律拒绝）；
- **走基板带闸门的下载入口 `Http.download`**：环回（`127.0.0.0/8`、`::1`、`localhost`）、私网
  （`10/8`、`172.16/12`、`192.168/16`）、链路本地与云元数据（`169.254.169.254`）、唯一本地 IPv6
  （`fc00::/7`）一律拒绝，**并且每一跳重定向都重新判定**（302 跳到内网同样被拦）；
  IP 变形（十进制 `2130706433`、十六进制 `0x7f000001`、八进制 `0177.0.0.1`、`127.1`、`[::1]`）一并处理；
  判定本体在 `kit/NetGuard`，技能改不动；被拒时用 `prompt.md` 的「下载拒绝内网」文案；
- 落点固定是 `conf.filesDir()`（数据目录下的 `files/`）：`path` 相对 `files/`，绝对路径也必须落在 `files/` 内，
  **越界直接拒绝**；`path` 留空则用 URL 里的文件名，取不到就用主人配的「默认下载名」（**出厂 `download.bin`**）—— 你不用去找那个文件，要改就跟主人说；
- 超过 `下载上限字节` 会被删掉并如实报告；
- 落盘前已过 `file.download` 这个 op（`FileSkill` 的 download 分支开头一句 `h.need("file.download")`），
  判不过就把拒绝原文原样回给调用方 —— 不再另判落点（授权只看 op）；
- 返回 `已下载 <相对路径>（N 字节）← <url>`；没网/超时返回 `[file] 下载失败：…`，
  跳转链本身没走通（3xx 但没有 Location / 超过 5 跳）返回 `[file] 下载的跳转没走通（…）`，**都不抛异常**。

### `write` —— 写文件
- 执行前判这个动作自己的 op（`FileSkill` 的 write 分支开头 `h.need("file.write")`）：判不过就把拒绝原文原样返回
  （形如 `[权限阻断] 「file.write」没有授权给你（未授权 = 不可用）`）—— 调用方靠这句话判断要不要换别的路，技能不另造拒绝文案；
- **没有"必须落在数据目录以内"这道自设边界**：能不能写由 op 判定决定；正文超过 `写入上限字节` 拒绝；
- **写前报字节数**：先把"将要写多少字节、原文件多大"写进控制台日志，再落盘；
- 返回 `已写入 <相对路径>（N 字节，M 行；原文件 K 字节）`。

## 路径怎么解析 / 结构性防护（关键实现）
```java
File root = h.conf().root().getCanonicalFile();     // 只是"相对路径相对于谁"，不是允许范围
File f = new File(p).isAbsolute() ? new File(p) : new File(root, p);
f.getCanonicalFile();                               // ① `..` 与符号链接：规范化（结构性，不是权限）
real(f);                                            // ② 目录联接/junction：toRealPath 解出真实位置
h.need("file.read" / "file.write");                 // 能不能碰 —— 看技能管控表；被拒就用它的原文回话
```
**没有"必须在数据根以内"这一步**：绝对路径原样采用，只有相对路径按 `root` 解析 —— 挡人的是管控表，不是技能。
① 与 ② 仍然都做，是**结构性防护**（防穿越）：Windows 上 `getCanonicalPath()` **不解析目录联接（junction）**，
只做 ① 会让 `files/联接名/secret.txt` 静默指到数据根外面；`toRealPath()` 会把
最深一层已存在的祖先解成真实路径，所以不存在的新文件（write / download 的落点）也一起被管住 ——
别名（软链 / junction）骗不过这两道。
唯一的"必须在某处以内"是 `download` 的**落点**：`resolveIn()` 保留 ① + ② 两道前缀校验，因为那个 op 的语义
就是"下到 `files/` 里"，越界返回 `[file] 拒绝访问：下载只能落在数据目录的 files/ 里面：<path>`。

## 失败与拒绝
一律返回一句说明，不抛异常（文案全在 `prompt.md`，可以直接改）：
- `[file] 路径不合法（系统不接受这种写法，无法解析）：<path>`（输入不合法，不是权限拒绝）
- `[file] 文件不存在：<relative>` / `[file] 路径不存在：<relative>`
- `[file] 拒绝访问：下载只能落在数据目录的 files/ 里面：<path>`（只有 `download` 的落点会走这句）
- `[file] 文件太大（N 字节，上限 L）…` / `[file] 看起来是二进制文件…`
- `[file] 下载失败：<url>（<原因>）`
- `[file] 这个下载地址指向内网（<主机> · <类别>），按安全口径拒绝：<url>`（SSRF 闸门）
- `[file] 下载的跳转没走通（<原因>），最后停在：<url>`

被 op 拦下的那几句**不在 `prompt.md` 里**：它们由技能管控表判定生成（`Acl` 的判定），统一带 `[权限阻断]` 标识，
形如 `[权限阻断] 「file.write」没有授权给你（未授权 = 不可用）` / `[权限阻断] 「file.write」在技能管控表的黑名单里`。
**权限面没装配**那一支（`auth == null`，只在早期装配/桩宿主里出现）用的同样是 `Acl.DENY_PREFIX`，
后面跟的是「权限面没有装配（auth == null），按拒绝处理：…」——
`Auth.DENY_PREFIX`（`[auth] 权限阻断：`）**只留给识别面兼容，不再出现在任何产出文案里**。

## 使用建议
- 用户说"读一下某个文件"时，先 `list` 看清目录，再 `read` 具体文件，不要瞎猜路径。
- 找东西优先 `find`（一次过滤掉大量文件），别一个个 `list` 翻。
- **主人要读数据根以外的文件就直接 `read`／`find`**，不必绕道 `exec` —— 起进程是另一件更重的事，
  用它来"读个文件"并不划算；`path` 可以直接写 `D:\Share\...\x.mp3` 这样的绝对路径。
- 普通人/群要碰这些动作，得让主人在技能管控表里给对应的 op 开 `Run`（例如 `Run["file.read","user:123"]`）——
  没开时回执会点明是哪个 op 没授权（`[权限阻断] 「file.read」没有授权给你（未授权 = 不可用）`）。
- 要存网上的东西用 `download`，它会替你放进 `files/` 并告诉你路径与大小 —— 别自己去拼磁盘路径。
- 被拒时的说明带 `[权限阻断]`，这是设计，不是故障：它说的是"这个 op 没授权给你"。
- 所有阈值与文案都在同目录 `prompt.md`，改完即时生效（技能每次调用都重读）。

## 读文档：PDF / Word / Excel / PPT（本批新增）

`op=read` 现在**按扩展名分派**，不再一律当纯文本（以前遇到 NUL 就判「是二进制」拒掉）：

| 扩展名 | 怎么读 | 依赖 |
|---|---|---|
| `.pdf` | `pdftotext -layout -enc UTF-8`（poppler） | **零新依赖**（Git for Windows 自带），可用 `prompt.md` 的 `pdftotext:` 指路径 |
| `.docx` | ZIP → `word/document.xml`，段落/表格/换行转成换行与制表 | JDK 自带 `java.util.zip` |
| `.xlsx` / `.xlsm` | 共享字符串表 + 每张工作表逐行逐格 → 制表符表格 | 同上 |
| `.pptx` | 按页取 `<a:t>` 文本，段一行 | 同上 |
| `.doc` / `.xls` / `.ppt` | **读不了**（OLE2 二进制），会明确说「另存为 docx/xlsx/pptx 或 PDF」 | — |
| 其它 | 仍走原来的纯文本 + 编码探测；含 NUL 才判二进制 | — |

**新增参数**（仅文档走）：

| 参数 | 说明 |
|---|---|
| `max` | 最多返回多少字符（默认 8000，上限由 `文档最长字符` 定，出厂 40000） |
| `from` / `to` | **仅 PDF**：只读第 from 页到第 to 页（省 token，几十页的 PDF 很有用） |

**为什么不用 PDFBox/POI**：会往 `plugins\lib` 塞两个大 jar，破坏「单 jar 零原生依赖」的约束；
而 PDF 用现成的 `pdftotext`（质量比手写提取器好得多）、Office 三种本质是 ZIP+XML，JDK 自带的 `ZipFile` 就够。

**边界（要说实话）**：

- **扫描版 PDF** 没有文字层 ⇒ `pdftotext` 抽不出东西，会明确回「大概率是扫描件，给我图片或截图」；
- **`.xlsx` 的公式**只读缓存值（`<v>`），不重算；没有缓存值就显示空；
- **`.docx` 的图片/文本框**读不到文字层里没有的东西；
- 文档超过 `文档最大字节`（出厂 50 MiB）直接拒，不硬啃。

## 取回对方发的文件：`op=fetch`

以前她只能**看到** `[文件 名字 大小]` 这个标签，拿不到内容；现在 `op=fetch` 能把那份文件**取回本地**再读。

| 参数 | 说明 |
|---|---|
| `name` | 文件名或片段（全等 → 包含 → file 值匹配依次尝试）。**不填 = 取对方最近发的那一个** |
| `parse` | 默认解析；传 `0` 只取文件不解析 |
| `max` / `from` / `to` | 取回的是文档时，直接透传给解析（见上一节） |

**流程**：基板登记簿（`Inbound`，TTL 30 分钟 / 最近 16 条）里定位文件段 → 用 `file` 值换下载地址
（`Api.refreshImageUrlQuiet`：rkey → `get_image` → **`get_file`** → `get_msg` 四级降级）→
**复用 `download`** 落到 `files/`（逐跳过 NetGuard）→ 是 pdf/docx/xlsx/pptx 就顺手解析。

**它读什么、不读什么**：

- ✅ 对方刚发的**群文件/私聊文件/文档**，能在 30 分钟内取回；
- ❌ **超过约 5000 条消息**或**已撤回**的文件取不回（上游 LRU 清理，会明确说「换不到下载地址」）；
- ❌ 文件段本身**不带宽直链**，所以必须走 `get_file` 换地址这一步；换不到就是换不到，不会编一个。
