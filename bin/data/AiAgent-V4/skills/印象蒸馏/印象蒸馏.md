# 印象蒸馏（工具 `impression`；`memory` 库是 C 类资源，写行靠归属硬判；`on_timer` 钩子）

「她记得住人」这件事由这个技能负责：**定时**把某个人最近的发言蒸馏成几条"长期印象"，写进基板六库的
**`memory`**（`scope=user` + `scope_id=<QQ>` + `source=印象蒸馏` + `tags` 含 `印象`）。
**印象是按「人」存的，不是按群**：同一个人在 A 群、B 群、私聊说过的话都并到他一个人头上，
换个群照样读得到他的印象；取样覆盖到的群号记进 `extra.groups`，回想时用来标"这些印象是哪几个群看出来的"。
它只是基板资源的调度者：存储走 `h.store()`、模型走 `h.ai()`、日志走 `h.out()`，**不建表、不写 SQL、不碰基板代码**。

## 一轮流水线（`on_timer` 每次 tick 都进来，但绝大多数 tick 什么都不做）
1. **读配置**：`prompt.md` 的 `## 配置`（启用 / 间隔小时 / 每轮人数 / 挑人候选 / 每人取样条数 /
   最少消息条数 / 最低重要度 / 维度标签 / 目标库 …）；
2. **节流**：闸门全在基板 **`kv` 表**里（进程重启不重置）：
   `distill:impression:last`（上次**开跑**）、`distill:impression:done`（上次**成功**）。
   上一轮成功 → 等 `间隔小时`；上一轮失败 → 只等 `失败重试分钟`；**过期就补一轮**
   （重启后第一次 tick 只要距上次成功 ≥ `间隔小时` 就正常跑）；未到间隔 → 直接 return（**不会每 20 秒都打模型**），
   并留一行 `warn` 说清"还需多久、上次成功是什么时候"；
3. **挑人（轮转，不是每次挑当下最活跃的那几个）**：候选池 = `grouplog` 最近发言去重后的
   `挑人候选` 个人（新的在前）；游标落在 kv `distill:impression:cursor`，每轮从游标处往后取
   `每轮人数` 个**没在「间隔小时」内蒸过**的人，然后游标前进。老口径（每轮重挑"最近活跃的 N 个"）
   在群里人一多就只会一直重复蒸同几个话痨，别人永远轮不到 —— 而"问自己的人偏偏就是没被蒸过的那个"；
4. **取样**（每人）：`grouplog` 里 `user_id=<QQ>` 的最近 `每人取样条数` 条 +
   `dialog` 里 `session=qq:<QQ>` 的最近 `每人取样条数` 条（默认只收 `role=user`，即"他自己说的话"）；
   两边按时间合并，行格式取自 `prompt.md` 的 `样本行群聊` / `样本行对话`；总数 < `最少消息条数` → 跳过这个人
   （跳过原因并进本轮那行 `warn` 汇总，看得见）；
5. **问模型**：把样本套进 `## 提取提示词` 的模板，`h.ai().chat(...)` 要它返回 **JSON 数组**
   （`{"label":"…","content":"…","importance":0-10,"tags":["…"]}`）。返回不是数组 / 调用失败 →
   **这一轮不写任何东西**，并把模型回文**前后各 200 字**打进控制台（warn）与 kv 状态；
6. **查重**：把该人已有的印象（同 `source` + `scope` + `scope_id`）拉出来，与新内容做**归一见容**比较
   （只留字母数字与汉字；比较前先剥掉 `标签: ` 前缀；完全相等，或一方包含另一方且短的那边 ≥ `查重最短长度`）；
7. **写库**：重复的**只更新 `importance`**（新的更高才更新，否则不动）**并合并 `extra`**（把这次的来源群并进
   `extra.groups`、`extra.hits` 累加），不重复的才 `put` 新行；
   `importance < 最低重要度` 的直接丢弃；
8. **落状态 + 留痕**：状态写 kv `distill:impression:status`（JSON：ts / op / ok / ran / picked / cursor /
   **why（本轮为什么没跑成）/ last（开跑时间戳）/ done（上次成功时间戳）** / 每人明细 / error / raw）；
   `distill:impression:last` **只在真正开跑过一轮后更新**
   （"真正开跑" = **至少尝试过一次模型调用** —— 客户端缺失那一路也算尝试，`r.model=true`），
   `done` 只在那一轮成功（`ok=true`）时更新。
   模型失败的那一轮不算成功：`last` 照样推进（否则每个 tick 都重打），但状态里 `ok=false`，
   闸门下一次按 `失败重试分钟` 的短退避放行，所以失败不会把流水线永久卡死。

## 写入形状：与「用户画像」的解析约定对齐
`memory` 行的 `content` **不是**随手的句子，而是给「用户画像」解析用的形状：
**一行一条「标签: 值」**，标签取自 `维度标签`（默认 = 情绪稳定 / 兴趣 / 说话风格 / 诚实度 / 发图习惯 / 态度）——
**与 `用户画像/prompt.md` 的清单是"包含"关系、不是逐字相等**：`用户画像` 的「维度」是五项、
「态度键」是 `态度` + `关系` + `印象` 三项，合起来 8 项；本技能的默认清单是它的**前五维 + `态度`**（6 项），
`关系` / `印象` 两个标签本技能不主动产出（模型若给，按"清单外"处理 → 写纯句子）。
所以提示词要模型给一个 `label`：
命中 `维度标签` → 写成 `兴趣: 他长期研究…`（进五维）；没给或给了清单外的标签 → 写纯句子
（「用户画像」把它当"原文补充"渲染，不会丢）。**换标签清单 = 两边一起改**。

## 工具 `impression`
| op | 作用 |
|---|---|
| `get [qq]` | 读该人的印象条目（按重要度降序）。`qq` 缺省 = 当前调用者；**非主人只能读自己**（`qq` 会被改回自己并在结果里说明） |
| `list` | 列出已有印象覆盖的人（按 QQ 去重 + 条数 + 最高重要度）。非主人只看到自己 |
| `refresh [qq]` | 立刻对一个人跑一次蒸馏（同样过闸门；要强制跑就先把 `distill:impression:last` 清成 0） |
| `run` | 立刻对"轮转到的下一批人"批量跑一轮（受 `每轮人数` 约束）。**真正拦人的是归属硬判**：`ImpressionSkill.run` 调 `noDistillDeny` ⇒ 非主人（含群主/管理员，群角色不参与 ACL）一律拒，拒文是 `[权限阻断] 蒸馏/重算是她自己的事，只有主人或她本人（MASTER/SYSTEM）能做。`；另有第一道位判定（工具属 T 类、只判入口：`X` 位 + `memory` 的 `W` 位），`ALLUSER` 默认 `T=无`、C 类只有 `R` ⇒ **非主人一把工具都用不了、写库也一律被位拦下**，要特例放行。主人与她本人（`SYSTEM`）照常。详见「边界与取舍」 |

## 配置与文案在哪
全在同目录的 `prompt.md`（`## 配置` / `## 文案` / `## 提取提示词`）：阈值、开关、提示词模板、样本行格式、
以及技能说出来的每一句话。**保存即生效**（每次运行重读）。技能 Java 里只留三类东西：
结构性字符串（kv 键名、库名、工具名、日志前缀）、**配置读不到时的兜底值/兜底文案**
（`P(c,"键","兜底")` 那一族）、以及**归属拒绝句**（`noDistillDeny` / guard 里那几句中文，前缀是
`[权限阻断]`）—— 最后这一类是安全判定输出，**故意不走 `prompt.md`**。

## 落库 / 观测
| 键 | 内容 |
|---|---|
| `memory` 行 | `scope=user`、`scope_id=<QQ>`（**按人，跨群**）、`content`（`标签: 值` 或纯句子）、`importance`、`source=印象蒸馏`、`tags`（首个标签 = `印象标签`）、`extra.groups`（取样覆盖到的群号，来源场合） |
| `kv.distill:impression:last` | 上次**开跑**的毫秒时间戳（节流闸门；重启不重置） |
| `kv.distill:impression:done` | 上次**成功**（ok=true）的毫秒时间戳（判"该不该补一轮"、日志里说"距上次成功多久"） |
| `kv.distill:impression:cursor` | 挑人轮转游标（候选池下标；重启不倒退） |
| `kv.distill:impression:status` | 上一轮状态 JSON：`{ts,op,ok,ran,skipped,failed,cand,add,upd,dup,low,error,pool,cursor,skip_fresh,picked,people:[{qq,sampled,add,label,skip,error,raw,…}]}` |
| 控制台 | `[印象蒸馏] …` 的 **warn** 行：本轮挑中谁、到点/未到间隔、本轮汇总（含跳过原因）、模型失败、解析失败（带模型回文前后各 200 字） |

> **为什么是 warn 而不是 dim**：基板默认 `logConsole=tool,model`，技能自己的 `dim` 过程行会被丢掉
> （见 `GatedOut`）。"为什么这轮没蒸"是必须看见的事实，所以决策行一律走 `warn`；
> 每人一条的过程细节（取样多少条、新增多少）才是 `dim`。

## 边界与取舍
- **模型失败不写脏数据**：解析失败、`Res.error`（例如没配 apiKey）都只记状态，绝不 half-write；
- **隐私**：`memory` 行按 `scope_id` 分人存，`get` / `list` / `refresh` 非主人只能读自己 / 蒸自己
  （`ImpressionSkill.get` / `.list` / `.refresh`），`run` 这条路上也有**归属硬判** —— 非主人（含群主/管理员）
  被 `ImpressionSkill.noDistillDeny`（由 `ImpressionSkill.run` 在入口调用）拦下：一行模型都不打、库一个字节都不动；
  位判定（工具属 T 类、只判入口：`X` 位 + `memory` 的 `W` 位）对非主人一律先拦下（`ALLUSER` 默认 `T=无`、C 类只有 `R`），账本里的例外条目也改不了这道归属硬判；
- **删掉即消失**：技能目录整体删掉，基板照常运转，只是不再有人记得住人（已写下的 `memory` 行仍在库里）。
