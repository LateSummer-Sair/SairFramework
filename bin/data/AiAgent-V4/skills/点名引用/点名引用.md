# 点名引用（on_message 记账 + 两段上下文 + 出站收尾执行）

**这个插件不给模型任何工具**（front matter 里没有 `tool:`）。它做三件事，而且**只做这三件**：

1. **记账**（`AtPickHook`，`hooks: on_message`）：群里来一条消息，就把「谁 / 几号 / 说了什么 / 什么时候」
   记进 kv（键 `pick:in:<群号>`，新的在后，最多 `清单条数` 条）。
2. **两段上下文**：
   - `AtPickTeach`（稳定段）：告诉她"@ 谁、引用哪条由你自己定"，以及两个标记怎么写；
   - `AtPickList`（易变段，只对群）：把本群最近几条入站的 `message_id` 与 QQ 摆出来 ——
     她手机上看到的聊天窗口里**没有这两个号**（`ctx\ChatWindow.java` 的行是 `[时间] 谁: 说了什么`），
     没有清单就只能靠编。
3. **出站收尾**（`AtPickStage`，`OutboundStage` order=20）：把她写的标记就地换成 CQ 码。

## 她的写法

| 她想干什么 | 她写 | 变成 |
|---|---|---|
| @ 某个人 | `<at qq="1284688456"/>` | `[CQ:at,qq=1284688456]` |
| 引用某条消息 | `<quote id="1942507147"/>`（`<reply id="…"/>` 同义） | `[CQ:reply,id=1942507147]` |
| 什么都不加 | 什么都不写 | 纯正文，一个字节都不改 |

位置由她定：写在开头就是开头，写在句中就是句中。成对写法（`<at qq="1">名字</at>` /
`<quote id="1">原文</quote>`）会**整段吃掉**，不留内层文字（避免同一句话出现两遍）。

## 为什么安全

`at` / `quote` / `reply` 三个标签名本来就在基板 `qq\MarkerTags` 的白名单里，而剥除发生在
出站 stage **之后**（`term\Sinks.java`：先 `stage(...)`、再逐条 `MarkerTags.strip`）⇒
插件读得到、用户看不到；就算插件没跑，基板也会剥掉，**绝不会有一条裸标签发给用户**。

## 边界（说清）

- **不判断**：不看谁是主人、不看回复多长、不看时间差、不记"上一轮是谁"、不做任何兜底补 @。
  要不要 @、@ 谁、引用哪条，**全是她的决定**；
- 号码必须是十进制且 > 0，否则标记直接**丢掉**（宁可没有前缀，也不发畸形 CQ 码）；
- 她若自己写了同号的 CQ 码，标记只被丢掉、**不重复加**；
- 私聊里 `at` 无意义（`私聊不@: true` ⇒ 丢掉），引用照做；
- 只管群：私聊一个键都不写；`开关: false` ⇒ 一条都不记（等于没装）；
- 异常全吞：记账失败最多清单少一条，出站转换失败最多保持原样，**绝不拖垮一条消息**；
- **不许靠 static**：热重载 = 新类加载器 + 新静态字段，所以状态只写 kv。

## 配置

全部外挂在 `prompt.md`（教学文案、清单模板、两个 CQ 模板、条数与有效期）。
惰性缓存 + mtime 失效：**改完保存，下一条消息就生效**，不用 reload。

## 与旧的「@提问者」的区别（为什么换掉它）

旧的按固定规则替她 @：`重要长度 ≥ 40 字` 就 @、`caller 是主人` 就 @、`时差 > 10 秒` 必引用，
而引用的对象是**回合开始时钉住的那条**、@ 的对象是**这一轮的 caller** —— 两半用的是两个时间基准。
回合一长（模型 + 工具 + 子 Agent，实测 80 秒），钉子停在旧消息上、caller 已经换了人，
于是同一条消息里 @ 了一个人、引用了另一个人的旧话。这个插件把决定权交还给她，那套规则整体删除。
