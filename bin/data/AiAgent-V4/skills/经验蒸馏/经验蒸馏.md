# 经验蒸馏（工具 `experience`；`note` 库是 C 类资源，写/改/删靠技能自己的归属硬判；`on_timer` 钩子）

对应 V3 的 `SkillExtractor.extractFromJournal` + `SkillBank.evolve`，在 V4 里就是一条**插件层流水线**：
定时（或手动 `run`）把最近的成功对话/群聊片段蒸馏成**可复用的经验**写进基板六库的 **`note`**
（`source=经验蒸馏`、`tags` 含 `经验`），达标时再**把一条经验提升成一个真技能**（技能自进化）。

它只用 `Host` 给的能力面：存储 `h.store()`、模型 `h.ai()`、工具调用 `h.call("skill_write", …)`、位复核 `h.need*()`、
日志 `h.out()`；不建表、不写 SQL、不碰基板代码。

## 一轮流水线（`on_timer` 每次 tick 都进来，绝大多数 tick 什么都不做）
1. **读配置**：`prompt.md` 的 `## 配置`（启用 / 间隔小时 / 取样条数 / 最少条数 / 最低重要度 / 自动提技 / 提技门槛 …）；
2. **节流**：闸门是 kv `distill:experience:last`（上次**开跑**的时间戳）。上一轮成功 → 等 `间隔小时`；
   上一轮失败 → 只等 `失败重试分钟`；未到间隔直接 return；
3. **取样**：`dialog` 最近 `取样条数` 条（**只取最近 N 行，不筛"成功回合"** —— assistant 行是否落库由基板决定）
   + `grouplog` 最近 `取样条数` 条，
   按时间升序合并、内容去重；行格式来自 `样本行对话` / `样本行群聊`；合并后 < `最少条数` → 跳过本轮（不打模型）；
4. **问模型**：套进 `## 提取提示词` 模板，`h.ai().chat(...)` 要它返回 **JSON 数组**：
   `{"title":"…","content":"…","tags":["…"],"importance":0-10,"skill_candidate":true/false}`；
   调用失败 / 不是数组 → **这一轮不写任何东西**，只记状态；
5. **查重（三道）**：与已有经验（`source=经验蒸馏`）比：① 标题归一化后相等、② 正文归一化后相等 / 一方包含另一方
   （短的那边 ≥ `查重最短长度`）、③ 都不中时按基板 `kit/Fingerprint` 的中文 2-gram Jaccard 判近似
   （标题优先、其次正文；≥ `相似阈值` 且指纹项数 ≥ `指纹最短项数`）。命中 → **只更新 `extra`**
   （`hits+1`，重要度更高才抬高），不重复堆；没命中 → 新增一行（`importance < 最低重要度` 的直接丢弃）；
6. **自动提技**（技能自进化，**默认 off**）：仅当
   `自动提技: on` **且** `importance ≥ 提技门槛` **且** `hits ≥ 提技最低命中` **且** 模型标记了
   `skill_candidate=true` **且** 这一条还没提技过（`extra.promoted != true`）时，才：
   - 先用 `h.needPath(h.conf().skillsDir(), 'W')` **复核写位**（写技能源码 = **B 类**：`SYSTEM` 的 B 是 `R|W`、
     主人 `RWX`、B 类对非主人无位（∅）⇒ 不够就只记状态、不写技能）（`ExperienceSkill.promote`）；
   - 把 `## 提技模板` 的 ```md / ```java 两个代码块用 `{name}/{tool}/{id}/{title}/{tags}/{content}` 渲染；
   - `h.call("skill_write", {op:draft, name, md, java})` 先写草稿，确认后 `{op:promote, name}` 才上线（写线上用 `{op:add}`，写完要 `{op:reload}`）；
   - **成功判据是"注册表里真的多了这个工具"**（`h.tools().getView(tool)`）——基板返回文案不参与判断；
   - 成功后把 `extra.promoted=true` + `extra.skill=<技能名>` 写回去，避免重复提升；
   - 生成的技能**只做查库与回话**（读 `note` 库里那一条经验 / 按关键词搜经验库），不执行命令、不读写文件。
7. **落状态**：kv `distill:experience:status`（JSON：ts / op / ok / sampled / add / upd / dup / low / promoted / error）；
   `distill:experience:last` **只在真的调用过模型的那一轮更新**（样本不足、被节流都不算）。

## 工具 `experience`
| op | 作用 |
|---|---|
| `list [query] [limit]` | 最近的几条经验（带 `query` 就按关键词过滤），显示 `[重要度] 标题 命中次数 标签` 与"已提技"标记 |
| `search query [limit]` | 关键词检索（同样只列本技能写的行；全库检索用基板的 `store`/`note` 工具） |
| `add title content [tags] [importance] [skill_candidate]` | 手工记一条（写 `note` ⇒ 非主人（`ALLUSER`）**一律拒**：`ExperienceSkill.add` 的 `noteWriteGuard`），**先查重**：重复的只累加 `hits`（重要度更高才抬高），返回"已存在" |
| `forget id` | 按 id 删除。非主人（`ALLUSER`）**一律拒**（`note` 是共享知识库、没有归属列）：归属硬判 `ExperienceSkill.noteWriteGuard`，拒绝文案带 `[权限阻断]` 标识 |
| `run` | 立刻跑一轮蒸馏（与定时同一道闸门；非主人（`ALLUSER`）**一律拒**：`ExperienceSkill.run` 开头的归属硬判；受 `取样条数`/`最少条数` 约束） |

## 数据形状（为什么重要度在 extra 里）
基板六库的 `note` 只有 `id/ts/title/content/tags/source/extra`，**没有 `importance` 列**，所以：

| 位置 | 内容 |
|---|---|
| `note.title` / `content` / `tags` | 经验标题 / 正文 / 标签（首个标签 = `经验标签`） |
| `note.source` | `经验蒸馏`（本技能只认自己写的行） |
| `note.extra` | `{"importance":8,"hits":2,"skill_candidate":true,"promoted":true,"skill":"经验_xxx"}` |

`extra` 是 JSON 文本列，基板的 `Store` 会自动序列化/解析（入参给对象、出参拿回对象），所以更新 `extra` 用一次
`store.update("note", id, {"extra": …})` 就把"命中次数 + 重要度 + 提技标记"一起写了。

## 配置与文案在哪
全在同目录的 `prompt.md`（`## 配置` / `## 文案` / `## 提取提示词` / `## 提技模板`）：阈值、开关、提示词模板、
提技模板、素材行格式、以及技能说出来的每一句话。**保存即生效**（每次运行重读）；Java 里只留三类东西：
结构性字符串（kv 键名、库名、工具名、日志前缀）、**配置读不到时的兜底值/兜底文案**（`P(c,"键","兜底")` 那一族）、
以及**归属拒绝句**（`noteWriteGuard` 里那几句中文，前缀 `[权限阻断]`）—— 最后一类是安全判定输出，故意不走 `prompt.md`。

## 落库 / 观测
| 键 | 内容 |
|---|---|
| `kv.distill:experience:last` | 上次**开跑**（真的调用过模型）的毫秒时间戳 |
| `kv.distill:experience:status` | 上一轮状态 JSON（含 `ok`/`error`/`promoted`/`skip`） |
| 控制台 | `[经验蒸馏] …` 过程行**走 `dim`**：基板默认 `logConsole=tool,model` ⇒ **默认一句都看不到**（要看得把 `skill` 加进 `logConsole`）。本技能**没有 `warn` 级的决策行**（印象蒸馏有），所以"这轮为什么没蒸"要靠 kv 状态看 |

## 安全边界（提技为什么默认关）
- 提技会**写文件 + 编译加载代码**，是插件层最重的动作 → 默认 `自动提技: off`，门槛是"重要度 + 命中次数 + 模型标记"三重；
- 调用前还要过**写技能源码目录的位复核**（`h.needPath(skillsDir,'W')`，B 类，在 `ExperienceSkill.promote` 里）：
  普通人（B 类对非主人无位，一位都没有）其实**到不了这一步** —— `run` 在入口就被归属硬判（`ExperienceSkill.noteWriteGuard`）挡住并
  **当场回绝**，既不会写出任何技能，**也不会往 `distill:experience:status` 里留痕**（`on_timer` 那条路的主体是她本人，不受影响）；
- 生成的技能模板是**固定的、只读库**的形状（`h.store()` 查 `note`）——不生成执行命令、不生成读写文件、
  不生成调用 `exec`/`napcat` 的技能；模板本身在 `prompt.md` 里，机主可以审阅后再决定开不开；
- 已提技的行不会重复提技（`extra.promoted`），命名也稳定（技能名固定 + 撞名时自动补 `_<经验id>` 后缀**另建**，
  **不覆盖**已存在的同名技能/工具）；
