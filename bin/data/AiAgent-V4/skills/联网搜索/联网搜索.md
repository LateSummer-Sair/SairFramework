# 联网搜索（工具 `search`：单动作工具，op = `search`，按技能管控表判）

抓 `https://www.bing.com/search?q=...` 的结果页，解析出标题 / 链接 / 摘要返回；出网走基板的带闸门入口 `Http.getGuarded`（环回 / 私网 / 链路本地 / 云元数据一律拒绝，每一跳重定向复检；判定本体在基板 `kit/NetGuard`，技能改不动）——与同族「网页抓取」同口径。适合"上下文里没有、需要外部事实"的问题（新闻、版本号、人物、行情、梗的来源）。

权限上**有门槛**：搜索是一次出网执行（op = `search`，`SearchSkill` 里判 `h.need("search")`），
技能管控表里没给这个身份授权（**空** = 没写这条，或写了没给身份 / 命中 **Ban**）⇒ **非主人用不了这把工具**。
要放开只能由主人在表（数据根 `skillctl.json`）里写一行，例如 `Run["search","ALLUSER"]`；
她本人 `SYSTEM` 与主人恒全权（好感度不再决定任何权限）。

## 参数
| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `query` | string | 是 | 搜索关键词 |
| `count` | integer | 否 | 返回条数，默认 5，上限 10 |

## 返回
```
必应搜索 <关键词>：<n> 条
1. 标题
   https://真实链接
   摘要文字
2. …
```
`[search] 搜索失败：…` 表示没网 / 必应不可达 / 被反爬；`没有解析出结果` 表示页面结构变了或返回了验证页；
`[search] 这个地址指向内网（主机 · 类别），按安全口径不搜：地址` 表示**被 SSRF 闸门拦下** —— 回的是内网拒绝说明，不是「搜索失败」，也不是网络问题。

## 文案在哪
本技能**暂无 `prompt.md`**：面向模型的文案（`[search]` 开头的搜索失败 / 没有解析出结果 / 内网拒绝）目前**硬编码在
`SearchSkill.java` 里** —— 改文案要改 Java，改这份 md 不生效。（收拢进 `prompt.md` 属另一笔改动。）

## 实现要点
- 解析优先用 jsoup（classpath 上有就反射调用），没有则回退内置正则解析 —— 技能是运行期由基板编译的，不能假定宿主 classpath 一定有 jsoup。
- 必应的跳转链接（`bing.com/ck/a?...u=a1<base64>`）会被还原成真实 URL 再返回。
- 超时 15 秒；任何异常都转成一句可读说明，绝不抛给模型。

## 使用建议
- **多对象拆分搜索**：一次只搜一个对象，多个对象拆成多次调用（可以并发派给子 Agent），最后合并分析。
- 搜到的东西要落成笔记就先 `note` 查重再写，别重复存。
- 只有链接没有摘要时，用 `web` 工具抓那一条具体网址看正文，别靠标题猜内容。
- 拿不到就说拿不到，不要用记忆里的旧信息冒充搜索结果。

## 两个后端（本批新增 DeepSeek 官方）

| 后端 | 谁用 | 优点 | 代价 |
|---|---|---|---|
| **DeepSeek 官方**（`POST /v1/tools/search`） | 主人与她本人（`via=auto` 时自动） | 结构化字段（`rerank_score`/`summary`/`date`/`authority`）、支持搜索语法（`site:` / `-site:` / 精确短语 / `lang:` / `after:` / `before:`）、`need_content=true` 直接带正文 | 按**成功请求**计费（约 5 元/1000 次） |
| 必应（抓结果页） | 其他身份，以及官方不可用时 | 免费、无需 key | 怕反爬/改版，解析不到就只说「没解析出结果」 |

**选后端的规则**：`via=auto`（默认）看**调用者身份** —— 主人/她自己走官方，其他人走必应。
这样群里的搜索不会烧主人的额度。要强制指定就传 `via=ds` 或 `via=bing`。
官方失败时（无 key / 401 / 402 余额 / 429 限流 / 断网）会**安静退回必应**，并在结果头写清原因。

## 让官方后端发挥满血（两个参数别浪费）

### `ori_question` —— 把**用户原话**一起带过去

官方文档明确说它用来「更好地理解搜索意图」。所以搜索时**把你收到的原问题也传进来**：

```
用户说：「有没有甘雨加强的消息？」
→ search(query="甘雨 加强", ori_question="有没有甘雨加强的消息？")
```

`query` 是给搜索引擎的关键词，`ori_question` 是**意图** —— 两个都给，结果质量明显不一样。

### `need_content=true` —— 一次调用同时拿到结果和正文

默认每条只有 `snippet`/`summary`。要读正文时，**别先搜再一条条 fetch**：

```
search(query="…", count=3, need_content=true)     ← 一次就够
```

省掉 N 次 `web op=fetch`（也就省掉 N 次计费）。代价是这次搜索更慢、更贵一点，所以**只在确实要正文时开**。

### 搜索语法直接用，不需要额外参数

`query` 里**原样写**就行，官方搜索引擎自己认：

| 想做的 | 写法 |
|---|---|
| 只要某个站 | `DeepSeek site:github.com` |
| 排除某个站 | `DeepSeek -site:example.com` |
| 精确短语 | `DeepSeek "release notes"` |
| 限定语言 | `DeepSeek lang:zh,en` |
| 限定时间 | `DeepSeek after:2025-01-01` / `before:2026-06-01` |

⇒ 所以**不需要** `site=` / `lang=` 这种糖参数 —— 直接在 `query` 里写，少一层转换、少一处可能与官方语义脱节的地方。
