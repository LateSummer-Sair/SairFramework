# 辅助识图（工具 `look`；单动作工具 op = `look`，取图另按 `napcat.get_msg` 判）

一个 op：`look`（`declareOps` 里 `ops.add("look", "", "让会看图的模型看一条消息里的图")`）。
**只吃消息身份**（`id` = 消息 id 的十进制串，`seg` = 这条消息里第几个图片段），
把图交给基板的 DeepSeek 客户端（`h.ai().vision(...)` + `Msg.userWithImages`），拿回一段**机器描述**。

权限：入口判自己的 op（`h.need("look")`：技能管控表里**空** = 未授权 = 不可用），
放行后取图那一步另判 NapCat 动作的 op（`h.need("napcat.get_msg")`）；两道都过才真的看图。
判不过就把基板的拒绝原文原样回给模型；她自己（`SYSTEM`）与主人恒全权，不受管控表影响。

它是一台**长生命期的辅助组件**，不是一次性子 Agent：

| 性质 | 怎么落 |
|---|---|
| 跨回合存活 | 进程内单例 `VisionAgent`，留着自己那一小段对话（`recognizer.md` 是第一条 system，之后是它自己的「问题 → 它自己的描述」文字轮） |
| 懒启动 | 第一次 `look` 才建 worker；线程名 `v4-look` |
| 空闲自退 | 队列空 `空闲退出秒`（默认 120）自己退出（`worker=null`），下次请求再懒建 ⇒ 热重载不留孤儿线程 |
| 重启不丢 | 会话计数落 `kv`（`mediax:look/session`）、去重账本落 `kv`（`mediax:look/<id>#<seg>`） |

## 只在主模型自己看不了图时才有意义（门在入口）

`look` 存在的前提是「主模型看不见原图」：能看图的模型（`deepseek-flash` 这类）**自己就看得到**，
再派一个识图组件去看是白花钱、还多一层转述。所以入口先判，判据**只有配置面那一处**：

| 判据（按序） | 结果 |
|---|---|
| `conf.mediaVision()` 是 `no` / `off` / `false` | 拒：`[look] ok=0 图片能力被关（mediaVision=no）` |
| `conf.mediaVision()` 是 **`relay`** | **放行**（不判"能不能看"、也不再要求模型名非空）⇒ 正常走识图 |
| `CtxBuild.looksVisionCapable(conf.resolveModel(), conf.visionModels(), conf.visionModel())` 为真 | 拒：`[look] ok=0 你自己能看原图，不需要识图组件` |
| `conf` 读不到 / `resolveModel()` 为空 | 拒（判不出来 = 拒，与全仓 `Host.need` 同口径） |
| 以上都不是（`auto` / `yes` / 怪值） | 正常走识图 |

**`relay` 这一档为什么必须放行**：它的语义是「图不再原生挂进主模型请求、**所有图都只能过看图手**」——
此时若还按上表那条能力判据拒，就是"提示词让她用图手、图手却拒她"= 她永远看不了图。
那条能力判据只服务**原生模式**下的"别白花钱"（"我能不能看"与"允不允许把图挂上去"是两件事）。
在这一档下每张她真的看了的图会多一次视觉调用（原生模式下本来挂在主模型那一次请求里），
她的图片理解也从"自己看原图"变成"读图手给的机器描述" —— 这是有意的取舍，回退只需把
`mediaVision` 改回 `auto`。

> `relay` 说的是**配置值** `mediaVision`（正式取值只有 `relay` 这一个名字；基板侧另接受别名 `look`，
> 技能面只认 `relay`，不实现别名）。事实行里的 `models.mode`（`off`/`native`/`relay`）是**基板**
> `CtxBuild.visionMode(...)` 算出来的另一个口径，本技能不读、也不判它。
> 配置是活配置：**改了要基板重载才生效**。

> 判据用的是**基板自己的** `CtxBuild.looksVisionCapable(model, visionModels, visionModel)`
> （`ctx\CtxBuild.java:198-213` 的**带配置追加项**那个重载：硬白名单 + 配置里的 `visionModels`/`visionModel`
> 追加项）—— 本技能**不自己维护第二套白名单**。R3 起这一处的两个追加项走 `ConfView.visionModels()` /
> `ConfView.visionModel()`，与 `CtxBuild.selfHasVision`（`ctx\CtxBuild.java:250-252`）**同一个默认值来源**
> （缺键 = `deepseek-flash`），不再有"缺键传空串"的形式差异。

## 身份 → 图 URL：三级阶梯（绝不编 URL）

```
look(id="10001", seg=0)
  ① 进程内身份索引：id#seg 已经登记过 ⇒ 直接复用（src=index，0 次网络）
     ①b 知道这条身份的 file 值时，问基板入站登记簿 h.inboundImageUrl(file)（src=inbound，0 次网络）
  ② h.napcat().call("get_msg", {message_id: id}) ⇒ data.message[] 里第 seg 个 image 段的 url（src=get_msg）
  ③ 拿不到 ⇒ 如实失败（gone / empty / 瞬时），绝不编一个 URL、绝不下载字节
```

**阶梯① 不是摆设**：本技能声明 `hooks: [on_message]`，**每条入站消息到达那一刻**就把
`"<消息 id>#<图片段序>" → {url, file}` 记进进程内身份索引（TTL 30 分钟、上限 256 条，
与基板自己的 `qq.Inbound` 登记簿**同寿同量级**）⇒ 一条刚到的图片消息，**第一次** `look`
就是 `src=index`、**0 次 `get_msg`**。索引过期后自动回落 ②。

> 钩子只碰内存：**零 I/O、零网络、零 kv 写**，不改 `payload` 的 `_handled`/`_reply`（也就不会
> 改变基板还要不要自己回），异常一律吞掉 —— 它在**入站同步路径**上，任何昂贵操作都会拖慢所有消息落库。
> 剪枝按登记顺序做（amortized O(1)），**不遍历大表**。
> 索引有效期由 `prompt.md` 的 `索引TTL秒`（默认 1800 = 30 分钟）控制；调小只影响"新图多久走一次 `get_msg`"。

- **不接受 URL**：传 `http(s)://…`、`data:image/…`、`file:…` 一律拒（`[look] ok=0 只接受消息身份（id/seg），不接受 URL`）——
  这条堵的是"模型自己抄事实行里的 rkey URL 再去第三方取图"（越权 + 泄密 + rkey 过期）。
- `get_msg` 是**带闸门**的 NapCat 动作（`h.need("napcat.get_msg")`，判在**调用者线程**上）；
  真打网那一跳在 worker 线程上跑，worker 里会把原主体重新绑上（`Ctx.of(subject)`），**不会因为换线程就变成 SYSTEM**。

## 账本（`store.kv`，前缀 `mediax:look/`）

| 键 | 值（键序固定） | 说明 |
|---|---|---|
| `mediax:look/<id>#<seg>` | `{"v":1,"id":"10001#0","state":"ok","src":"get_msg","model":"deepseek-flash","ts":…,"text":"…","chars":N,"n":1}` | 正/负**同键**，靠 `state` 区分 |
| `mediax:look/session` | `{"v":1,"ts":…,"turns":N,"looks":N,"model":"…"}` | 会话的持久部分（也是"它活着"的可观测面） |
| `mediax:look/budget` | `{"day":"YYYY-MM-DD","n":N,"min":<ms>,"minN":N}` | 每日 / 每分钟计数（按 `day` 串翻页，重启不清零） |

`state` 的词表与 `qq\QuoteCache` 的 `ST_*` **同名同义**：

| state | 什么时候 | 进 kv 吗 | 第二次调用 |
|---|---|---|---|
| `ok` | 模型给出了描述（此时才有 `text`/`chars`/`n`） | 是 | 命中账本，**0 次模型调用** |
| `empty` | 取回来了但这条消息在那个 `seg` 上没有图片段 | 是 | 命中账本，回"看不到" |
| `gone` | `retcode 1200` / "撤回/不存在" | 是（**永不过期**：撤回是永久的） | 命中账本，不重试 |
| `fail` | 非 1200 的 `retcode≠0`（参数错/权限不足这类永久性拒绝） | 是 | 命中账本，不重试 |
| `pending` | 预算超限被丢弃（这一轮没去看） | 是（下一轮**照样重试**，`pending` 不算命中） | 重新尝试 |
| （瞬时失败不落 kv） | 超时 / 未连接 / 非 JSON / 模型报错 / 取到段但没有可用 URL | **否** | 内存里抑制 60 秒，不写任何键 |

**TTL** 逐字照抄 `QuoteCache.ttlMs()`：`min(mediaCacheHours × 3600000, grouplogKeepDays × 24 × 3600000)`
（`mediaCacheHours ≤ 0` ⇒ 永不过期）。**只有 `ok` 才写 `text`**（非 ok 时那个键**不出现**，不是空串、更不是"（取不到）"这类填充词）。

## 表情包候选：看图时顺带产一行（跨技能接口）

甲方口径：**表情包收集是跟着看图手走的，是在看图时的一个顺带，而不是主动自动去监听每一个消息**。
所以候选只有**这一个生产者**，落点就在那次识图调用里（`run(Task)` 里**唯一**那处 `ai.vision(...)`）：

- 第一条 system = `recognizer.md` 逐字 **+ 一个固定的"附加任务"块**（要求它在描述最后另起一段给四行：
  `表情数量` / `图中文字` / `内容描述` / `安全判定`）—— 仍是**同一条 system、同一次请求**，
  不因此多打一次网、多调一次模型；
- 回执先**剥掉** trailer：描述 = trailer 之前的正文，回执形状仍是 `[识图·<模型>] <描述>`
  （账本里也只存正文 ⇒ 命中账本那条路同样不带 trailer）；
- 解析出三项后写一行 kv `sticker:cand/<md5>`（`md5 = Fs.md5(Utf8(url 非空 ? url : file))`，
  与 `表情包` 的 `srcMd5` **同配方**）：

| 键 | 值（键序固定） |
|---|---|
| `sticker:cand/<md5>` | `{"v":1,"src":…,"url":…,"file":…,"faces":"无\|一张\|多张","text_len":N,"safe":true\|false,"desc":"…","id":"<msg_id>#<seg>","model":"…","ts":<ms>}` |

口径与纪律：

- **只在 `state=ok`（真识别成功）且 trailer 解析成功时写**；`gone` / `empty` / `fail` / 瞬时失败一律不写；
- `safe` **只有逐字"正常"才是 true**；读不到 / 写错 / `表情数量` 不在枚举里 ⇒ **不写候选**（fail-closed）；
- `text_len` 与 `表情包` 的 `countChars` **同口径**（实现逐字照抄，两边对同一串必须同值）；
- `desc` **压成单行并截到 200 字符以内**（超长时末尾补「…」并在行里多一个 `"cut":true`；
  它是全文正文那一句，不是 trailer 里的「内容描述」行），不把整段描述塞进 kv；
- **跨技能接口**：键名 / 字段 / 判定口径两边必须一致，改键名要先过技能线经理；
  **本技能不删这个键**（清理只由消费者 `表情包` 做：读到即删 + 超 `ts` 过期删）；
  同一个 `id#seg` 第二次进来会先命中账本**直接返回** ⇒ 生产者侧天然幂等（只会同键覆盖，不会多出行）；
- **三道防线**（她自己的图绝不入池）：① 钩子只收 `post_type=message`，`message_sent` 在基板入站之前
  就被丢了 ⇒ 她自己的消息**根本登记不进**身份索引；②/③ 写候选前判 `user_id == self_id`（且 `self_id > 0`）
  ⇒ 不写，并且**证明不了"发图的人是别人"（两个数读不到 = 0）也一律不写** —— 代价是索引过期
  （30 分钟）的老图不会被收成候选；
- **不新增任何配置键**（`prompt.md` 的键面没变）。

## 图片内容审查：涉政 / 黄赌毒只审「图片内容」这一层

甲方令（逐字）：**涉政、黄赌毒只针对图片内容审查，消息内容放宽的** —— 这两类红线**不再拦聊天正文**
（那是情绪 / 出站那条线的事），只在**图片内容**这一层审。判据真源就是本技能 `prompt.md` 里的两张词表：

| 配置键 | 条数 | 读法 |
|---|---|---|
| `禁图-涉政` | 16 | 逗号分隔（半角/全角都认）；命中 = 模型对这张图的回执里出现**任一词形**（子串、大小写不敏感） |
| `禁图-黄赌毒` | 9 | 同上 |

> **词表原文只许留在 `prompt.md` 里**：报告 / 日志 / 控制台输出**只报条数**，一个词都不许复述。
> 本技能的 `.java` 里**一个词都没有**（改词只改数据：`prompt.md` 每次调用重读，保存即生效）。

**审查点（唯一插入点）**：`VisionAgent.run(Task)` —— **模型回执拿到之后、回执成形与任何落盘之前**。
那条路一次产出**两样东西**，所以这一处就把两条路一起盖住了：

1. 交给她的识图回执 `[识图·<模型>] <描述>`（`MediaRender.machine`）；
2. 给 `表情包` 的候选行 `sticker:cand/<md5>`（`writeCandidate`）。

命中任一类 ⇒ **描述不交出去、候选行不写、账本不落**，回执换成固定的一句（`prompt.md` 的 `图片拦截`）：

```text
[识图·已拦截] 这张图的内容按红线不转述。
```

并记**一行 warn**：`图片拦截 类目=<类目名> id=<消息id>#<seg>` —— **只带类目名与图 id/seg，不带描述正文**。

- **账本命中那条路也过同一道闸**（`fromLedger` 调同一个 `imgGate`）：否则本次改动**之前**落进账本的
  旧描述会在缓存期内被原样转述出去。判据仍是那两张表、仍是**同一个函数**，不是第二套逻辑。
- **拦截结果不落账本**：同一张图再看一次会**重新识别、再拦一次**（回执逐字相同，确定性）；
  代价是重复的视觉调用，换来的是"拦截结果不落盘"这条干净纪律，且 `state` 词表**一个都没新增**。
- **fail-open**：读不到词表（缺行 / 整份 `prompt.md` 读不到）⇒ **放行** + 一行 warn
  （`图片审查词表读不到，这几类按放行（fail-open）：…`）—— 识图是功能，不能因为读不到词表就把图全禁了。
- **审的范围** = 模型对这张图的**整条回执**（描述正文 + trailer 那四行）：trailer 里的「图中文字」
  也是图片内容（图上的字），所以一并审，不做"只审正文"的收窄。
- **绝不碰她的聊天正文**：本技能只声明 `hooks: [on_message]`，那个钩子只登记内存索引（零 I/O、
  零网络、不产描述、不写候选）；`imgGate` 全仓只有**两个调用点**，都在 `VisionAgent` 内、
  输入都只有"模型对这张图的回执"。正文里出现同样的词**不拦**（那是另一条线的面）。

## 串行闸 / 预算闸 / 空闲自退

- **串行 1**：单线程 worker + `ArrayBlockingQueue(32)`；同一个 `id#seg` 同时只入队**一个**任务
  （`ConcurrentHashMap.putIfAbsent` 分流等待），所以"同一身份只解析一次"是构造性的，不是靠约定。
- **预算**：每分钟 / 每日上限写在 `prompt.md`（12/min、300/天）。超了**丢弃（不排队）**、
  账本写 `pending`、打一行日志、回 `[look] ok=0 …`（缓存是优化，不是正确性依赖）。
- **空闲自退**：队列空 `空闲退出秒` 后 worker 自己 `return`（不是永驻线程），下次请求懒建。

## 只描述不行动（构造性）

会话的 `messages` 里**永远不带 tools**（`opts` 只有 `model`），所以它**没有手**：
想改库、想发消息、想调工具都没有工具可调。别指望它去执行任何动作——它只把看到的说清。

## 边界与取舍

- **不看字节**：不下载、不落盘、不返回 base64；URL 原样交给模型（`image_url`）。
- **`seg` 的口径**：本文冻结为"**这条消息里第几个图片段**（0 起）"，不是 `message[]` 里第几个段。
  `id#seg` 就是去重身份 ⇒ 一条消息 3 张图 = 3 个身份 = 最多 3 次识别。
- **`seg` 与基板 `ord` 差 1（跨线事实，不许隐式混用）**：基板事实行那个序号是 `ord` = "**第几张图（1 起）**"
  （`qq\MediaAttach.java:71` 的 `Skip.ord`，注释逐字"它是第几张图（1 起）"）⇒ 两边换算**只有一条**：
  `ord = seg + 1`。**要跟基板对账就必须显式写 `ord = seg + 1`**，不许把 0 起的 `seg` 直接当 1 起的 `ord` 用。
  本技能现码**没有任何调用点读基板的 `ord`**（grep 证据见 R3 对账记录）—— 这一条是"**防将来踩**"，不是现存换算。
- **历史轮不带图**：会话窗口里的旧轮只留文字（图只在它自己那一次请求里出现过）。要它"再回头核对像素"
  就再调一次 `look`（`refresh=true` 会绕过账本重新识别）。
- **删掉即消失**：技能目录整体删掉，`look` 工具就没了（账本与会话 kv 仍留在库里）。
