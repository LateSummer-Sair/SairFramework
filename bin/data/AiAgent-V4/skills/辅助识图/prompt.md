# 说明
# 缓存小时：同一条消息的同一张图的结果保留多久（0 = 永不过期）。有效 TTL 还会被
#   min(缓存小时, grouplogKeepDays×24) 夹一刀 —— kv 表不被 Store.maintain() 清理，
#   不夹这一刀账本会活得比群聊记录还久（与 qq\QuoteCache.ttlMs() 逐字同一条规则）。
# 每日上限 / 每分钟上限：真打模型的次数上限（命中账本不算）。超了**丢弃、不排队**：
#   账本写 state=pending、打一行日志、回一句"这张图我没看"。
# 空闲退出秒：worker 线程空闲多久自己退出（0 = 不退出，常驻）。默认 120 是"防热重载留孤儿线程"的口径。
# 最大图片字节：单张图超过它就跳过这张并如实说明（判据是事实里的 file_size，0 次网络）。
# 等待秒：一次 look 最多等 worker 多久（worker 是单线程，第 2 个请求要在队列里等第 1 个）。
#   超时只回一句"我没看"，worker 仍会把结果写进账本 ⇒ 稍后同身份再调就是 0 成本命中。
# 对话窗口轮：会话里最多留几轮「它自己的问题 → 它自己的描述」（旧轮只留文字、不带图：
#   图只在它自己那一次请求里出现过，历史里重发图只是多付钱）。
# 视觉模型：留空 = 用基板配置 conf.visionModel()（默认 deepseek-flash）；填了会覆盖这次请求的 model 字段。
#   **不随主模型变** —— 这一条是"识图用会看图的模型"的全部含义。
# 不接受URL：这一句是**冻结文案**（契约逐字）：传 URL 一律拒，堵"模型自己抄 rkey URL 再去第三方取图"。
# 各项文案里的 {id} / {seg} / {state} / {error} / {why} / {n} / {sec} / {op} / {path} 会被如实替换；
#   文案缺失时用 Java 里的结构性兜底（同一句话，保证回执形状永远是 [look] ok=0 … 或 [识图·模型] …）。
