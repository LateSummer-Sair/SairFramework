# 网页抓取（工具 `web`：三个 op —— 默认的 `web`、`web.dom`、`web.shot`）

权限上**有门槛**：抓取由技能管控表按 op **`web`** 判（`WebSkill` 里 `h.need("web")`）——
没给授权的身份（账本里 `Run["web", …]` 那行没写他）= **不可用**，拒绝文案带 `[权限阻断]` 标识，
要特例放行由主人在账本 `skillctl.json` 里补身份；她本人 `SYSTEM` 与主人不受表影响、恒全权
（好感度不决定任何权限）；与权限无关的 SSRF 闸门见下面「安全闸门」。

抓一个具体网址，把内容整理成模型能读的样子：

- 内容像 JSON（`{` / `[` 开头且能解析）→ 用 Gson 美化后返回；
- 否则按 HTML 处理：去掉 `script/style/注释`，块级标签转行，去标签、解实体，压掉多余空行；
- 想自己看原始 HTML（找结构、取属性）时传 `raw: true`。

## 参数
| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `op` | string | 否 | `text`（默认，纯 HTTP）／`dom`／`shot`／`look`／`nav`（跳转）／`act`（执行 JS）／`close`（关容器） |
| `js` | string | act 必填 | 在页面里执行的 JS，返回值原样带回 |
| `browser` | string | Linux 必填 | 浏览器可执行文件路径；不传则看 `prompt.md` 的「浏览器:」，再退到 Windows Edge 默认位置 |
| `url` | string | 是 | 完整网址；只写域名时会补 `http://` |
| `max` | integer | 否 | 最大字符数，默认 4000，上限 20000（≤0 或非数字按默认；超过上限夹到 20000） |
| `raw` | boolean | 否 | 默认 false；true 时不解析，直接返回原始内容（同样截断） |

## 返回
正文文本（第一行是 `GET <最终地址>（HTTP <状态>，<字符数> 字符，编码 <编码>）` —— 这个数**是解码后的字符数**，代码传的是 `Http.Res.body` 的 `length()`；占位符名 `{bytes}` 与 Java 绑定、别改）；超长时末尾附 `…（已截断，原始 N 字符）`。失败返回 `[web] 抓取失败：…`（DNS 失败、超时、HTTP 4xx/5xx 都会说清是哪种）。

## 文案在哪
**全部在 `prompt.md`**（本文件夹里）：拒绝内网 / 拒绝协议 / 重定向异常 / 抓取失败 / 空正文 / 结果头 / 截断尾巴。
缺键时技能明确回 `[web] prompt.md missing text: 键名` —— **没有兜底文案**，改文案只改 `prompt.md`（改完即生效）。

## 安全闸门（SSRF）
抓取走基板的 `Http.getGuarded`，判定在基板 `kit/NetGuard`（技能改不动）：

- **拒绝**环回（`127.0.0.0/8`、`::1`、`localhost`）、私网（`10/8`、`172.16/12`、`192.168/16`）、
  链路本地（`169.254/16`，含云元数据 `169.254.169.254`）、唯一本地 IPv6（`fc00::/7`）、
  运营商 NAT（`100.64/10`）、保留/组播段，以及云元数据域名（`metadata.google.internal` 等）；
- **IP 变形一起处理**：十进制 `2130706433`、十六进制 `0x7f000001`、八进制 `0177.0.0.1`、少段 `127.1`、
  末尾点 `localhost.`、IPv6 方括号 `[::1]`、IPv4 映射 `::ffff:127.0.0.1`；
- **域名先解析再判**（解析出的任一地址是内网就拒；解析失败按非内网放行，与原口径一致）；
- **重定向逐跳复检**：JDK 的自动跟随被关掉，`Location` 由基板自己解析，**每一跳在发起连接前**重新判定
  （否则 `http://外面/` 302 到 `http://169.254.169.254/` 就绕过了），最多 5 跳。

## 编码（非 UTF-8 网页不再乱码）
响应体统一按基板 `kit/Text` 的口径解码：**BOM → Content-Type charset → `<meta charset>` →
严格 UTF-8 → GBK → GB18030 → 强制 UTF-8 兜底**；实际用的编码写进结果头（`编码 GBK`）。
`Content-Encoding: gzip/deflate` 的响应会自动解压。

## 实现要点
- 超时 15 秒；跳转由基板逐跳处理（最多 5 跳）；UA 用浏览器标识，尽量少被挡。
- 只读：不落盘、不改任何数据。抓到的东西要留档，用 `note` 工具自己记。
- 响应体超过基板 `Http` 的 `DEF_MAX_BYTES`（8MB）会被**静默截断**（读到上限就停，不报错、结果头里也看不出来），
  被截断的大 JSON 常常解析不出来（`looksJson` 不过就按 HTML 去标签）——怀疑抓到的东西不完整时，先想到这一点。

## 使用建议
- 用户贴了 URL 就**必须**真的抓一次再回答，不要照着链接文字编内容。
- 搜索结果只有标题没有摘要时，挑一条最相关的链接抓正文。
- 页面是动态渲染（JS 加载）时正文可能是空的 —— 如实说明"抓到的正文是空的"，别硬凑。
- 抓到的长文要提炼，不要把 4000 字原文倒给用户。

## 看见网页：`op=dom` 与 `op=shot`（本机 Edge，无头）

默认的 `text` 只拿**服务端返回的 HTML**，不执行 JS。页面靠 JS 渲染时它看到的是空壳。
另外两个 op 交给**无头 Edge**（Chromium）真跑一遍：

| op | 做什么 | 产出 | 什么时候用 |
|---|---|---|---|
| `dom` | `msedge --headless=new --dump-dom <url>` | 执行完 JS 的 DOM → 去标签成文本；另留一份 `<files>/web/dom-<时间戳>.html` 快照 | 要真实文本、真实链接；页面靠 JS 渲染 |
| `shot` | `msedge --headless=new --screenshot=… <url>` | `<files>/web/shot-<时间戳>.png` | 要判版式/看图/看图表；**产出交给 `screen(op=see, file=…)` 就是「看见网页」** |

实测成本：一次调用 **6~8 秒**（浏览器冷启动占大头），1280×900 的截图约 40 KB。

### 两条硬性设计

1. **开浏览器前先过 SSRF 闸门**：`kit/NetGuard.check(url)`（**只判、不发请求**）。
   浏览器自己解析域名、自己跟重定向，`Http.getGuarded` 那道闸门**管不到它** ——
   不在这里拦，`shot` 就成了打穿内网的通道。命中时回 `[web] ok=0 这个地址落在内部/私有网段，拒绝：…`。
2. **不走 shell**：进程用 `ProcessBuilder` + **参数数组**拉起，URL 不经过命令行。
   URL 是模型给的、可能含 `&` `'` `|`，走 `cmd /c` 就是命令注入洞。

### 浏览器 profile

落在 `<files>/web/profile/`（持久）。**好处**：登录态可跨调用复用；**代价**：它是个会累积的状态，
也是本技能唯一会留凭据的地方 —— 要清就整个删掉那个目录。

启动参数固定带 `--no-first-run --no-default-browser-check --disable-sync --disable-extensions --mute-audio`：
少了 `--disable-sync` 会在新 profile 上弹 Edge 的同步确认页，截到的就是那个对话框（实测踩过）。

## Web 容器（`nav` / `act` / `close`）—— 真正「操作网页」

`shot` 那种一次性 `--screenshot` 每次都是**全新会话**，没法「先点一下再截」。所以另有一个**持久容器**：
一个带调试口的无头 Edge，端口与 pid 记在 `<files>/web/browser.{port,pid}`。
**登录 cookie、页面 JS 变量、滚动位置都跨调用保留**。

| op | 作用 |
|---|---|
| `nav` | 让容器里的页面跳到某个网址（过 NetGuard 之后才跳） |
| `act` | 在**当前页面**执行一段 JS —— 这是操作的主力：`document.querySelector(sel).click()`、填 `value` + 派发 `input` 事件、滚动、读状态，都能一步到位 |
| `close` | 关掉容器 |

**典型一轮**（全程不需要像素坐标）：

```
web op=nav  url=https://example.com/list
web op=act  js="[...document.querySelectorAll('a')].map(a=>a.textContent).slice(0,10)"
web op=act  js="document.querySelector('a.next').click(); 'clicked'"
web op=act  js="await new Promise(r=>setTimeout(r,800)); document.body.innerText.slice(0,500)"
web op=shot                       ← 不给 url = 截容器当前页
web op=look  ask="这一页的表格第三行是什么"
```

### 为什么不用 CDP 的 `Input.dispatchMouseEvent`

像素点击在网页上是最差的一条路：元素会被遮挡、会滚动、响应式布局还在动。
`Runtime.evaluate` 直接按**选择器**点到元素，精确且不依赖分辨率 —— 这也正好绕开了远程桌面分辨率漂移的问题。
真需要像素级（canvas 画布类页面）时再另说。

### 能力边界（要讲清楚）

`act` 是**在页面里跑任意 JS**，等价于「主人的 exec」，所以它的 op 单独判权：`web.act` 默认只给主人与她本人，
ALLUSER 一律 Ban。同理 `web.nav` / `web.shot` / `web.look` / `web.close` 也是单独 op、默认不给 ALLUSER。

## DeepSeek 官方 Fetch（`op=fetch`）

`op=text` 是自己抓 HTML 再去标签 —— 粗糙、怕反爬、怕 SPA 空壳。
`op=fetch` 交给 **DeepSeek 官方**（`POST https://api.deepseek.com/v1/tools/fetch`），回来是**结构化 Markdown**：
标题层级、列表、表格、代码块都保留，反爬/编码/JS 渲染都不用操心。

| 项 | 说明 |
|---|---|
| 请求 | `{ "url": "https://…" }` |
| 响应 | `{ "title": "…", "content": "# Markdown…" }` |
| 鉴权 | 复用基板配置里的 `apiKey`（技能不打印、不落盘） |
| 计费 | 官方按**成功请求次数**计（约 5 元/1000 次）⇒ 单独 op `web.fetch`，默认只给主人与她本人 |
| 失败语义 | 401（key 无效）/ 402（余额不足）/ 403（被安全策略拒）/ 404（拿不到可用内容）/ 429（限流）/ 5xx 都翻成一句人话，并提示可退回 `op=text` |

⇒ **默认路径不变**（`text` 免费、不依赖 key）；`fetch` 是要质量时的升级选项。

## 优先级（先看这张）：默认两条，渲染是例外

### 默认（绝大多数情况走这两条）

| 场景 | 用哪个 | 成本 |
|---|---|---|
| 要正文 | **`op=text`** | 免费、不依赖 key |
| 要正文，且质量优先（长文/表格/代码块/反爬站） | **`op=fetch`** | 按成功请求计费 |

### 附加项（**非必要不用**：要开无头浏览器，冷启动 6~8 秒，重）

**只有下面这几种情况才该上**：

1. 用户**说页面异常**了 —— 打不开、样式错乱、内容不显示、疑似被拦；
2. 用户问的是**长什么样** —— 版式、配色、布局、图形、图标、图表、按钮在哪；
3. 用户问「**页面上有没有某个东西**」；
4. `text` / `fetch` 拿回来的东西**明显不对**（空壳、乱码、只剩导航），要确认是页面问题还是抓取问题；
5. 要**操作**页面（点击/填表/翻页）—— 这时必须用容器（`nav` + `act`）。

| 附加项 | 干什么 |
|---|---|
| `op=dom` | 跑完 JS 之后的 DOM（要真实链接/真实文本时才用） |
| `op=shot` | 截一张图（只要文件） |
| `op=look` | 截图 + 视觉模型描述（「看见」网页） |

**纪律**：上渲染之前，先想清楚**是哪一种情况**，并在回话里**说清为什么上它**。
「顺手截个图看看」不是理由 —— 正文能拿到就用 `text`/`fetch`。

### 省钱三条

- 同一页已经在容器里了 ⇒ 优先 `op=dom`（不额外计费），别为拿正文再 `fetch` 一次；
- 搜索要正文用 `need_content=true`（一次调用），别先搜再一条条 fetch；
- 渲染结果落在 `files/web/` 里，**能复用就别重跑**。
