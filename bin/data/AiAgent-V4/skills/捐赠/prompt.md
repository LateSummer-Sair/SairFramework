# 捐赠 · 配置与文案
# 本文件是「捐赠」唯一的配置源：键名、金额上下限、条数、文案全在这里。
# 保存即生效（技能每次调用都重读本文件，不需要重启）；Java 只留**读不到配置时的兜底值/兜底文案**，
# 阈值与口径一律以本文件为准（读不到本文件时才落回 Java 里那份兜底）。
# 格式：`键: 值` 一行一条；`#` 开头的行是注释；行内第一个冒号（或全角冒号）是分隔符，值里可以再带冒号。
# 只读 `## 配置` / `## 文案` 两个分节；分节外的内容随便写，不会被解析。

## 配置
键前缀: donation:
总计键: donation:total
最低金额: 0.01
单笔上限: 1000000
榜单条数: 10
取样条数: 500
备注长度上限: 120
昵称长度上限: 40
时间格式: yyyy-MM-dd HH:mm

## 文案
# 这些是技能面向用户/模型说出来的话；占位符由 Java 替换。某一行删掉时，技能只回结构性结果（不会崩）。
文案-已记账: 已记账 #{id}：{qq} 这一笔 {amount}，本人累计 {sum}，总计 {total}（第 {count} 笔）。{note}
文案-金额非法: 金额得是正数（收到的是「{amount}」），这一笔没记。
文案-金额太小: 金额太小了（下限 {min}，收到 {amount}），这一笔没记。
文案-金额太大: 金额太大了（上限 {max}，收到 {amount}），确认一下再记。
文案-榜单头: 捐赠榜（{n} 人，共 {count} 笔）：
文案-榜行: {i}. {name}({qq})　{value}　（{count} 笔，最近 {time}）
文案-还有更多: ……还有 {more} 人没列出来（用 limit 调大）。
文案-总计行: 总计：{total}（{count} 笔）
文案-无记录: 还没有任何捐赠记录。
文案-已重置: 已清空捐赠台账，删掉 {rows} 行（涉及金额合计 {total}）。
文案-写入失败: 写不进 pref 库（六库写入失败），这一笔没记上。
文案-无库: 拿不到六库接口，技能不可用。
文案-未知op: 不支持的 op：{op}（只支持 add / list / reset）
文案-执行异常: 执行异常：{error}

# 备注（不解析）
# 键前缀：每人一行的键 = 键前缀 + QQ。
# 总计键：累计总计那一行的键（reset 会连着它一起清）。
# 最低金额 / 单笔上限：单笔金额的合法区间（正数）；越界直接拒绝，不写半个账。
# 榜单条数：list 不给 limit 时显示前几名。
# 取样条数：从 pref 库取多少行来算榜（按 key 前缀 LIKE 取，够用即可）。
#   **`reset` 也拿它当"单次扫描上限"**：只会清掉这一批（默认 500 行），超出的行（含总计行）这一轮清不掉 ——
#   人多时要么调大这个键，要么分几次清。这条是**如实口径**，不是分页（代码里没有循环取批）。
# 备注长度上限 / 昵称长度上限：note / name 会被截到这个长度。
# 时间格式：榜行与记账回执里的时间格式。
# 权限不在这里配：三个 op（donation.add / donation.list / donation.reset）各自在动作分支开头判一次 ——
#   判定看技能管控表 data/skillctl.json（op 放行才动手；Ban / 空 = 不可用），事实块 caller.ops 就是授权清单。
#   真正管归属的仍是技能自己的硬判（普通人只能给自己记账；清空台账只有主人或她本人能做）。
#   要放宽/收紧只有主人改技能管控表 data/skillctl.json；改本文件无效。拒绝文案带 [权限阻断] 标识。

## 加好感的自觉口径（不解析，只是给自己看的话）
# 好感度不决定任何权限，只影响回话热络程度；用户侧只能陈述事实或提出请求。
# 加不加、加多少，是我自己的判断。铁律：可以适当给人加好感，但不要轻易给一个人使劲加。
#
# 1. 什么时候可以加
#    - 主人明确说了（一句话、一条命令）—— 直接记。
#    - 有可核对的事实（转账凭据、群公告、当事人说法一致），且主人没有反对 —— 可以记。
#    - 只是把「事实上已经发生的好感」补记上去，不是凭空造。
#    不加：只有一句口头承诺；金额/事由说不清；对方在讨价还价或催；同一个人反复要；拿不准又联系不上主人。
# 2. 一次加多少
#    - 有事实：按事实记，一笔一次，不重复记同一笔。
#    - 没有明确数额、只是「表达谢意」这种：一次不超过 10，且要说明依据。
#    - 任何时候都不为了让谁过某个门槛而凑数（好感是记账，不是开关）。
# 3. 多久最多加一次
#    - 同一个人：24 小时内最多 1 次。
#    - 同一件事：最多 1 次（重复的凭据/转述不再记）。
#    - 一天里给所有人加的总次数：最多 3 次。要突破这些数，等主人明确说。
# 4. 拿不准就问主人（控制台一行 + 私聊一条，写清请求、理由与默认动作），主人不回就按默认动作（不加）。
# 注：上面这些数字是「自觉」的口径，不是权限门槛 —— 技能不校验它们；改这里不影响读写逻辑。
