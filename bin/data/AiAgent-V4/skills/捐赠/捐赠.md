# 捐赠（工具 `donation`，台账落在六库的 `pref` 库（C 类）；普通人只能给自己记账，清空只有主人或她本人能做）

一本很轻的台账：**谁捐了多少 / 一共多少**。只写基板六库的 **`pref` 库**（key/value 形态），
不碰好感度、不发消息、不做任何支付动作 —— 它只是记账。

## 行结构

```
pref 一行一个人：  scope=global  key=donation:<qq>    value=累计金额   importance=笔数
pref 一行总计：    scope=global  key=donation:total   value=总金额     importance=总笔数
extra：{"qq":10001,"name":"小明","last":1750000000000,"last_amount":"30","last_note":"微信转账"}
```

- 键前缀与总计键名在 `prompt.md`（「键前缀」/「总计键」）；
- `value` 是文本列 → **排序在 Java 侧按数值做**（直接 SQL `ORDER BY value` 会按字典序："9" > "10"）；
- 一笔一笔累加，不保留明细流水（要明细用 `note` 库另记）。

## 三个 op

### `add` —— 记一笔
| 参数 | 说明 |
|---|---|
| `qq` | 可选，默认当前说话的人 |
| `amount` | 必填，正数；低于「最低金额」或高于「单笔上限」直接拒绝 |
| `note` / `name` | 可选：这一笔的备注 / 捐赠人昵称 |

- **给别人记账只有主人或她本人能做**：`qq` 不等于调用者、且调用者是 `ALLUSER` 时直接拒（归属硬判，不看位）；
- 落库两处：这个人的行（金额与笔数都累加）+ 总计行。
- `amount` 收字符串或数字都行（`"30"`、`30` 等价）。

### `list` —— 榜
按累计金额从高到低（Java 侧排序），末尾附总计；可以用 `limit` 限人数。

### `reset` —— 清空
**只有主人或她本人能做**（`MASTER`/`SYSTEM` 照常，`ALLUSER` 一律拒，归属硬判；
拒绝原文：`[权限阻断] 清空捐赠台账只能由主人或她本人（MASTER/SYSTEM）做。`）：
把 `donation:` 前缀下的行（含总计）逐行删除，返回清掉的条数。
**单次最多清 `prompt.md` 的「取样条数」行（默认 500）**：实现是"取一批再逐行删"，没有分页 ——
人/行数超过这个上限时剩下的行（含总计行）这一轮清不掉，要调大「取样条数」或分几次清。

## 权限
- 台账落在 `pref` 库 = **C 类运行时数据**：读判 `R`、写判 `W`（`h.needDb("pref", …)`）；
  C 类对非主人只有 `R`（`RWX` 只有 `SYSTEM` 有）⇒ 非主人写一律被位拦下 —— 所以**真正在管归属的是技能自己的硬判**（位只拦得住写这一侧）；
- 归属硬判（受限的只有 `ALLUSER`）：`MASTER` 与 `SYSTEM`（她本人）照常；
  普通人 `add` 只能给自己记账（`qq != caller` 一律拒）、`reset` 清空台账一律拒；
- 拒绝文案带 `[权限阻断]` 标识（**值同** `Acl.DENY_PREFIX`）—— 技能自己硬判的那句以它开头，基板 `h.need*` 的原文是 `缺 X 位 —— [权限阻断] …`（前缀不在首位）。工具可见性按 `T:X` 筛（`ALLUSER` 默认 `T=无` ⇒ 他的工具清单为空；工具是她的手段，属 T 类、只判入口），
  能不能答应对方看事实块 `caller.bits`；
- **改权限只有主人改账本 `data/perms.json`（v3）一个入口**（`perm` 工具的授权 op）；改本 md 无效。

## 边界
- 不校验"这笔钱真的到账了" —— 那是人的事，技能只记录；
- 不因为捐赠自动加好感度（好感度只影响回话热络程度，**不决定任何权限**）—— 要联动也是主人的选择，不在这里偷偷联动。
