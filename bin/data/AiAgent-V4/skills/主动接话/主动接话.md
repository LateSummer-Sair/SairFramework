# 主动接话（`on_message` 钩子 + `inject: context`，不注册工具，钩子按 `SYSTEM`（她自己的自主行为）跑）

群里没人 @ 你时，默认**不插话**。这个技能只做一件事：在"值得接一句"的时候，把**一段说明**注入上下文，
让下一轮对话里的你自然能顺着聊 —— 它**从不直接发消息**，不会骚扰任何人。

**默认保守（人设口径）**：他是**被动**的一方 —— 有人提及（被 @ / 私聊）才回，回复慢点是人情之常，
不值得为了"显得在线"去抢话。所以出厂 `启用: false`：没人点他名时**完全不插话**，连关键词都不看；
要主动，必须在 `prompt.md` 里明确写 `启用: true`。

## 判定：全部满足才算"该接"
1. `启用` 为 true（**出厂 false → 整个技能不动作**）；
2. 是**群**消息（私聊不接）；
3. **没被 @**（被 @ 由基板判定接手，技能不抢）；
4. 不是主人发的（**主人已无豁免** —— 群里没被 @ 时基板也不会回；这一条是本技能自己的保守口径：
   不替主人插话）；
5. 不是自己发的（`user_id != self_id`）；
6. 没有被其它钩子技能接管（`payload._handled` 仍为 false）；
7. 群在 `只在这些群` 里（留空 = 所有群）；
8. 文本命中 `关键词` 之一（没命中就什么都不做 —— 默认保守，宁可不接）；
9. 距上次接话 ≥ `间隔秒`（冷却）；
10. 当天接话次数 < `每日上限`。

## 判定为"接"时做什么
```java
h.inject("context", "主动接话", 说明文本);   // 只注入，不发消息（会话级，只影响这个群）
payload.addProperty("_handled", false);       // 明确交回基板判定：不接管、不代答
// 但"这条要不要自动回"必须投一票 true：基板的地址规则是"群里只认被 @"，
// 不投这一票的话这条（没被 @ 的群消息）会被直接跳过，本技能等于白开。
payload.addProperty("_reply", true);
payload.addProperty("_reply_reason", "proactive_" + 命中的关键词);
// 并把冷却与配额写进 kv
```
`说明文本` 由 `prompt.md` 的 `接话说明` 渲染（占位符见下），例如：
`群里 小明 说「有人在吗」，命中「有人在吗」。没人点你名，你可以自然顺一句…`

## 配置与文案在哪
全在 `prompt.md`（同目录）。**注意**：front matter 声明了 `inject: context`，
所以这个 `prompt.md` 会被基板**注入到每一轮的 context 槽位**（全局作用域）—— 它同时是"配置"和"给模型看的规则"，
写的时候请保持简短，别把大段说明塞进去。

```
启用: true             # 不为 true → 整个技能不动作
关键词: a,b,c          # 逗号分隔，命中任意一个才考虑接
间隔秒: 300            # 冷却
每日上限: 5            # 每天最多接几次（0 = 不限）
只在这些群:            # 群号白名单，留空 = 所有群
接话说明: …            # 占位符 {name} {qq} {group} {text} {word}
```
**没有关键词就不接手**（技能里没有写死的用户文案；`间隔秒` / `每日上限` **缺键或写坏时用 Java 兜底
`300` / `5`** —— 这两项是有兜底的，其余项缺了就不生效）。

## 落库 / 观测
| 键 | 内容 |
|---|---|
| `kv.talk_last_ts` | 上次接话时间戳（冷却用） |
| `kv.talk_day` / `kv.talk_day_count` | 当日日期与已用次数（配额用，跨天自动重置） |
| `kv.talk_last` | 最近一次接话记录 JSON：`{ts,group,qq,name,word,text,why}` |
| 控制台 | `[主动接话] …` 日志（决定接 / 因为冷却或配额跳过） |
| 上下文 | `context` 槽位里以 `主动接话` 为 key 的注入项（下次装配上下文时被模型看到） |

## 为什么这样设计
- 直接 `sendGroupMsg` 抢话是骚扰，也是基板判定被绕过的信号；这里只提供"素材"，
  **发不发、怎么发，仍然由基板和模型自己决定**。
- 冷却与每日上限让"接话"是稀缺动作：宁可少接，也不当复读机。
- **默认关掉**（`启用: false`）是"被动优先"的落地：没有提及就不插话，慢一点没关系；
  真需要她偶尔主动搭一句，是主人显式打开的一件事。

## 与「主动接话」的分工（口径统一，2026-09-19）
- **触发词 = 硬触发**：消息命中词表 ⇒ 立刻派一个回合（优先，先算它）。
- **「主动接话」只在"没有硬触发"的消息上做判断**：它自己看冷却与每日上限，决定要不要把"为什么该接"写进上下文。
- 同一条消息**只允许一次发言机会**：已经因为硬触发起了回合，就不再由接话判定追加一次。
- 冷却与上限各自只算一份，不互相读取（跨技能接口不在本轮范围）。
