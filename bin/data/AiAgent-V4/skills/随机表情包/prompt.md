# 随机表情包 · 配置与文案
# 本文件是本插件唯一的配置源（改完保存，下一条消息生效，不需要重启）。
# 格式：`键: 值` 一行一条；`#` 开头的行是注释（`## 配置` 这种分节标题也是注释）；
#       行内第一个冒号（半角 `:` 或全角 `：`）是分隔符。
#       ⚠ 图片模板里带冒号（`[CQ:image,file=...]`）不要紧 —— 分隔符只认**第一个**冒号，
#         而它在键名 `图片模板` 后面，模板里的冒号属于值。
# 读法：惰性缓存 + 按文件 mtime 失效 —— 每条消息不读盘，改完保存下一条生效。
# Java 里只留「文件读不到 / m.host() 为 null 时的兜底默认值」，兜底值与下面这些行逐字相同。

## 配置

库存为空时: 静默
允许fileid: true

图片模板: [CQ:image,file={file}]

追加日志: [sticker] 追加表情包 id=#{id} scene={scene} file={file} session={session}
空日志: [sticker] 没挑到可发的表情包（库存空 / 字段全空）—— 本轮不追加

## 备注（不解析，只给人看）
# 开关：false = 本插件完全不工作（等于没装）。
# 概率：命中才追一张。出厂值 0.4 是 V3 原样数字（QQAgentBridge.java:21
#   `STICKER_RANDOM_PROBABILITY = 0.4`），比较口径同样是"小于"（V3 :643 `Math.random() < 0.4`）。
#   三种写法都认：0.4（小数）/ 40%（百分号）/ 40（裸百分数）。<=0 = 关掉；>=1 = 每条都追（调试用）。
# 最多库存扫描：一次触发最多看多少行库存（有界窗口兜底时的行数上限；也受基板 Store.MAX_LIMIT=10000 夹住）。
#   随机取点那一步每次只看 1 行，所以正常情况下根本用不到这个上限 —— 它是"库存里可用行很少"时的兜底，
#   同时也是"绝不把整个库拉进内存"的那条线。
# 随机重试次数：随机 id 取点最多试几次（每次 LIMIT 1 只看一行）。试完还没挑到才退到有界窗口。
# 取图优先级：本地优先（默认，V3 口径）/ URL优先 / 仅本地 / 仅URL。写别的值一律按「本地优先」。
#   本地优先 = ① file 是本地绝对路径且**文件真的在** → 用它（V3 :649-651）
#              ② 否则 file 本身是 http(s):// 或 base64:// → 用它（V3 :652-653 的"回退原始 QQ URL"）
#              ③ 否则 extra 里留的 URL（URL键）→ 用它（本地副本被清理之后的回退）
#              ④ 否则 允许fileid 为 true 时，别的非空 file 值（NapCat fileid / 相对名）原样发
# URL键：`extra` 这个 JSON 口袋里可能留着原始 URL 的键名（逗号分隔）。第 ③ 步按这个顺序找。
# 库存为空时：静默（默认）= 什么都不发、什么都不打；写别的值（比如「打日志」）= 还是不发，但打一行「空日志」。
# 允许fileid：true = file 既不是本地路径也不是 URL 时（NapCat fileid / 相对名）也填进 file= 发出去
#   （基板原样透传 fileid，NapCat 自己认）；false = 只发"能确认在本地"或"是 URL"的值。
#   注意：本地绝对路径但**文件不在**的值一律不发（V3 :649-650 的存在性检查），与这一项无关。
# 仅QQ落点：true = 只在有 QQ 落点（群/私聊，Outbound.target()>0）时追；控制台没有图片通道，追了也没用。
# 图片模板：追加消息的原文。`{file}` 会被替换成挑中的值。形状与 V3 的
#   ToolDispatcher.buildImageCq 一致（`[CQ:image,file=` + 值 + `]`）。
# 图片最大字符：这一条追加消息的字符上限（默认 500）。超过就**这一轮不追**。
#   为什么要有它：追加的消息与正文共用同一把分段尺子（replyMaxChars=1000 / 群聊 180），
#   一条被劈成两半的 `[CQ:image,...]` 是坏消息；超长 base64 交给 QQ 也容易被拒。
#   500 落在"V3 单条上限 1000"与"群聊 180"之间偏安全的一侧；群聊尺子调得很小时可以再调小它。
# 打日志：追加成功后在控制台打一行（dim）。追加日志 / 空日志是那两行的文案。
#   追加日志可用占位符：{id} {scene} {file} {session} {group} {total}（#{id} 里的 {id} 也会被替换）。
# 不做的事：不拼 URL、不起文件服务、不做 base64 —— NapCat 的本地文件改写是基板在 Api.call 里统一做的，
#   本插件只把值原样填进 file=；也不写库（不 increment uses）—— 出站热路径上不写库。
