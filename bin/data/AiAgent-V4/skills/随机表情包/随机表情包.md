# 随机表情包（OutboundStage · order=30）

**这个插件不给模型任何工具**（md 的 front matter 里没有工具声明，只有 `name` 与 `description`）。它挂在**出站管线**上，
位置是**分段之后、发送之前**：一轮回复**发完之后**再追**一条独立的图片消息**（`[CQ:image,file=…]`），
**绝不与文字拼在同一条里**。工具/扩展点的识别靠**类实现了 ext 接口**（`RandomStickerStage implements OutboundStage`），
基板装载时会扫这个插件的每个顶层类并自动注册，不需要在 md 里再声明一遍。

## 挂在哪

| 项 | 值 | 为什么 |
|---|---|---|
| 扩展点 | `sair.v4.ext.OutboundStage` | 改"发出去的东西" |
| `order()` | `30` | 排在 `拟人化`（order=10）与 `@提问者`（order=20）之后；同序按插件名，顺序确定 |
| 实现的口 | `extra(Outbound)` | **整批**级别的口，一次 `say` 只收一次 —— 三段的回复不会追成三张表情包 |
| 不实现的 | `veto` / `transform` / `finish` | 本插件只追图：不否决、不改正文、不动整批 |
| 返回值 | `List<String>`（每条一个 CQ 串）/ 空表 = 不追加 | 基板把追加的消息 **trim** 后按分段尺子拆，且**不再过 stage**（防插件互相追加） |

收口条件由基板保证（`ExtRegistry.runStages`：`if (!keep.isEmpty())` 才调 `extra`）：整条被否决、或被别的 stage 洗成空 →
**不会调**本插件的 `extra`。所以"还有没有正文要发"这件事本插件**不自己再判一次**（判了就是第二份口径，早晚跟基板对不上）。

**故意不照抄的一处**（写在这里免得被当成漏抄）：V3 的 `StickerManager` 的 `randomSticker()`（`StickerManager.java`）
挑中之后会 `incrementStickerUsage(id)` —— 本插件**不写库、不改 `uses`**。理由：出站热路径上写库会拖慢每一轮对话，
而且"用了第几次"这件事该由工具面（`sticker` 技能）负责，一条追图不该有写副作用。

## 库存从哪来（只读口径）

- 库 = 基板六库的 `sticker`（列 `file`(TEXT) / `hash` / `scene` / `source` / `uses`(INTEGER) / `extra` / `id` / `ts`）；
  表结构由插件「表情包」（`data/skills/表情包/StickerSkill.java` 的 `declare`）声明，**本插件不建表、不写 SQL**。
- 只用 `Host` 能力面：`m.host()` → `h.store()` → `store.count("sticker", null)` + `store.list("sticker", filter, limit, order)`。
  `m.host()` **可能为 null**（探针直接注册的合成 stage 就是 null）→ 用兜底阈值、且因为拿不到 `store()` 而**静默不追加**，
  **绝不抛异常**。`h.store()` 也可能是 null，同样容忍。
- **只读**：只调 `count` / `list`（两者都是 `SELECT`）。不 `put` / `update` / `delete`，不改 `uses`，不留 kv。
- **不把整个库拉进内存**（库存可能很大），挑法是两段：
  1. `count("sticker", null)` 拿总数；为 0 直接静默。
  2. 随机 id 取点：`list(…, "id ASC")` / `list(…, "id DESC")` 各取 1 行拿 `id` 两端 →
     在 `[minId, maxId]` 上 `RND.nextDouble()` 取一个随机 id → `list(filter={"_gte":{"id":x}}, limit=1, order="id ASC")`
     **只看 1 行**（最多 `随机重试次数` 次，默认 6 次；`_gte` 是 `Store` 的合法控制键，不是我们拼 SQL）。
  3. 还挑不到才退到**有界窗口**：`list(null, limit=最多库存扫描, order="id DESC")`（默认 200 行，且被
     `Store.MAX_LIMIT=10000` 夹住）里随机挑一张可发的。
  代价：正常情况**每次触发 ≤ 9 条 LIMIT 1 级查询**，绝不整库入内存。
  （`Store.list` 没有 offset 参数，`order` 是白名单校验过的"列 + ASC/DESC"，所以"偏移量"只能这样取 —— 见"自己拿主意的地方"。）

## 取图优先级（`取图优先级: 本地优先`）

`sticker` 表只有**一个 `file` 字段**（V3 是 `getFilePath()` + `getImageUrl()` 两个字段），所以本插件按**值的形态**分层：

1. **本地** —— `file` 是本地绝对路径（`C:\` / `C:/` / `\\server\` / `//server/` / `/x` / `file:///C:/x`）**且文件真的在** → 原样用（V3 的本地存在性检查那一支：`getFilePath()` + `File.exists()`）。
2. **URL** —— 否则 `file` 本身是 `http(s)://` / `base64://` → 用它（V3 的"回退原始 QQ URL"那一支：`getImageUrl()`，回退发生在**本地没命中**时）。
3. **extra 里的 URL** —— 否则看 `extra`（插件自己的 JSON 口袋）里的 `URL键`（默认 `url,image_url,imageUrl,origin,qq_url`）——
   "本地那副本已被清理、原始 URL 还留着"的等价物。
4. **fileid** —— 否则 `file` 是别的非空值（NapCat fileid / 相对名）：`允许fileid: true`（默认）时原样发，`false` 时不发。
5. 都不成立 → **静默不追加**。

`取图优先级` 可写 `本地优先`（默认）/ `URL优先` / `仅本地` / `仅URL`；写别的值一律按 `本地优先`。

**不做**的事：**不自己拼 URL、不起文件服务、不做 base64** —— NapCat 的本地文件改写是基板在 `Api.call` 里统一做的
（`Api` 的改写层 `rewriteCqBlock` / `rewriteLocalFile`：中转在跑 → 外链 URL，没跑 → **保留原值 + 打一行 warn**；
`file:///C:/x` 只出现在上传类（`upload_*`）的 `file` 参数那条路上，见 `legacyFileParam` / `Relay.urlOf`），
所以本插件**只把值原样填进 `file=`**。

## 文案与阈值在哪

全在同目录的 `prompt.md`（`键: 值`，`#` 开头是注释）。Java 里只留"文件读不到 / `m.host()` 为 null 时的兜底默认值"，
兜底值与 `prompt.md` 的出厂值逐字相同。读法是**惰性缓存 + 按 mtime 失效**：每条消息不读盘，改完保存下一条生效。

| 键 | 出厂值 | 含义 |
|---|---|---|
| `开关` | `true` | `false` = 本插件完全不工作（等于没装） |
| `概率` | `0.4` | **V3 数字**（`QQAgentBridge` 的 `STICKER_RANDOM_PROBABILITY`）。`0.4` / `40%` / `40` 三种写法都认；`<=0` 关掉；`>=1` 每条都追 |
| `最多库存扫描` | `200` | 有界窗口最多看多少行（也受 `Store.MAX_LIMIT=10000` 夹住）—— "绝不整库入内存"的那条线 |
| `随机重试次数` | `6` | 随机 id 取点最多试几次（每次 `LIMIT 1` 只看一行） |
| `取图优先级` | `本地优先` | `本地优先` / `URL优先` / `仅本地` / `仅URL`（见上一节） |
| `库存为空时` | `静默` | 默认什么都不发、什么都不打；写别的值 = 还是不发，但打一行 `空日志` |
| `允许fileid` | `true` | `file` 既不是本地路径也不是 URL 时，是否原样发（NapCat fileid 由基板透传） |
| `仅QQ落点` | `true` | 只在 `Outbound.target() > 0`（群/私聊）时追；控制台没有图片通道 |
| `URL键` | `url,image_url,imageUrl,origin,qq_url` | 在 `extra` 里按这个顺序找原始 URL |
| `图片模板` | `[CQ:image,file={file}]` | 追加消息的原文；`{file}` 会被替换成挑中的值 |
| `图片最大字符` | `500` | 这一条追加消息的字符上限，超过就**这一轮不追**（追加消息与正文共用同一把分段尺子，半条 CQ 是坏消息）；值小于 16 会被夹到 16（`atLeast(…, 16)`） |
| `打日志` | `true` | 追加成功后在控制台打一行（`dim`） |
| `追加日志` | `[sticker] 追加表情包 id=#{id} scene={scene} file={file} session={session}` | 那一行的文案；占位符 `{id} {scene} {file} {session} {group} {total}` |
| `空日志` | `[sticker] 没挑到可发的表情包（库存空 / 字段全空）—— 本轮不追加` | 「库存为空时」非静默时才打 |

## 护栏

- `m.host()` 为 null → 用兜底阈值，且**不追加**（拿不到宿主 = 拿不到库存），**不抛异常**；`h.store()` 为 null 同；
- `sticker` 库没被声明（插件「表情包」没装）→ **本插件不追加**；基板 `Store` 的未知库分支会打一行 warn（`[store] count: 未知库 …`）；
- 库存为空 / 行里字段全空 / 值脏（带换行、控制字符、`[`、`]`）→ 静默不追加（脏值会把整条 CQ 拼坏）；
- 本地绝对路径但**文件不在** → 不发（V3 的本地存在性检查；这与 `允许fileid` 无关）；
- 选中的是**本地路径**时先判一次读位（读位判定 `h.needPath(sel.file, 'R')`；**判位主体是当轮说话人、不是 `SYSTEM`**：
  `Host.subject()` 返回 `Ctx.caller()`，外向扩展点由 `ExtRegistry` 的 `guarded` 绑当轮 caller
  —— `actor = c != null ? c : Caller.systemActor(...)`，`Sinks` 的分段/发送用的也是当轮 caller ⇒ 引用回复那条路上
  主体就是发消息的人）：表情包图就落在 `data\files\stickers\` 里 ⇒ 那是 `files/` 树，属 C、无专有位 ⇒ 非主人只读（`R`）；
  **根外绝对路径（A 类）对普通用户会被拒**（`Acl.DEF_A = Bits.NONE`）。读不到就记一行日志、**本轮不追**；
  追出去的那条图走基板的出站（`SYSTEM` 的 E = `RWX`（`Acl.SYS_E = Bits.ALL`）），本插件不自己调 NapCat 动作、也不自己判 E 位；
- 拼出来的 CQ 超过 `图片最大字符`（默认 500）→ 不发：追加的消息与正文**共用同一把分段尺子**
  （`replyMaxChars=1000` / 群聊 `replyGroupMaxChars=180`），半条 `[CQ:image,…]` 比不追更糟；
- `extra()` 最外层一层 `catch (Throwable)` → 返回空表：**一轮对话绝不会因为本插件挂掉**（基板还有 200ms 的超时闸门兜底）；
- 不写库、不改 `uses`、不留 kv、不动 `veto`/`transform`/`finish` —— 本插件对"这条发不发、正文长什么样"零影响。

## 验收（对应冒烟断言）

冒烟脚本**不在工程里**（`%TEMP%\s4bsmoke\SmokeSticker.java`，按"只许新增本插件目录下的文件"的口径）：
真 `ExtRegistry`（真 `extra` 口、真 host 绑定、真 200ms 超时闸门）+ 真 `Store`（临时 SQLite 里真建一张 `sticker` 表）
+ 假 `Host`（动态代理，可控 `skillDir()`/`store()`/`out()`）。本地冒烟数字，脚本未随工程提供：**42 条断言全 PASS，0 FAIL**：

1. `概率: 1` → 50/50 次都追加一条；`概率: 0` → 200 次一条都没追加；
2. `概率: 0.4` → 2000 次里追加 800 次（= 0.400），与 V3 的 0.4 一致（概率确实是从 `prompt.md` 读的，不是写死的）；
3. 追加串形如 `[CQ:image,file=…]`，且**只占一条**：`appended=1`、`parts = 正文 + 表情包`、正文 `changed=0`、追的那条不含正文；
4. 库存空 / `file` 为空串 / 值脏（带 `]` 或换行）→ 静默不追加、不抛异常；超长（> `图片最大字符`）也不发；
5. 一行里同时有"本地存在的文件 + URL"时：`本地优先` → 本地、`URL优先` → URL、`仅本地` → 本地、`仅URL` → URL；
   本地路径**文件不在**时 → 不发（V3 的本地存在性检查）；本地副本没了但 `extra` 里有 URL → 用那个 URL；
6. 两行（一行 URL、一行本地）连发 60 次：两行都会被挑到（随机行选择，不是永远挑同一行）；
7. `host()` 为 null → 不抛异常、不追加；`target<=0`（控制台落点）→ 不追加；
8. 三段正文 → 只追 **1** 条（`extra` 是整批口）；整批被否决/洗空 → 基板不调 `extra`，一条图都不发；
9. 改 `prompt.md` 的 `概率: 0` → `概率: 1` 保存后，下一条生效（惰性缓存 + mtime 失效），不需要重启；
10. `order() == 30`；`transform()` 返回 null（不改正文）、`veto()` 返回 false（不否决）。

## 自己拿主意的地方（如实记）

- **`Store.list` 没有 offset**：所以"随机取一个偏移量"落成"在 `id` 空间里随机取点 + `_gte` 找回，
  每次 `LIMIT 1`"（见上）。它是**按 id 空间均匀，不是按行数均匀**：`id` 有空洞时（删过库存）取值略偏。
  V3 是 `listAllStickers()` 全量入内存后 `random.nextInt(size)` —— 那正是本工程明确不要的做法，所以这里是有意的偏离。
- **`取图优先级` 的第 3 层（`extra` 里的 URL）是我加的**：V4 的 `sticker` 表没有独立的 URL 列（V3 有 `getImageUrl()`），
  而"本地被清理 → 回退 URL"是 V3 明写的口径，`extra` 是唯一可能留 URL 的地方。键名可配（`URL键`），
  找不到就是没有这一层，不影响其余口径。
- **`允许fileid: true`**：`file` 既不是路径也不是 URL 时（NapCat fileid）我选择"照发"（基板原样透传，NapCat 自己认），
  因为"字段非空"是本插件唯一能确认的事；不想要这一层就把 `允许fileid` 改成 `false`。
- **`仅QQ落点: true`** 也是我加的：`m.target() <= 0` 是"只进控制台"的落点，往控制台追一条 `[CQ:image,…]` 没有意义。
- V3 的 `!useExecs` 条件没有对应物（V4 没有 execs 通道这条分叉），所以没有搬。
