# 工具索引

事实块里那一行 `tools: {...}` 就来自这个文件：**类别 → 工具「名字 + 一句话」**。
每个工具的完整说明、op 取值明细都在工具表自己给的 schema 里，所以索引只给"分组 + 一句话"这一层增量，
刻意压成一行（B10 起带描述：**省掉探索轮** —— 看一眼就知道该用哪把，不必先 `tools op=show` 转一圈）。

改这个文件只影响事实块那一行，不动任何工具本身：

- 工具名写错的（不在注册表里、或技能管控表没给这个调用者授权 —— 工具面已按表筛过，看不到就是没授权）会被**忽略**，不会报错；
- 没在这个文件里出现的可见工具，自动落到下面的「默认类别」桶里；
- 类别名、桶名、示例前缀都是文案，改这里就改模型看到的东西，不用碰 Java。

阈值说明（V3 `SkillBank.buildStableIndex` 的先例是"每个技能一行、单行截 120 字符、预算 = maxTokens×4"）：

- `总预算`：这一行最多多少字符；装不下的**整个类别跳过**（像 V3 一样"只跳过放不下的那条，不放弃后面的"）。
  B10 起条目带一句话，预算相应调大（旧值 4000 只够装工具名）；
- `条目描述上限`：条目里那一句话最多几个字符（超了截断加 `…`；`<=0` = 不截，只压成单行）。
  默认 40：够说清"这把是干什么的"，又不至于把整行挤爆；
- `候选数`：工具名没命中时，最多给几个候选（要带"该怎么调"，所以别给太多）；
- `距离上限`：拼写容错的编辑距离上限（长名字会自动放宽，见 `ToolIndex.nearest`）。

下面三个键是**主循环的连续失败闸门**（事实化，不注入劝导语）：同一个工具连续失败达到
`失败提示阈值` 时，下一轮往上下文里加一行事实 `tool_failures: {"<工具>":n,"last_error":"…"}`；
达到 `失败终止阈值` 就停止本轮并回 `失败终止文案`。
缺任一键 → 基板只在日志里报"缺哪个键"，不注入、也不编文案。

- `失败终止文案`：支持 `{tool}`（工具名）与 `{n}`（连续失败次数）两个占位符。

下面两个键是**回合队列的两句话**（调度面：按会话分道 + 溢出不静默丢弃，见 `sair.v4.schedule.Lanes`）。
基板 Java 里没有一句面向用户的话，全在这里；**缺任一键 → 只在日志里报"缺哪个键"，那一路提示就不发**
（不兜底、不编话）：

- `队列溢出文案`：队列真的装不下、且这条又不适合合并成一回合时，回给原会话的那一句
  （`turnDropNotice=true` 时生效）；
- `排队中告知文案`：同一会话的消息已经排在一条正在跑的回合后面时，回的那一句
  （默认**关**：`turnQueuedNotice=false`，同一会话每轮繁忙期最多一句，避免刷屏）。

最后两个键是**会话快照"跟不跟得上"的告警**（只有一行控制台 warn，不改任何行为）：

- `快照落后阈值`：一次快照里"还没被覆盖的新消息条数（lag）"或"被裁掉的条数（skipped）"达到它就 warn 一行；
  缺键或 `<=0` = **不告警**（基板不编阈值）；
- `快照落后告警间隔秒`：同一会话两次告警的最小间隔（缺键 300 秒），避免热闹的群刷屏。

下面这个键是**"只 @ 一下、没带任何话"那一条消息给模型的输入**：群里有人（含主人）只 @ 了机器人、
既没有文字也没有图片/语音，基板照样起一轮 —— 这一轮的全部输入就是**上下文快照**（窗口到这条 @ 为止），
让模型自己读一遍上下文再决定怎么接。缺键 → 只在控制台报"缺哪个键"，**这一条消息就不起回合**
（基板不编兜底话，与其余文案同一契约）：

- `被单@时的输入`：给模型的用户轮文本（就一句说明，别写死回复内容）。

下面这个键是**本地交流面板选项卡的标题**：本地控制台 = 主人对话，对话正文与流式输出落在
SFW 控制台右侧隔离区的那一页上（`sair.v4.ui.TalkPanel`），结构性日志（装配进度、工具台账、
错误与警告）仍走主输出框，两边互不污染。缺键 → 面板**不设名字**（框架自己叫「面板N」），
并在装配日志里报"缺哪个键"（基板不编名字）：

- `面板标题`：选项卡标题。

下面三个键是**偏好块的三行文案**（`sair.v4.ctx.CtxBuild` 每回合把六库 `pref` 里这个调用者可见的
三层 —— `global` + `user` + `group`，控制台只有 `global` —— 合并后注入系统提示词的**稳定段**，
让"以后都这样"的设定每轮都在场，而不是等模型主动去调 `pref` 工具）。
**这三个键与上面所有文案键口径相反：缺键不停止注入，改用内置默认值渲染，并且只 warn 一次** ——
"缺键就不发"在这里等于功能静默消失。截断有两把尺子：配置 `prefInjectMaxRows`（条数）与
`prefInjectMaxChars`（字符），超了就丢**尾巴**（排序是 `importance` 降序、`key` 升序，
所以尾巴恰好是"先丢 importance 最小的、同档再按 key 降序丢"）：

- `偏好标题`：块首那一行（默认 `偏好/设定（必须遵守）`）；
- `偏好行`：一行一条的模板，占位符 `{key}` `{value}`（另支持 `{scope}` `{importance}`；值里的换行会被压成空格，保证一行一条），
  默认 `- {key}: {value}`；
- `偏好截断`：丢过条目时追加的那一行，占位符 `{rest}` = 丢掉几条，默认 `…（还有 {rest} 条未列）`。

`初始化中文案` 是**基板还在装配时 `chat` 回的那一句**（装配跑在自己的守护线程 `v4-boot` 上，
这几秒里 `help/status/tools/config` 已经可用，只有 `chat` 要等就绪）。四个占位符在发送前替换：
`{n}` = 第几步、`{total}` = 总步数（19）、`{step}` = 步骤名、`{ms}` = 已耗时毫秒。
**缺键 → 只在控制台报"缺哪个键"，不发那句话**（同样是"基板不编兜底话"的口径）。

下面四个键是**生命周期命令的两句话**（`AiAgentV4/start`、`/restart`）。
配置生效口径**只剩一条**：`config set` 这类命令只把值写进 `config.json`、**不生效**；
要 `ai/start`（已在运行则 `ai/restart`）才加载运行 —— 不再有"即时生效 / 改了要重启"两把尺子。
同一口径：**缺键只报缺键，不编兜底话**。
占位符：`{cmd}` = 组件命令前缀（如 `AiAgentV4`）、`{key}` = 配置键、`{value}` = 值、
`{progress}` = "第 x/19 步 …"、`{skills}`/`{tools}` = 当前技能/工具数。

- `需要重启提示`：**旧口径遗留键**（"改了要重启"那套已整条退休，`Conf.RESTART_KEYS` 已删）——
  现在没有调用者，留着只为满足"缺键即报"的清单要求；文案已按新口径改写，将来要用可直接取；
- `已在运行回话`：`start` 打在已经就绪的基板上时回的那一句（幂等，不会重启）；
- `装配中回话`：已经有一条装配/重启在跑时，再来 `start`/`restart` 回的那一句（重复不并发）；
- `启动已受理回话`：`start` 真的开始装配时的那一句；
- `重启已受理回话`：`restart` 受理时的那一句（先停旧基板，再按 `config.json` 重新装配）。
