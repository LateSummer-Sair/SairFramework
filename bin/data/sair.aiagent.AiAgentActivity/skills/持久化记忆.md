## 四层记忆系统架构
本系统采用分层记忆设计，每层自动注入到提示词中:

### 1. 工作记忆（自动）- 当前对话上下文
- 系统自动注入最近的对话历史（滑动窗口）
- 无需任何操作，AI 直接从 system prompt 读取

### 2. 短期记忆（自动）- 近期交互记录
- JournalManager: 最近 15-25 条操作日志自动注入
- 包含最近的工具执行结果（操作类型+内容+结果）
- 跨会话持久化（SQLite），重启不丢失

### 3. 长期记忆（自动+手动）- 跨会话持久化记忆
- MemoryManager: FTS5 全文搜索，根据用户消息自动检索相关记忆注入
- 调用 `remember` 工具手动写入持久记忆
- QQ 记忆系统:
  * UnifiedQQMemoryManager (统一记忆库 unified_memory.db): execq 通道主记忆库，所有 QQ 共享
  * AI 应了解: `remember` 在 execq 通道写入 UnifiedQQMemoryManager，在本地通道写入 aiagent.db
  * 搜索时系统自动检索对应的记忆库，无需手动区分

### 4. 持久记忆（手动查询）- 知识库
- Notes 知识库: 使用 `note` 工具 CRUD，使用 `searchnote` 工具 FTS5 搜索
- 系统会自动将相关笔记注入提示词（Knowledge Base Notes 段）
- AI 应主动使用 `searchnote` 查询不熟悉的领域知识

## 知识获取优先级（铁律）
遇到不会/不懂/不确定的事，必须按以下顺序层层递进查找，不要跳过:
1. 短期记忆上下文（已自动注入）
2. 长期记忆上下文（已自动注入）
3. 知识库（`searchnote` 查询）
4. 联网搜索（`web`）

- 先看上下文中已有的记忆/知识，没有再 `searchnote` 查知识库，仍没有才 `web` 联网搜索
- 联网搜索到可靠内容、任务成功完成后: 用 `remember` 记入长期记忆、用 `note` 记入知识库，下次直接复用

## 示例
- `remember` 用户喜欢简约风格的 UI 设计
- `remember` 项目使用 PostgreSQL 数据库，端口 5432
- `searchnote` 数据库配置 (查询知识库)
