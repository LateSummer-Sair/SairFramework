# 文件读取（readfile）

原硬编码实现：`AgentActionHandler.executeReadFile()`。剥离后行为完全一致：

- **仍然要过确认闸门**：控制台通道下会先弹「读取文件: xxx，是否允许？」（`ai/yes` / `ai/no`）；
  execs 与 QQ 通道沿用既有的 bypass 语义。确认逻辑调的是 Java 里的同一份闸门
  （`ConfirmationGate.confirm`），所以 execs/QQ 的 bypass 开关照旧作用。
- 底层仍调 `sair.aiagent.util.FileUtils.readFile(path, offset, limit)`（切片在完整文本上做，
  不会出现「第 5 万字符之后永远读不到」的老问题）。
- 返回文本格式与原来一字不差：`文件 [path] [分块读取: offset=.., limit=..]:\n<内容>`。

## 安全边界（为什么这些没跟着搬进来）

- **确认闸门**留 Java（`ConfirmationGate`）：技能只调用，不能自己决定"不用问了"。
- **文件读写的路径与权限判定**留 Java（`FileUtils`、`HarnessConfig` 的权限矩阵）：
  技能声明的 `permission` 对内置工具名无效，矩阵说了算（防止改 md 就放宽门禁）。
